# 双端日历、出勤、比赛与演示数据收口

## Goal

按 2026-08-30 已确认的在线 Figma 与甲方交互要求，完成家长与教练端的日历、导航、出勤、比赛、战术板和七个测试账号演示数据的可稳定展示与编辑。

## Requirements

- 在线 Figma 文件 `zZ6wKyOHKcO4UYXDd9jGwv` 是唯一视觉权威；本轮先读取 P1 `1008:186`、C1 `1293:8`、C2 `93:606`、C6 `93:796`、C7 `1040:9` 后再编辑。
- 家长端默认保留周条，展开/收起月历的下拉箭头必须居中、无倾斜；教练端提供同等的“周条默认、下拉月历选日、可前后翻周和翻月”能力。
- 家长端底部导航顺序为“日程 / 成长 / 发现 / 我的孩子”；不得将已正确的“发现 / 我的孩子”顺序改回去。
- 教练训练工作台出勤为四列头像网格：绿色勾表示已到，灰色头像表示未到；点头像即切换并调用真实出勤写入，失败回滚。不要流程状态、销课或“查看详情”。姓名显示在头像下方，展示值最多四个汉字。
- 教练日程和训练工作台的训练、比赛必须使用清晰不同的色彩、标签和入口，且不伪造 API 数据。
- 比赛记录提供真实的全屏录入入口：比分、进球（含乌龙）、助攻、犯规及既有可用事件；写入后列表和比分重读可见。
- 战术板保持全屏上下结构：上半为足球场、下半为全部球员；可拖拽上场/下场、切换阵型、保存并在重启 API 后重新读取。
- 七个双角色测试账号在最近三周应有中文、可读、彼此合理关联的训练、比赛、出勤、评测与战术板数据；生产数据导入先备份且不得在文档、提交或日志输出手机号、会话 token、密码或数据库绝对路径。
- WXML 不调用 `.map()`、`.filter()`、`.slice()`、`.indexOf()` 等 JS 方法；展示字段必须在 TypeScript view model 预计算。
- 不触碰、删除或连带提交当前 350+ 项历史未提交/未跟踪文件；每批仅路径限定暂存。
