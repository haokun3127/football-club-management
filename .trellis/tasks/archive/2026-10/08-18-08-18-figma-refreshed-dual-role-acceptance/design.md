# 双端 Figma 更新复原设计

## 来源与边界

唯一来源是 `zZ6wKyOHKcO4UYXDd9jGwv`：家长画板位于 `4:6`，教练画板位于 `4:7`。`figma-online-frame-map-2026-08-12.md` 给出 49 个页面级节点与路由；每次改动前重新读取目标节点，因此该映射只是定位索引，不冻结视觉内容。

不写回 Figma。本地 `docs/design/reference/figma/*.png` 是 2026-08-12 快照；在线图与快照的差异会记录为本轮设计变化，只有在明确需要离线交接时才更新快照。

## 实施边界

页面按共享壳层优先：家长端先校准登录/顶栏/四栏 TabBar/P1，再完成成长、孩子与内容流程；教练端先校准三栏 TabBar/C1，再完成活动交付、训练、评测和个人中心。页面内使用现有 API view model，视觉信息不够时宁可显示真实的缺失态，也不把 Figma 示例值写进生产 UI。

每页的验收记录包含：在线三元组（file key / node ID / name）、路由、源码范围、可见差异、真实数据差异、验证命令、截图证据路径或无法取证原因。微信胶囊、状态栏和 Figma 示例数据被单独标注为系统/数据豁免，不能遮掩其他几何错误。

## 变更与回滚

一次提交只覆盖一个页面或一个明确共享壳层批次，避免把 49 页变成不可定位的大补丁。每批先跑定向测试和类型检查，最后依批次重截。回滚以独立提交反转为单位；不使用 `git reset`、`git checkout --` 或覆盖工作区文件。
