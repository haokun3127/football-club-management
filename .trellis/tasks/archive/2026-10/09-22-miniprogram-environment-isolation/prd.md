# 重庆天才小程序环境隔离

## 目标
隔离 develop、trial、release 的请求、会话与数据库，使正常开发/体验操作以及环境误配不能误写生产。

## 已确认事实
- `apps/miniprogram-cq-talent/utils/config.ts:4` 三个环境共用生产基址；`:33` 的缓存键没有环境维度。
- `apps/api/src/index.ts:9` 缺省数据库路径且启动默认迁移/seed；`src/server.ts:29` 尚无环境入口检查。
- `docker-compose.yml` 只有单 API、单固定 named volume；`docs/current/deployment-requirements.md` 最近部署证据为 2026-09-16，不能当作当前线上事实。
- 官方本地快照 `docs/reference/wechat-miniprogram/pages/ability-network.md:73`：微信 Referer 的 0 包括开发、体验、审核；devtools 是开发工具，其余为正式版本。Referer 不能区分 develop/trial。

## 要求
R1. 三环境各有固定入口，未知环境、错误入口拒绝；不回退生产。
R2. 会话、上下文、草稿按环境隔离，不导入历史无环境缓存。
R3. API 在任何业务路由及幂等处理前拒绝环境不匹配；生产拒绝开发/体验 Referer，包括无新请求头的旧客户端；来源检查不代替 Bearer/角色认证。
R4. 启动及迁移显式选择环境和数据库，非生产不能打开历史生产数据库；部署模板分开容器与卷。
R5. 使用临时合成数据库/HTTP 注入重复验证允许路径与拒绝路径，以及拒绝前后数据库不变。

## 验收
- 三环境矩阵、未知/缺失环境、缓存隔离、请求标记不可由调用方覆盖测试通过（R1/R2）。
- 不匹配/缺失/矛盾标记、旧体验 Referer、旁路路径的请求在路由写入前被拒绝，正常正式来源与鉴权保留（R3）。
- 非生产路径/符号链接/硬链接/数据库归属错误启动失败；独立临时库可迁移、重启（R4）。
- pnpm check、相关构建、平台检查和 diff 检查有实际结果；运维文档明确尚未上线（R5）。

## 范围边界
不连接生产数据库，不复制生产数据，不运行远程部署/迁移/重启，不上传小程序、不更改体验/审核/发布状态。不改变现有业务权限。未来线上生效及真机验收单独安排。
