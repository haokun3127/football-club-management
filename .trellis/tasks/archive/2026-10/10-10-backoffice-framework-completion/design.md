# 技术设计

## 方案
优先采用 Ant Design Pro 官方模板，建立 apps/backoffice 独立 pnpm workspace 包，使用 React、TypeScript、Umi Max 与 ProComponents。布局、路由、列表、表单复用框架，按既有后台需求组织工作台、数据管理、评测与模型、BI、专业服务和设置。品牌沿用 #A80F1B、中文标签和现有 Figma 业务结构。

这是第三方开源框架的项目级选择；不改变 Trellis 工作流，也不将其描述为 OpenAI 框架。实施第一步固定模板来源提交和依赖兼容组合，适配本仓库 Node 24、pnpm 10.33.0 与 TypeScript 工具链；不将上游 master 依赖范围直接视为已验证版本。

## 架构与边界
浏览器页面 → 同源 /backoffice/api 适配路由 → 现有 application/domain 服务 → SQLite 仓储。新业务确实缺少服务或仓储时才补层内实现。HTTP 路由不放 SQL，不通过请求伪造 X-User-Id，不使用服务端 HTTP 自调用绕过授权，不重复创建微信 BFF 业务副本。

鉴权继续使用现有密码认证和环境命名 HttpOnly Cookie。请求携带匹配的 X-FCM-Environment，服务端核对配置来源路径、Origin、Referer、身份和动作权限；clubId/操作者来自会话。前端菜单权限只改善体验，服务端每次请求检查权限。普通 admin 不默认获得全部敏感字段或导出权限，沿用需求权限矩阵。

## 客户端配置
- 禁用官方模板 mock，清理示例页面、默认示例账号、token/localStorage 登录实现；替换为真实 session/login/logout。
- 运行时环境和 API 基址从受控配置生成，保留 develop/trial/release 的既有前缀；不把 clubId 和正式 URL 写死在模板。
- 使用同源相对 URL、Cookie、统一错误结构，401 回到登录，403 显示权限状态；写请求不自动无条件重放。
- 业务表单使用显式字段定义和类型，日期/单位/引用校验来自服务端契约；列表使用稳定 ID、后端分页、筛选和排序白名单。
- 409 返回获准最新值和 revision，保留本地输入，由用户核对再保存。高影响写操作使用 requestId/幂等键，事务内保存事实与历史。
- 不内插动态 HTML，不显示数据库/内部错误文本。无来源的数据显示实际空/缺失状态，不能伪造演示统计。

## 静态资源与环境路由
现有 backoffice-web.routes.ts 仅允许 app.js/style.css，Docker 复制原生 backoffice 目录。迁移时改成构建清单限定的静态资源与 SPA HTML 回退，阻止目录穿越并排除 API 路径；保留旧入口路径。哈希资源、路由 base 和 publicPath 与各环境 URL 一致，支持深链刷新。

Ant Design 的运行时样式、Umi 引导脚本与当前严格 CSP 需要真实浏览器验证：优先提取样式或在 HTML 与样式运行时使用每响应 nonce。禁止为了方便放开 script-src unsafe-inline/unsafe-eval 或全局放宽微信来源保护。只有浏览器资源经验证后更新限定 CSP 契约；开发热更新不能成为生产安全策略。

Docker/CI 新增工作区依赖、客户端构建和输出复制；部署包不复制源码凭证或模板 mock。高频构建目录、缓存、夹具 SQLite 和日志落到项目实际路径 /Users/dongjun/projects 或系统临时目录，不放 Documents 实体目录。

## 业务增量
人员与队伍：主档和任职/成员/绑定关系分开；停止状态保留历史引用。场地无坐标不生成导航位置。保险和课包为独立获准维护，不使普通培训计次触发扣账。

活动和内容：复用 CalendarEvent 及训练/比赛/其他扩展，校验时间、场地、球队、教练与成员归属。活动/课程变更和记录修正继续受当前版本与历史保护。后台内容编辑不授予改评分权限；通知保留实际发送状态。

评测与模型：复用图依赖、任务工作流、发布事务和血缘，确认当前代码是否已有映射实现后补缺。原始值、整数分值、等级分别关联定义和不可变规则版本；试算不发布，规则更新不静默改变历史结果。缺正式阈值不影响框架和编辑交付，但阻止把试验版本发布为正式标准。

导入/导出：复用 Excel/WPS 暂存、映射、预览和确认管线；每对象模板定义关键标识、空值和部分失败策略。预览与确认携带批次及事实版本，确认复核授权/关系，幂等去重。敏感数据按动作和字段授权且留历史。

BI：使用短读事务或一致快照查询，返回事实版本/快照标识及截至时间；明细和导出引用同一口径。版本变更明确要求刷新或生成新版本，不新增数据仓库。

服务：现有服务能力需要逐对象核对，代码检索尚未发现完整通用服务目录/咨询服务。按已确认最小范围补持久化和权限，复用人员、活动、评测对象。外部专业人员、收费预约、复杂交付流程仍受未决项限制。

## 数据迁移、兼容与回滚
迁移以当前最大版本为起点，仅增加必要结构/索引/版本与历史；不按历史文档的迁移数量写死序号。临时文件数据库验证旧库升级、写入、重启、外键和回滚。实际上线前先验证一致性备份和恢复；旧客户端继续读共享事实。

保留迁移前备份和旧静态构建用于部署回滚。禁止旧页面或代码回退重新启用已禁用的培训扣账副作用；不通过删新表回滚真实业务。只提交本任务明确拥有的改动，原有未提交文件按基线逐项核对。

## 选择依据
Ant Design Pro 自带中文后台所需的布局和集成配置，适合本项目多步骤领域工作流。React-admin 支持通过 authProvider/dataProvider 接入任意 API，可作为替代，但需额外适配现有品牌及发布/导入/冲突流程。当前主推 Ant Design Pro，不同时建设两套客户端。官方来源与仍需验证的版本/CSP问题见 research/framework-and-baseline.md。
