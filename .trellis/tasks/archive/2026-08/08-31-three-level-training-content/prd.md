# 三层指标训练内容规划

## Goal

依据 `docs/archive/2026-06-discovery/assessment-system-analysis.md`，把教练端训练内容选择从当前“训练维度 → 训练项目”的两层列表，升级为可配置的“一级核心能力 → 二级子项 → 三级子项 → 训练动作”展示结构。教练可以在选定球队的训练活动中按指标层级浏览、搜索、查看训练动作要点，多选训练动作并保存到现有训练计划；底层继续保留指标图谱能力，不能把指标关系写死为单一父子树。

视觉参考是用户提供的训练内容选择截图：顶部搜索与当前组合、左侧一级/二级导航、中间按当前三级指标分组的训练动作卡片、底部固定的临时超级组与完成操作栏。在线 Figma 仍是小程序视觉的唯一权威，截图只用于补充交互结构描述。

## Requirements

- 先读取并遵循 `docs/archive/2026-06-discovery/assessment-system-analysis.md`、当前 Trellis 规范和现有 `content-select` 代码；不得把 Excel 的展示树误当成底层唯一数据模型。
- 训练目录需要表达一级核心能力、二级子项、三级子项。一级和二级来自指标视图节点，三级节点关联一个或多个训练动作；同一指标或训练动作允许在多个视图/指标下复用。
- 训练动作卡片至少展示：中文动作名称、动作图或稳定图标、难度、次数或训练剂量、查看动作要点入口；没有真实图片/次数时使用明确的空值展示，不伪造事实。
- 教练可以按三级指标筛选训练动作，并使用中文搜索框搜索动作名称、动作要点和关联指标。
- 支持多选训练动作，底部汇总已选数量/训练时长，并沿用现有训练活动保存接口保存；保存后必须通过 API 读回验证，不能只更新本地状态。
- 训练管理按所选球队读取目录和训练数据；同一教练可切换多个可访问球队。训练目录不应泄漏其他球队的私有内容。
- API 需要提供稳定的三层训练目录响应；尽量扩展现有 `coach/training-project-tree` 契约，兼容现有 `projects` 和保存接口，避免无必要的破坏性路由重命名。
- 三层目录的组装应使用现有 `AbilityMetric`、`MetricView`、`MetricViewNode`、`TrainingDrill` 等模型；训练动作与三级指标的关联应由 `TrainingDrill.metricIds` 或明确的扩展映射表达，不在 WXML 中临时推导。
- WXML 不调用 `.map()`、`.filter()`、`.slice()`、`.indexOf()` 等 JS 方法；所有展示字段、CSS 类名、搜索文本和分组结果在 TypeScript view model 中预计算。
- 视觉验收必须使用微信开发者工具或真机真实 375×812 截图；类型检查、单测和编译不能单独宣称视觉完成。
- 每个逻辑批次先写失败测试，再实现最小改动；API 变更后重新 build 并重启本地 API；路径限定暂存，不能连带当前工作区其他未提交改动。

## Acceptance Criteria

- [ ] 读取真实训练目录后，教练端能看到一级核心能力、二级子项和三级子项，且当前筛选下只展示对应训练动作。
- [ ] 同一训练动作或指标出现在多个关联节点时不会重复保存错误，也不会因页面分组而丢失其稳定 ID。
- [ ] 搜索、一级/二级/三级筛选和清空筛选均有定向测试，WXML 不含禁用的 JS 方法调用。
- [ ] 训练动作卡片在真实运行态包含中文名称、难度、剂量/次数、动作图或稳定占位、动作要点入口；长名称在 375×812 下不挤压选择控件。
- [ ] 多选后点击完成，API 保存成功并读回相同的训练动作 ID 集合、顺序/分组所需字段和时长摘要；请求失败时页面选择不被错误覆盖。
- [ ] 切换球队后，训练目录、训练统计和可选动作均按 `teamId` 读取；不可访问球队返回结构化错误或空结果，不返回其他球队内容。
- [ ] API schema/OpenAPI、领域类型或应用契约与小程序类型同步，相关 API、持久化（如有）、页面定向测试和 TypeScript 检查通过。
- [ ] 小程序 WXML/WXSS 可由微信开发者工具编译；取得可信 375×812 截图并完成与在线 Figma 对照后，记录静态、API 和视觉三类证据。
- [ ] 逻辑批次独立通过 `git diff --check`、相关测试和构建后，使用限定路径单独提交；最终更新 `docs/current/progress.md` 与交接记录。

## Confirmed Facts

- 当前 `apps/miniprogram-cq-talent/pages/coach/content-select` 只有搜索、平面分类胶囊、训练项目卡片和多选保存。
- 当前 API `GET /clubs/:clubId/app-clients/:clientId/coach/training-project-tree` 返回 `dimensions → objectives → projects`，项目摘要包含 `metricIds` 和匹配的 `metrics`，但没有给小程序返回三层指标视图。
- 领域层已经存在 `AbilityMetric`、`MetricGraphVersion`、`MetricDependency`、`MetricView`、`MetricViewNode`、`TrainingDrill`；指标图谱的依赖关系和展示视图已经有基础骨架。
- `AbilityMetric` 的 `dimensionId` 不是安全的三级父子关系；分析文档明确要求把树作为视图，把指标本身作为可复用图谱节点。
- 现有训练项目保存接口使用稳定的 `projectIds`，应优先保持其兼容性。
- 用户参考图的视觉结构为：顶部搜索框和组合标题/新增按钮；左侧纵向指标导航；右侧两列动作卡片；卡片有动作图、蓝色标签、右上训练剂量、动作名称和“查看动作要点”；底部固定操作栏。

## Out of Scope

- 本任务不实现完整的 Excel 导入器、任意公式 DSL、评分录入流程或雷达图重构；这些属于评测引擎或评测页面任务。
- 本任务不重写现有训练计划持久化边界，不删除旧的 `groups/projects` 字段，除非测试证明兼容扩展不可行。
- 本任务不修改与三层训练目录无关的家长端、比赛、战术板或登录代码。

## Notes

- 该任务与已有 `08-30-coach-calendar-attendance-match-refinement` 分开，不能把两者的未提交文件混在同一批提交。
- 生产数据导入如确有必要，必须先备份、导入、重启 API、接口读回审计，且不得在文档、日志或提交中写入手机号、密码、token 或数据库绝对路径。
