# 修正天才足球200人测试数据关系

## Goal

修正重庆天才小程序的 200 人验收数据，使学员、家庭、家长账号、球队、教练、活动和业务表之间形成可解释的真实关系，不再用一个验收家长绑定全部 200 名学员。

## Background

- 当前生成器已经创建 200 名学员、多个家长、8 支球队和对应教练，也填充了全量用户、缴费、考勤和保险四张业务表。
- 当前家庭分布过密：约 120 个单孩家庭、30 个双孩家庭和约 7 个三孩家庭，多孩家庭比例明显偏高。
- `createCqTalentAcceptanceSeed` 又额外创建 `parent-cq-talent-acceptance`，将其作为非主要联系人绑定全部 200 名学员；小程序 smoke 和文档随后把“该家长有 200 个孩子”写成验收条件。
- 用户明确要求绝大多数家庭只有 1 个孩子，只随机生成少量 2 个孩子和 3 个孩子的家庭。

## Requirements

- 保持 200 名学员总数以及天才足球四张业务表各 200 行的数据覆盖。
- 使用可复现的确定性生成方式分配家庭，避免测试每次运行产生不同结果，同时让多孩家庭散布在数据集中。
- 绝大多数家庭为单孩家庭；只保留少量双孩家庭和极少量三孩家庭；任何家庭最多 3 名学员。
- 200 人验收集固定为 178 个单孩家庭、8 个双孩家庭、2 个三孩家庭，共 188 个家庭；家庭规模位置使用固定 seed 打散，保证可复现。
- 每个学员只绑定其真实生成家庭的家长，不创建可查看全部 200 名学员的万能家长关系。
- 保留稳定的 dev/验收家长用户 ID，但让该账号代表一个真实的少量多孩家庭，便于验证“全部孩子”视图。
- 每个家庭拥有对应的家长用户、俱乐部会员和家长档案，手机号与业务表联系人一致。
- 每名学员拥有主要球队归属；少数学员可拥有第二训练组。球队必须有有效默认教练，活动 owner、参与者和教练权限关系保持一致。
- 修正 API fixture 测试、app-client smoke、README 和人工验收/发布就绪文档中的错误口径。
- 不改变生产业务模型，不新增仅为演示服务的万能权限或跨家庭访问能力。

## Acceptance Criteria

- [x] seed 恰好生成 200 名重庆天才学员，四张业务表各有 200 行且关键字段完整。
- [x] 所有 200 名学员各有且仅有一个家庭监护关系，监护关系引用存在的家长档案。
- [x] 不存在绑定 200 名学员的家长；每个家庭最多 3 名学员，多孩家庭占比保持低位。
- [x] 家庭规模统计严格为单孩 178、双孩 8、三孩 2，总计 188 个家庭。
- [x] 稳定 dev 家长账号只返回其真实家庭的 2 或 3 名孩子，家庭日历仍能验证多孩子聚合与筛选。
- [x] 每名学员至少有一个有效球队成员关系，每支 seed 球队的默认教练、训练/比赛 owner 和参与者引用均有效。
- [x] 所有生成家庭均有唯一家长账号、俱乐部会员和家长档案，登录手机号可解析到正确家庭角色。
- [x] fixture 契约测试明确断言单孩/双孩/三孩家庭数量、最大孩子数、无重复万能绑定及关系引用完整性。
- [x] 小程序 smoke 不再期望单个家长返回 200 名孩子，并仍通过家长、教练、训练、比赛、评测与雷达链路。
- [x] API、domain、小程序类型检查和测试通过，200 人整体数据覆盖通过。
