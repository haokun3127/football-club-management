# V3 双端页面重组与改版

## Goal

把当前混杂在历史稿、CODE 稿和多轮局部改版区的在线 Figma，重组为两个**新增且非破坏性**的当前产品页面：家长端 V3 与教练端 V3。后续小程序改版只以这两个 V3 页面中的明确画板为实施基准，不再从旧稿、归档稿或 CODE 画板猜测。

## Confirmed facts

- 唯一在线设计文件为 `zZ6wKyOHKcO4UYXDd9jGwv`；原有页面 `05 Parent Generated`（`4:6`）和 `06 Coach Generated`（`4:7`）均已混入历史、CODE 和多批局部改版画板。
- 已验证的 V3 当前语义：教练日程展示全部有权限的球队课程；“我的球队／选择球队”只属于训练管理上下文；家长端底部栏为“日程 / 成长 / 发现 / 我的孩子”；家长日程默认周日历、下拉展开月历。
- 在线旧稿和已有 V3 区不得删除、覆盖或重新命名为当前稿；它们保留为历史审计材料。
- 小程序运行数据必须继续来自真实 API/会话；Figma 示例不能成为前端伪造数据或权限范围的依据。

## Requirements

1. 新增两个 Figma Page，而非继续向 `4:6`/`4:7` 堆叠：`10 Current Product · Parent V3` 和 `11 Current Product · Coach V3`。
2. 每页第一个画板为只读导航总览，清楚列出当前画板、对应小程序路由、状态（当前 / 待实现 / 历史不在本页）和日期；总览不是小程序 UI。
3. 家长 V3 首批收口当前四个一级入口的关键画板：日程（周态、展开月历、空态）、成长、发现、我的孩子；底部栏固定为“日程 / 成长 / 发现 / 我的孩子”。
4. 教练 V3 首批收口演示主链：全部球队日程、训练工作台、点名、比赛记录、满屏战术板、训练管理及选队、能力评估、我的；日程中不得出现选队。
5. 画板一律为 `375×812`，各画板命名以 `P*` 或 `C*` 路由编号开头；相同状态在同一流程内按阅读顺序排列，历史稿不在新页面复制。
6. 每次迁入现有画板前都读取现有在线节点、截图复核；无相应在线基准的新视觉只允许基于当前产品需求新增，且标为“待代码验收”。
7. 小程序随后按“一个画板／功能批次”实现和验收；本任务的页面整理本身不改后端契约、不伪造数据、不批量重构页面代码。
