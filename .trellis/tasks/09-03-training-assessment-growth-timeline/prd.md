# 训练评测、学期测评与成长足迹

## Goal

把训练课内的训练内容评测、按球队与学期执行的阶段测评、以及家长可追溯的成长足迹拆成三条边界清晰但共享真实数据的业务链。

## Confirmed facts

- 当前 C10 已能为活动保存训练内容；C15 只按模板录入，尚未与测评任务绑定；C11 的任务目前没有球队、学期或真实任务完成关联。
- 点名是唯一的课时同步入口。比赛不计训练课时；历史课时更正流已退休。
- P4 成长页当前只显示训练次数、出勤率、比赛/训练摘要和能力雷达，未提供详细的、可追溯成长时间线。
- 评估体系遵循 `docs/archive/2026-06-discovery/assessment-system-analysis.md`：原始测试值与标准分分离，长期能力数据通过 `PlayerMetricRecord` 统一输出，不把 Excel 树形样例写死为数据模型。

## Requirements

1. 每堂训练课的训练内容评测按“每个已到场学员 × 本堂课每项已选训练内容”记录，字段至少包含 `score_0_100`、可选教练备注、活动、训练内容、学员、记录教练和时间。
2. 训练内容评测必须校验：活动为训练、训练内容已属于该活动、学员属于该活动且已点名到场；不得通过前端参数绕过范围。
3. 学期测评任务一次绑定一个测评模板、一个球队和一个学期；默认覆盖该球队全部学员。
4. 学期测评提交必须显式绑定任务；任务完成度只计算该任务、该模板、该球队范围内的真实提交，不能再按日期窗口内任意指标记录推断。
5. 家长端成长足迹展示当前孩子的真实时间线：完成训练（日期、球队、场地、训练内容、训练内容评分/备注）、完成比赛（日期、对手/场地、比分、属于孩子的比赛事件）和能力模型更新（来源训练/学期测评、时间、受影响指标、更新前后分数或变化）。
6. 课时统计采用 `已到课时 / 应到课时`：应到为当前学员应参加且已结束、未取消的训练课；已到为其中点名 `present` 的训练课。比赛不计课时；充值余额仍属于“课时与保障”，不与出勤课时混合。
7. 教练端的训练评测、学期测评任务与学期测评录入都使用全屏页面和返回导航，不增加弹窗流程。
8. 视觉改动先更新在线 Figma 文件 `zZ6wKyOHKcO4UYXDd9jGwv` 的当前 Parent/Coach 交付页，再最小同步小程序；所有屏幕以真实 API 数据验收，不用静态样例伪造记录。

## Acceptance Criteria

- [ ] 训练内容评测可重启 API 后读回，且不能为缺席学员、非训练活动或未选训练内容写入。
- [ ] C11 能创建并显示“球队 + 学期 + 单测评项目”的任务；C15 从任务进入时将提交绑定到该任务，进度随真实提交更新。
- [ ] P4/成长足迹可展示并进入全屏查看训练、比赛和能力模型更新的详细记录，且只显示当前孩子可见数据。
- [ ] P4 明确显示 `已到课时 / 应到课时`，计算仅涵盖训练活动。
- [ ] 新增 API、持久化、页面 view model 均有先失败后通过的回归测试；小程序 TypeScript、相关 WXML/WXSS 编译和全仓 `pnpm run check` 通过。
- [ ] 每批单独写 Figma 节点、真实截图证据、文档记录和路径限定 Git 提交；不带入工作区其他未提交改动。

## Out of scope

- 不改变充值余额、线下外部课时同步或历史更正流程。
- 不实现任意公式 DSL、Excel 自动导入器或评估体系图谱重构；继续复用当前版本化模板、原始结果和指标记录能力。
- 不部署生产、导入测试数据或修改线上数据库，除非用户另行明确授权。
