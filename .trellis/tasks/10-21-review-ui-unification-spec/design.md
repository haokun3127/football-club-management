# 技术与交互设计

v1.1 · 2026-10-21 · 已随PRD获用户整版批准，分批实施中。产品规则和参数只在PRD定义，本文件只规定实现合同。

## 1. 组件选择与局部决策

保留原生小程序及现有API/鉴权/导航。通用控件用官方组件，业务卡片继续复用；不为每个官方组件再造一层包装。

| 能力 | 实现选择 | 不满足时的唯一处理 |
| --- | --- | --- |
| Button/Checkbox/Input/Textarea、导航/底栏/Tabs、Picker、Popup/Dialog、状态与反馈 | TDesign原生小程序包，主题映射现有token | 只为缺失的平台能力保留最薄原生封装，注明原因 |
| 微信手机号与隐私开放按钮 | 先核对TDesign公开透传；外观统一 | 无法完整透传open-type/事件时使用原生button，不更换授权机制 |
| 表单日期/时间 | TDesign Calendar/DateTimePicker | 明确min/max，不让组件默认范围挡住历史 |
| 主日程周/月业务网格 | 一个共享日程组件，两端传入各自授权活动 | 单月格若不能用Calendar公开API实现PRD的两行布局，直接使用共享薄网格；周边选择器仍用TDesign，不维护双端两套网格 |
| 个人雷达 | ECharts按需构建+echarts-for-weixin，统一radar-canvas外部接口 | 无法满足基础库/真机/包体时记录具体失败，暂停UI-05；其他批次继续，不能暗增第二种图表框架 |

实施只选稳定发布包并锁定精确版本，不引入TDesign开发仓库、UniApp/Vue及其包管理配置。组件资料链接见[evidence](research/evidence.md)。日期网格技术判定只需验证“单月、两行内容、受控日期、受限高度”；不做多个日历库选型竞赛。

TDesign npm构建在B1验证一次；Calendar能力判定属于B2；ECharts构建与兼容判定属于B4。三者不是彼此启动条件。

## 2. 主题与日历状态

`styles/tokens.wxss`是唯一运行时源。TDesign公开CSS变量映射至现有语义token，具体字号/按钮/动画值按PRD；不逐页手写新的同义变量。旧color-page/club-page和边距别名在迁移时统一指向批准值，仍被旧页面引用的键暂留兼容。

日历共享状态：`selectedDate`、`visibleMonth`、`viewMode`；列表锚点由各父页维护。业务日期使用Asia/Shanghai的YYYY-MM-DD键；现有领域函数优先复用，不直接从UTC ISO字符串截日期。

| 动作 | 状态变更 |
| --- | --- |
| 首次/页面重建 | 今天、当前月、周视图 |
| 展开/收起 | 只改viewMode，日期/筛选/列表锚点不变 |
| 点日期 | 改selectedDate及列表，保持当前viewMode |
| 切周/月 | 移动可见区间；有选中日则按对应日移动，月末夹取到有效日期 |
| 回今天 | 更新日期和所在周/月，保持当前viewMode |
| 详情返回/现存页再显示 | 保留页面状态；必要时刷新数据，不能重置选择 |

高度H按当前页面实际窗口减去自定义顶栏、底栏及安全区占用计算，不使用固定88px推算。月历总高度上限为0.65H，标题、星期和收起固定，网格占余下区域；网格允许内部纵滚，周视图不拦纵滚。点日期与滑动区分须用同一套判定，不在两端分别调整阈值。

同一天活动按现有业务时间排序，数量N为去重后的总数减已显示的一项；跨队同一活动按eventId去重，归属信息仍可在列表查看。七列均分，整格点击，名称省略只影响摘要，不截断完整列表和可访问文本。

## 3. 自动角色：先确定可进入角色，再创建会话

现状：`app-client.routes.ts:993`对active-role-switch-v1多角色登录返回activeRole=null；`login/index.ts`显示角色选择。只删前端选择页无法完成UI-01。

新客户端明确声明`auto-active-role-v1`能力；服务端增加对应分支，老`active-role-switch-v1`分支保持原行为。新增分支依以下顺序执行：

1. 账号全局受限：直接返回受限状态，不尝试换角色。
2. 从有效membership、客户端开放角色和有效角色档案得到授权集合A。缺少角色档案的身份不进入集合。
3. 从A得到可入端集合E：家长须有已绑定孩子；教练须有有效教练档案。先算E，再按PRD优先级选角色，不能先命中无孩子的家长就封锁有效教练。
4. E为空且A含未绑孩子家长：返回绑定提示；A为空返回未匹配档案；其他状态按现有错误合同。
5. 在E中校验上次角色、后台默认；仅剩一个可入端角色时直接选它。E仍有多个而无有效配置返回`role_configuration_required`语义的可恢复提示，不创建activeRole=null的新模式会话。
6. 沿用现有sessionRegistry创建有效activeRole会话；前端persistAuthenticatedSession后进入对应首页。登录跳转来源仅在目标角色有权时恢复。

### 最小配置合同（拟新增，不声称已有）

以`clubId + appClientId + userId`唯一关联两项可空角色偏好：`defaultRole`（后台管理员设置）、`lastActiveRole`（登录/切换成功后服务端写入）。优先复用经核对语义完全相同的配置存储；当前已读会话表只有activeRole，不能当作后台默认配置。没有同义字段时增加一份最小偏好记录及迁移，不重构用户/成员体系。

后台只在现有账号角色配置位置增加默认小程序角色，选项必须属于该账号有效授权集合；不另建角色管理模块。迁移不推测双角色默认，双角色账号需配置defaultRole才能通过首次登录验收；单角色不要求配置。

“我的”继续调用真实switchActiveRole，成功后记录lastActiveRole、更新令牌并清掉旧角色业务缓存。数据库字段、请求模式和前端入口同批B3交付；旧客户端分支不改，避免为了本轮做第二套登录系统。

勾选状态只维持本次登录页面；协议打开再返回保留，登录页重建初始未勾选。微信平台同意状态由既有隐私链路维护，勾选不能将平台privacyAgreed直接设true。App监听与privacy-authorize先复用，不额外注册重复监听。

## 4. 球队上下文与必要查询改动

| 状态 | 用途 | 来源优先级 |
| --- | --- | --- |
| scheduleTeamIds | 日程多队筛选 | 现有账号级偏好；按权限校正；不受activeTeamId变化影响 |
| activeTeamId | 球队工作区单队 | 显式参数 → 当前有效偏好 → 唯一授权队伍；多队无选择时选队 |

两者在相同环境/俱乐部/账号/角色命名空间内分开存储。明确参数无权时返回错误，不尝试下一优先级。日程单队入口传该队；多队入口选择一次；活动内上下文来自活动，不用偏好覆盖。

旧`coach-training-team-id`缺账号归属，**不迁移其值**。首次改版重新选择/采用唯一授权队，不因旧ID恰好仍授权就继承其他用户偏好；只丢弃界面偏好，不动业务数据。

| 入口/查询 | 必要改动与明确输出 |
| --- | --- |
| training、team-selector | 改为球队工作区及统一activeTeamId；训练列表按稳定teamId过滤，不以teamName匹配 |
| team与training-project-tree | 已有teamId参数，调用方显式传入；无课程不等于无球队，不以近30天活动推断授权球队不存在 |
| team-ability、student-radar | 将入口teamId一路传递；学员选择后也保留teamId，服务端按既有范围校验 |
| test-tasks | 当前读取无teamId；给函数、请求schema和现有GET coach/assessment-tasks增加可选teamId。显式队伍时只回本队任务和适用选项；未传参数保留既有全授权范围行为 |
| 任务创建 | 从单队入口带teamId作为初始选择，沿用原有项目/学员/课程可选范围和创建权限；日程跨队入口保留原选择流程 |
| event、match | 继续以原eventId读取；teamId只作来源校验，不改写活动归属 |

无权显式teamId须返回既有权限错误（不返回200默认队）；服务端独立校验，不能只前端过滤。快速切队/切指标请求以页面代际阻止旧响应覆盖新状态；沿用现有控制模式，不增加通用请求框架。

保留现有路由和深链，底栏文案及工作区布局替换即可。球队内只增加必要入口和参数，不补做完整档案/历史查询/友谊赛聚合。

## 5. 雷达数据合同

当前`RadarMetricPoint`仅有value/maxValue/occurredAt等字段；`GrowthSummary.views`在normalizeGrowth中已按有值指标过滤，不能直接拿它作为“所有可选指标”。新的适配必须保留后台已配置指标，包括缺测项；只在绘制阶段决定系列能否显示。

为避免前端跨多个成绩接口拼凑历史，B4新增两个遵守原授权范围的**同语义只读入口**：

- `GET parent/students/:studentId/radar-comparison`（完整前缀沿用现有clubs/app-clients路径）；
- `GET coach/students/:studentId/radar-comparison`，教练端带来源teamId并校验。

不替换原growth-summary和旧radar接口，不要求重写其余成长页。前端以独立适配函数调用；后端共用数据组装函数，鉴权分别复用监护授权/教练队伍授权，不用教练接口给家长取数据。

### 请求与响应（拟新增最小DTO）

请求可带`historyResultId`、`standardId`；不传则只返回当前系列及可选来源摘要，不组装历史/标准的轴数据。首次打开“对比”后按选项ID重读，过期/无权ID返回明确错误，不回落成另一份结果。

响应包含：

| 字段 | 必要语义 |
| --- | --- |
| views | 后台有效视图的id/name和有序metricIds，不过滤缺测指标 |
| axes | metricId、label、rawUnit、scoreMin/scoreMax、metricVersion、mappingVersion；轴顺序取所选视图 |
| current | kind=latest_per_metric，逐项事实ID、成绩日期、映射后分值、版本与状态；跨日期则标“最新各项”，不写成单次测评 |
| comparisonOptions | 该孩子/学员可读的已确认历史结果集ID、标签和日期；适用批准标准ID和适用说明；无来源时空数组及reason |
| selectedComparisons | 请求的历史/标准系列及逐项值、版本、日期；来源ID贯穿查询、图例和数值明细 |

历史结果集只由已有确认/发布记录生成，使用稳定结果集ID（可沿用taskId+确认修订号），不得将“每个指标的上一次”拼成同一场历史测评。没有可追溯结果集则没有该历史选项；验收样本须至少提供一份完整已确认集，不能以全空选项判完成。

每个值状态为measured（含0）、missing、unmapped或incompatible。草稿在此合同之外。可比性按**每根轴分别**核对定义和映射版本，所有轴使用后台批准的同一分值量尺；不能要求不同指标共用同一个metricVersion，也不能因两轴max相同就推断其单位可比。没有明确跨版本兼容记录时，仅按同版本比较，不重算旧成绩。

渲染时按所选metricIds对齐，各系列若任一轴缺失/不兼容则不画该系列多边形，给原因和明细；其余完整系列正常显示。指标/来源变更保留仍有效选择，清空全部图例时展示“已隐藏全部系列”和恢复按钮。无需依赖图表库的缺失值默认行为。

此只读合同是B4的必要交付，不得以先换ECharts皮肤代替。标准没有实际批准配置时不新造标准；历史真实可用时仍须完成多线功能。

## 6. 兼容与故障边界

新增字段和读取接口均增量兼容，事件、人员、任务和成绩事实ID不变。回退按批次回退UI/适配，不删除测评、课程或偏好数据；B3回退时保留旧客户端模式并恢复对应前端。图表失败只影响能力展示，不能阻塞名单、日程或球队入口。

依赖/图片变更后官方开发者工具检查包体；超预算先做按需构建/裁剪，不自动扩张分包重构。服务器和发布操作按现有交付流程另行授权，本文不是操作授权。
