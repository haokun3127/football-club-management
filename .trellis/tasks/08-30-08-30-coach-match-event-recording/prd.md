# 教练端比赛记录与事件录入

## Goal

让教练能够从训练工作台或比赛预览进入比赛记录，编辑比赛摘要，并以真实 API 保存进球、助攻、犯规、黄牌、红牌和乌龙等事件；保存后回到比赛页并重新读取，确保这些数据可进入学员训练生涯和家长端展示链路。

## Requirements

1. C6 比赛记录页必须有清晰可见的“编辑比赛”与“添加事件”入口，不能依赖不可发现的区域或弹窗。
2. C6.1 事件录入页使用全屏页面，支持事件类型、发生时间、球员、备注；事件类型至少包含进球、助攻、犯规、黄牌、红牌、乌龙。
3. 事件录入必须调用现有真实教练 API，禁止伪造 session、角色、响应或仅写本机假数据。
4. 保存后必须回到比赛页，并通过真实 GET 重新读取事件；重复提交使用幂等键，不产生重复记录。
5. 新增“犯规”时同步 domain、API schema、路由校验、能力策略、前端类型/标签/草稿校验及测试；犯规不应被错误映射为能力得分。
6. 生产能力策略允许通过私有运行时配置追加已支持的比赛事件类型，不能把生产账号或 token 写入源码、文档或测试。
7. 遵守小程序约束：WXML 不调用 `.map()`、`.filter()`、`.slice()`、`.indexOf()` 等 JS 方法；展示数据在 TS view model 预计算。
8. 只提交本任务涉及的文件；不连带 apps/api/src/persistence/*、apps/api/test/* 及其他用户在途文件。

## Acceptance Criteria

- [ ] C6 页面从真实教练会话可进入比赛摘要编辑和事件录入页。
- [ ] 进球、助攻、犯规、黄牌、红牌、乌龙均能通过真实 API 保存并在 C6 时间线重新读取。
- [ ] 事件保存后重启 API/持久化层仍能读回，且不重复。
- [ ] C6/C6.1 定向测试、domain/API/小程序门禁和 `git diff --check` 通过。
- [ ] 有可信 375x812 WeChatIDE 模拟器截图记录；截图只作为视觉证据，不以静态检查替代。
- [ ] `docs/current/progress.md` 记录实现范围、验证结果、未完成项和数据/API限制。
