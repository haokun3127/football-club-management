# 教练全队日程与训练管理球队上下文 V3

## 目标

纠正已废止的信息架构：教练端日程不再承担选队职责，而是展示该教练所负责的**全部球队**课程；“我的球队 / 选择球队”仅在训练管理中作为训练计划、出勤、评测与统计的上下文入口。同步新增家长端、教练端 V3 画板，保留所有旧画板不覆盖。

## 已确认的产品决定

- 日程是跨球队的时间轴：不显示“我的球队”卡、不读写 `coach-selected-team`、不按队伍过滤课程。
- 全队日程中每张课程/比赛卡都必须保留所属球队标签，以避免多队课程混淆。
- 训练管理顶部拥有唯一的“我的球队”上下文卡；只有这里可进入全屏“选择球队”。
- 队伍来源必须是真实后端返回的已分配队伍；前台不得新增、编辑或伪造队伍。
- 因 `/coach/training-project-tree` 已真实返回受权限约束的 `teamOptions`（id、name、season），训练管理以它作为队伍上下文权威；日程继续读取 `/coach/home` 的全量课程。
- 新设计在唯一在线 Figma 文件 `zZ6wKyOHKcO4UYXDd9jGwv` 中以 V3 区域新增，旧画板只保留为历史参照。

## 范围

1. 整理并补全上述四张在线 V3 画板：家长端月历基准、全部球队日程、训练管理球队上下文、训练管理全屏选择球队。
2. 移除 `pages/coach/schedule` 内的球队选择状态、入口及过滤；所有日程数据保持 API 全量。
3. 在 `pages/coach/training` 放入真实队伍上下文；选队后只展示该队训练/比赛数据和由这些数据推导的诚实统计。
4. 将 `pages/coach/team-selector` 明确限定为训练管理的全屏选择页，使用带 id 的真实 `teamOptions` 持久化上下文，选中后回训练管理。
5. 更新与本任务直接相关的 Figma 权威文档、进度记录和 Trellis 任务说明。

## 非范围

- 不改变日程 API 的访问控制或伪造/注入队伍。
- 不新增教练可创建、编辑、删除球队的能力。
- 不修改无关的家长端业务代码、数据库、生产数据或当前工作区中其他人的在途改动。
- 不把页面截图、Figma 导出或临时证据写入桌面或仓库。
