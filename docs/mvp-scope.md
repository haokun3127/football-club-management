# MVP 范围说明

## 产品定位

这个 MVP 不是先做完整的招生、缴费、媒体和 AI 平台，而是先做好青训俱乐部最核心的训练与比赛交付闭环：

1. 用统一活动日历管理球队、学员、家长、教练的训练、比赛和其他活动。
2. 支持学员加入多个球队，并支持球队训练、小班课、私教课等不同训练形态。
3. 把细化训练内容组合成标准化训练课程，并关联培养目标和能力指标。
4. 记录日常比赛和主要比赛数据，例如出场、进球、助攻和教练点评。
5. 将球员能力数据原子化，支持未来通过不同算法组合出新的评估指标。

第一版的目标是证明俱乐部可以稳定管理训练和比赛过程，并沉淀可信的球员成长数据。支付、CRM、公众号、抖音、视频号、小红书、AI 视频剪辑、场地评价和完整赛事运营的完整流程放到后续阶段。

但基础数据容器不能等到后续阶段才考虑。渠道、区域、学校、学员状态、联系人、沟通反馈、保险、收费和课时余额是青训俱乐部的高频运营事实，MVP 至少要在数据模型和导入能力上能承接，功能界面可以分阶段开放。

MVP 对保险、收费和课时的边界要清楚：只同步和展示线下确认后的数据状态，不在平台内做线上收费、在线投保、自动财务审核或完整课包消课闭环。

## 核心角色

| 角色 | MVP 职责 |
| --- | --- |
| 管理员 | 管理球队、学员、家长、教练、活动日历、训练内容、比赛记录和评测模板。 |
| 教练 | 查看日程，准备课程，记录考勤，完成训练记录，记录比赛数据，评测球员。 |
| 家长 | 查看孩子日程、训练重点、比赛记录、出勤记录和能力进展。 |
| 学员 | MVP 阶段不需要独立登录，学员数据由家长和教练侧承载。 |

## MVP 核心模块

### 1. 统一活动日历与参与关系

目标：每一个与学员相关的活动都能明确回答：什么活动、什么时间、什么地点、谁负责、哪些学员参加、最终发生了什么。

活动类型：

| 类型 | 用途 |
| --- | --- |
| 训练 | 球队训练、小班课、私教课、专项训练。 |
| 比赛 | 队内赛、友谊赛、日常联赛、杯赛中的单场比赛。 |
| 其他 | 外出参观、观看职业比赛、团建、讲座、测评日等非训练非比赛活动。 |

必备能力：

- 管理球队，支持年龄段、水平层级、默认教练等信息。
- 支持一个学员加入多个球队，并记录所属周期、主队标记和状态。
- 管理学员，并把每个学员绑定到一个或多个家长。
- 把教练分配到球队，也允许教练临时负责某个活动。
- 创建单次或周期性活动。
- 按球队、教练、学员、家长查看日程。
- 记录活动参与状态：参加、缺席、请假、迟到、特殊说明。
- 支持基础日程变更：取消、改期、更换教练、更换地点。
- 支持没有球队归属的小班课和私教课，只通过教练与学员参与关系组织。
- 对同一教练或同一学员的时间冲突给出基础提示。

MVP 页面：

- 管理端活动日历
- 教练周日程
- 家长孩子日程
- 球队活动列表
- 活动详情与参与记录页

关键原则：

- 日历活动是系统的业务骨架。训练计划、出勤记录、比赛数据和球员评测，优先关联到具体活动上。
- 学员是否参加某次训练或比赛，最终以活动参与记录为准，不只依赖球队成员关系。
- 私教和小班课不应被强行建成球队，它们是训练活动的一种组织形态。

### 2. 训练内容课程化与培养目标管理

目标：让训练交付可以复用、对比和追踪，而不是只依赖教练自由发挥或课后文字描述。

训练内容层级：

1. 培养维度：技术、身体、战术、心理、团队协作等大类。
2. 训练目标：具体目标，例如第一脚触球、传球准确性、1v1 防守、速度、观察扫描、射门终结。
3. 能力指标：可以被观察、评分或计算的原子能力项。
4. 训练练习：可复用的训练动作或组织方式，包括时长、器材、人数、场地布置、指导要点、难度和关联能力指标。
5. 课程计划：由多个训练练习组合成的一节完整训练课。
6. 实际训练：某个球队、小班或私教在某个时间真正执行的一节课。

建议课程结构：

| 课程环节 | 示例 |
| --- | --- |
| 热身 | 灵活性、球感、协调性 |
| 技术练习 | 传接球、带球、射门、防守 |
| 战术练习 | 1v1、2v2、抢圈、逼抢、攻防转换 |
| 比赛场景 | 小场比赛、限制条件比赛 |
| 复盘 | 教练总结、个人重点提醒 |

必备能力：

- 创建和管理培养维度。
- 创建和管理训练目标。
- 创建训练练习库，并用年龄段、水平、目标、时长、器材等标签分类。
- 将训练练习关联到一个或多个能力指标。
- 从训练练习库中组合一节课程计划。
- 把课程计划关联到实际训练活动。
- 支持球队训练、小班课、私教课、专项训练复用同一套课程计划结构。
- 课后记录实际完成情况，包括完成的训练环节、强度、整体表现和教练备注。
- 教练可以在课后针对单个学员记录轻量观察，并关联到能力指标。

MVP 页面：

- 培养维度与训练目标库
- 能力指标库
- 训练练习库
- 课程计划编辑器
- 训练活动中的课程计划
- 教练课后完成记录
- 学员课后观察记录

关键原则：

- 一节课不能只叫“足球训练课”。系统需要记录这节课练了什么、为什么练、哪些人参加、应该观察哪些能力变化。
- 训练过程要能反哺评估数据：课程目标、训练练习、课后观察都应该能落到球员能力指标上。

### 3. 日常比赛与主要表现记录

目标：把比赛作为训练体系的一部分，而不是后续才补的独立赛事功能。MVP 只做单场比赛记录和核心球员表现，不做复杂赛事运营。

比赛类型：

| 类型 | 示例 |
| --- | --- |
| 队内赛 | 训练中的分组对抗、内部测试赛。 |
| 友谊赛 | 与其他俱乐部或学校的交流赛。 |
| 日常联赛 | 俱乐部常规参加的联赛单场。 |
| 杯赛单场 | 杯赛中的一场比赛记录。 |

必备能力：

- 创建比赛活动，记录时间、地点、参赛球队、对手、比赛类型和负责人。
- 从球队成员中选择比赛名单，也允许临时加入其他球队的学员。
- 记录比赛状态、比分、上下半场或节次信息。
- 记录学员出场情况。
- 记录主要数据：进球、助攻。
- 支持可扩展的比赛事件类型，例如扑救、抢断、黄牌、红牌、点球、乌龙球，MVP 可以先只启用少量类型。
- 教练可以为比赛和单个学员添加点评。
- 比赛数据可以进入球员个人档案和能力评估数据源。
- 比赛事件可以关联能力指标，例如进球关联射门终结，助攻关联传球或决策。

MVP 页面：

- 比赛活动详情
- 比赛名单
- 比分与事件记录
- 球员比赛表现记录
- 家长侧比赛摘要

关键原则：

- 比赛是高价值评估场景。进球和助攻不是孤立荣誉，而是球员能力数据的一种来源。
- MVP 不做完整赛程编排、积分榜、淘汰图、报名收费和赛事官网，只做俱乐部日常训练体系需要的单场比赛记录。

### 4. 球员能力原子数据、跟踪与评测

目标：建立家长看得懂、教练用得上、未来算法可以复用的球员成长数据体系。

MVP 评测维度：

| 维度 | 示例指标 |
| --- | --- |
| 技术能力 | 第一脚触球、传球、带球、射门、防守、弱势脚 |
| 身体能力 | 速度、敏捷、平衡、耐力、协调性 |
| 战术理解 | 站位、决策、观察扫描、无球跑动 |
| 心理表现 | 专注、自信、抗压、纪律性 |
| 团队协作 | 沟通、配合、训练态度 |
| 比赛表现 | 出场、进球、助攻、关键行为、教练赛后评价 |

数据图谱：

| 对象 | 说明 |
| --- | --- |
| 指标定义 | 一个能力、行为、测试结果或计算结果，例如传球准确性、射门终结、比赛进球数、综合进攻贡献。 |
| 原子数据记录 | 某个学员在某个时间、某个活动、某个来源下产生的一条具体数据。 |
| 指标依赖 | 一个指标通过公式引用其他指标，生成新的评估结果。 |
| 评测模板 | 面向某个年龄段或水平层级的一组指标、公式和展示视图。 |
| 派生指标定义 | 通过规则或算法把多个指标数据组合成新指标，例如进攻贡献、技术稳定性。 |
| 派生指标记录 | 根据某个算法版本计算出的结果，本质上仍然是一条标准球员指标记录。 |

评测方式：

- MVP 可以使用 1-5 分作为一种人工评测量表，但评测模型不能固定为 1-5；也要支持 0-100、次数、时间、距离和百分比等指标值。
- 比赛数据使用计数型原子数据，例如进球数、助攻数、出场次数。
- 训练观察可以使用评分、标签或简短备注。
- 每条数据记录来源：训练活动、比赛活动、周期评测、体测或人工修正。
- 每条数据记录保留记录人、时间、单位、量表、可信来源和备注。
- 展示基准值、最新值、趋势和历史记录。
- 支持给单个球员设置阶段性培养目标。

派生指标原则：

- 新算法不应该覆盖原始数据，只生成新的派生数据。
- 派生指标必须记录算法名称、版本、输入指标、输入数据范围和计算周期。
- 派生结果应写成标准的球员指标记录，并标记来源为算法，方便后续继续被其他算法组合使用。
- 指标关系不是固定层级树，而是可复用的图谱；一个评估结果可以继续成为其他体系的输入。
- MVP 可以先支持简单规则，例如加权平均、最近 N 次平均、比赛数据累计、训练观察趋势。
- 后续 AI 或更复杂模型只作为新的派生指标来源接入，不改变原子数据结构。

必备能力：

- 按年龄段或球队水平配置评测模板。
- 教练定期录入球员评测。
- 教练在训练课后记录轻量观察。
- 教练在比赛后记录主要比赛数据。
- 按球员和能力指标查看进展。
- 生成简洁的家长侧成长摘要。

MVP 页面：

- 球员档案
- 能力评分表或雷达图
- 原子指标库
- 评测录入表
- 训练观察记录
- 比赛数据记录
- 评测历史
- 家长成长摘要

关键原则：

- 第一版不要假装 AI 已经客观测量了运动表现。MVP 阶段的数据应以教练确认的训练观察、比赛记录和周期评测为准。
- 能力评估不是一张固定表，而是一套可演进的数据体系。未来算法越复杂，越需要保护好原子数据和计算来源。

## 核心业务流程

### 流程 1：创建球队并安排活动

1. 管理员创建球队，填写年龄段、水平、默认教练和默认训练地点。
2. 管理员添加学员并绑定家长，一个学员可以加入多个球队。
3. 管理员为球队创建周期性训练活动，也可以创建比赛或其他活动。
4. 教练和家长可以看到对应日程。

### 流程 2：安排小班课或私教课

1. 管理员或教练创建训练活动，选择小班课或私教课类型。
2. 系统不要求选择球队，只要求选择教练、学员、时间和地点。
3. 教练为活动选择课程计划或训练目标。
4. 课后记录参与情况、训练内容和学员观察。

### 流程 3：准备并完成一节训练课

1. 管理员或教练为训练活动选择课程计划。
2. 教练课前查看训练目标、练习安排和建议观察指标。
3. 教练课中或课后记录参与状态。
4. 教练标记实际完成的训练内容并填写课后记录。
5. 教练针对重点学员记录能力观察。
6. 训练数据进入球队、教练和学员历史。

### 流程 4：记录一场比赛

1. 管理员或教练创建比赛活动。
2. 教练确认比赛名单。
3. 比赛后记录比分、出场、进球、助攻和教练点评。
4. 比赛数据进入球队比赛历史和球员个人档案。
5. 关键比赛行为成为球员能力评估的数据来源。

### 流程 5：评测球员成长

1. 管理员为年龄段或水平层级配置评测模板。
2. 教练定期对球员进行能力评测。
3. 系统把训练观察、比赛数据和周期评测作为不同来源的数据保存。
4. 每次评测保存为历史记录。
5. 家长查看简化后的成长进展。
6. 教练根据薄弱项调整后续训练目标。

## 核心数据模型

| 实体 | 用途 |
| --- | --- |
| User | 登录账号与角色身份。 |
| Parent | 家长资料与联系方式。 |
| Student | 球员档案、年龄段、水平、证件匹配、入训状态和基础足球资料。 |
| StudentContact | 学员联系人，支持多个电话、微信、关系和通知偏好。 |
| StudentOperationalProfile | 学员运营资料，例如渠道、区域、学校、沟通阶段、负责教练和运营备注。 |
| Coach | 教练资料、专长和活动分配。 |
| Team | 训练球队或梯队。 |
| TeamMember | 学员与球队的成员关系，支持多队、周期和主队标记。 |
| Region | 俱乐部区域或校区目录。 |
| School | 学员学校目录。 |
| AcquisitionChannel | 招生或来源渠道目录。 |
| CoachAssignment | 教练与球队或活动的分配关系。 |
| TrainingLocation | 训练、比赛或其他活动地点基础信息。 |
| CalendarEvent | 统一活动日历，类型包括训练、比赛和其他。 |
| EventParticipant | 学员在活动中的参与记录。 |
| TrainingSession | 训练活动扩展信息，支持球队训练、小班课和私教课。 |
| Attendance | 学员在训练或活动中的参与结果。 |
| DevelopmentDimension | 技术、身体、战术等培养大类。 |
| TrainingObjective | 某个培养维度下的具体训练目标。 |
| AbilityMetric | 能力、行为、测试或计算指标定义。 |
| MetricDependency | 指标之间的公式引用关系。 |
| MetricView | 某个模板或报告里的指标展示视图。 |
| TrainingDrill | 可复用训练练习，并关联训练目标和能力指标。 |
| SessionPlan | 由多个训练练习组成的课程计划。 |
| SessionPlanBlock | 课程计划中的单个训练环节。 |
| SessionDelivery | 实际训练完成记录。 |
| SessionObservation | 教练对单个学员在训练中的能力观察。 |
| Match | 比赛活动扩展信息，包含对手、比分、比赛类型和状态。 |
| MatchRoster | 某场比赛的学员名单与出场信息。 |
| MatchEvent | 比赛事件，例如进球、助攻、扑救、牌类事件。 |
| MatchPlayerNote | 教练对球员单场比赛表现的点评。 |
| OtherActivity | 其他活动扩展信息，例如外出参观、观赛、讲座。 |
| AssessmentTemplate | 按年龄段或水平配置的评测模板。 |
| AssessmentMetricBinding | 评测模板对指标图谱中指标、公式和输出结果的引用。 |
| PlayerAssessment | 某个球员在某个时间点的一次评测。 |
| AssessmentScore | 单个评测指标的分数和评语。 |
| PlayerMetricRecord | 球员指标数据记录，来源可以是训练、比赛、评测、体测或算法派生。 |
| DerivedMetricDefinition | 派生指标定义，记录算法、版本、输入指标、输入范围和计算周期。 |
| MetricLineage | 指标血缘，记录派生数据由哪些原始或派生记录计算而来。 |
| PlayerDevelopmentGoal | 球员个人阶段性培养目标。 |
| PaymentEvent | 收费或充值事件，MVP 仅承接线下确认或 WPS 同步结果。 |
| LessonCreditLedger | 课时入账、消课、调整和余额计算流水，MVP 以外部同步和状态展示为主。 |
| InsurancePolicy | 学员保险购买、保单、到期和审核记录，MVP 仅同步保险状态和到期信息。 |
| CommunicationLog | 面向家长或学员的沟通跟进记录。 |
| CustomFieldDefinition | 俱乐部自定义字段定义。 |
| CustomFieldValue | 类型化自定义字段值。 |

## MVP 边界

本期包含：

- 球队、学员、家长、教练管理。
- 学员多球队归属。
- 统一活动日历：训练、比赛、其他。
- 球队训练、小班课、私教课。
- 训练参与记录和考勤。
- 培养维度、训练目标、能力指标和训练练习库。
- 课程计划组合。
- 教练课后记录和学员训练观察。
- 日常比赛单场记录。
- 比赛出场、进球、助攻和教练点评。
- 球员原子能力数据记录。
- 球员能力评测和简单派生指标。
- 家长侧成长摘要。
- 学员基础运营字段的数据承接，包括渠道、区域、学校、联系人、学员状态和保险到期快照。
- WPS/Excel 表格导入和后续 WPS API 自动同步的字段映射、数据校验和 staging 基础。
- 保险、收费、课时余额等线下确认数据的同步、确认、状态流转和状态展示。

本期不做：

- 完整支付收款流程、在线交易执行和无审核自动课包消课。
- 平台内线上收费、在线支付、退款、发票和财务结算。
- 平台内在线投保、保险购买流程和保险理赔流程。
- 完整 CRM 和线索转化流程。
- 公众号、视频号、抖音、小红书内容发布。
- AI 视频剪辑。
- 计算机视觉自动评分。
- 完整赛事运营，例如报名收费、复杂赛程编排、积分榜、淘汰图和赛事官网。
- 场地评分和维护流程。
- 装备销售。
- 复杂通知和企业微信集成。

## 验收标准

MVP 完成时应该做到：

- 管理员可以创建球队、绑定学员和家长、分配教练、安排训练、比赛和其他活动。
- 一个学员可以同时属于多个球队，并在不同球队中参与不同训练和比赛。
- 教练可以创建或执行球队训练、小班课和私教课。
- 教练可以打开今日活动，看到参与名单、训练计划或比赛信息，完成参与记录和课后记录。
- 教练可以记录单场比赛比分、出场、进球、助攻和球员点评。
- 家长可以查看孩子接下来的活动、历史参与记录、比赛摘要和基础成长摘要。
- 教练可以录入球员能力评测，并查看训练观察、比赛数据和周期评测带来的历史变化。
- 训练历史可以回答：谁在什么时候、跟哪个教练、练了什么、关联了哪些培养目标和能力指标。
- 比赛历史可以回答：谁参加了哪场比赛、比分如何、谁进球、谁助攻、教练如何评价。
- 球员历史可以回答：哪些能力在提升、哪些能力需要加强、哪些数据来自训练、比赛或评测、下一阶段训练重点是什么。

## 后续叙事预留

MVP 不实现这些能力，但数据结构要为它们留出口：

- AI 根据出勤、训练内容、比赛数据和评测数据生成教练报告初稿。
- AI 辅助视频打点和精彩片段剪辑，并关联到训练或比赛活动。
- 精英球员档案，包含认证评测、比赛视频、发展计划和展示页。
- 更复杂的运动表现算法，基于原子数据组合出新的技术、战术和比赛贡献指标。
- 场地质量记录，关联训练体验和安全反馈。
- 公众号、视频号、抖音、小红书的内容分发，基于系统内已有训练和比赛素材生成。
