# 小程序技术选型与开发工作流

## 适用范围

本文档约束重庆天才小程序及后续多俱乐部小程序开发。适用对象包括：

- 小程序前端页面、组件和工具库。
- 小程序 BFF/API 契约。
- 需要引入第三方依赖的图表、拖拽、Canvas、地图、富文本、通知等能力。
- 会影响家长端/教练端数据口径、权限边界或性能包体的技术决策。

所有进入开发的功能必须先通过本文档定义的工作流。产品规格文档只说明“做什么”；本文档说明“如何进入开发、如何选型、如何验收”。

## 强制产物

每个小程序功能进入开发前必须具备以下产物：

| 产物 | 文件/位置 | 负责人 | 必填 |
| --- | --- | --- | --- |
| 产品规格 | `docs/miniprogram-product-design-cq-talent.md` 或后续俱乐部规格 | 产品/总控 | 是 |
| 技术工作流检查 | 本文档对应 checklist | 总控/实现方 | 是 |
| API 契约草案 | OpenAPI、接口表或 BFF 需求清单 | 后端/总控 | 是 |
| 选型记录 ADR | 本文档 `ADR 模板` 或单独 `docs/adr/*.md` | 实现方 | 涉及依赖/架构时必填 |
| 依赖登记 | 本文档 `依赖登记表` 或单独依赖清单 | 实现方 | 涉及依赖时必填 |
| PoC 验收记录 | 本文档 `PoC 验收清单` | 实现方 | 涉及交互/性能风险时必填 |
| 开发验证记录 | 测试输出、真机/开发者工具截图、检查结果 | 实现方 | 是 |

## 阶段门禁

### G0 产品冻结

进入技术设计前必须确认：

- 页面职责已经明确。
- 用户角色和权限边界已经明确。
- 空状态、错误状态、只读/可写边界已经明确。
- 对应 BFF/API 数据需求已经列出。
- 不做项已经写清楚。

未通过 G0 时，不允许开始技术选型。

### G1 技术选型

涉及第三方库或关键实现路径时，必须完成：

- 官方文档核验。
- npm 当前版本核验。
- 最近发布时间/维护状态核验。
- 小程序运行时兼容性核验。
- 包体大小与分包影响评估。
- 与现有技术栈冲突评估。
- 是否有原生实现可替代。

选型原则：

1. 微信小程序原生能力优先。
2. 能自研小组件解决的，不引入大图表/跨端框架。
3. 第三方依赖必须版本明确、维护状态可接受、License 可用。
4. 任何图表/Canvas/拖拽库必须做小程序真机或开发者工具 PoC。

### G2 API 契约

前端开发前必须明确：

- 请求路径。
- 请求参数。
- 响应结构。
- 权限校验口径。
- 错误码。
- 缓存/幂等策略。
- 数据更新时间和来源字段。

小程序不直接推导业务模型，不在前端硬编码重庆天才字段。

### G3 PoC 验证

以下情况必须做 PoC：

- Canvas 图表。
- 战术板拖拽。
- 大列表录入。
- 自动保存。
- 地图/导航。
- 富文本内容页。
- 公众号/小程序消息联动。
- 任何会影响包体或基础库兼容的依赖。

PoC 只验证关键风险，不做完整业务实现。

### G4 实现

实现阶段必须：

- 使用 G2 已确认的 API 契约。
- 依赖版本固定，不使用浮动版本。
- 不在小程序端复制后端业务规则。
- 不绕过 `clubId/clientId/capabilities`。
- 不引入未登记依赖。

### G5 验证

完成后必须至少验证：

- 构建通过。
- 类型检查通过。
- 关键页面空状态/错误状态可达。
- 微信开发者工具或真机渲染正常。
- 关键交互无明显卡顿。
- 低权限用户看不到不该看的入口。
- BFF/API 403/404/网络失败处理正确。

涉及 Canvas/图表/拖拽时必须补充截图或录屏记录。

### G6 交付

交付说明必须包含：

- 变更文件。
- 已验证项。
- 未验证项和原因。
- 新增依赖及版本。
- 是否需要后台/WPS 配置。
- 是否需要后续技术债记录。

## 依赖选型流程

### 选型检查表

| 检查项 | 要求 |
| --- | --- |
| 官方来源 | 必须能找到官方文档或官方仓库 |
| 当前版本 | 使用 `npm view <pkg> version time.modified license dist.unpackedSize --json` 核验 |
| 维护状态 | 最近 12-18 个月有维护更佳；长期不维护需说明风险 |
| License | MIT、Apache-2.0 等可接受；其他需单独确认 |
| 包体 | 记录 `dist.unpackedSize`，评估小程序分包影响 |
| 运行时 | 确认支持微信小程序基础库和 Canvas/组件限制 |
| 冲突 | 确认不强依赖 DOM、window、document、WebGL 等不稳定能力 |
| 替代方案 | 必须评估原生实现或更小依赖 |
| PoC | 对渲染/交互类依赖必须做 |

### 依赖登记表

| 能力 | 决策 | 包/版本 | License | 包体/维护 | 结论 |

| 雷达图 | 原生 Canvas 2D 自绘 | 无第三方依赖 | 不适用 | 不增加包体 | 采用 |
| 复杂多图表备选 | ECharts 小程序适配 | `echarts@6.1.0`；`echarts-for-weixin@1.0.2`（npm）；GitHub release 需另核 | Apache-2.0/MIT | ECharts 包体大，wrapper npm 多年未更新 | 暂不采用，未来复杂图表 PoC 后再评估 |

## ADR-001：雷达图技术选型

### 状态

Accepted

### 日期

2026-06-28

### 背景

家长端和教练端都需要雷达图：

- 家长端成长 Tab 展示孩子能力雷达图、同龄平均、指标下钻。
- 教练端训练管理展示学员雷达图、全队能力概览。
- 训练内容选择页需要能力覆盖预览，可用雷达图或覆盖列表。

首版图表需求有限：6-10 个维度、孩子值/同龄平均两条数据、点击指标下钻、少量空值处理。没有复杂联动、缩放、多图表组合或后台下发图表配置的需求。

### 备选方案

| 方案 | 版本/状态 | 优点 | 风险 | 结论 |
| --- | --- | --- | --- | --- |
| 微信小程序原生 Canvas 2D 自绘 | 微信原生能力；建议基础库 `>= 2.9.0` | 无依赖、包体小、可控、冲突少 | 需要自行实现坐标、标签、点击命中 | 采用 |
| ECharts + echarts-for-weixin | `echarts@6.1.0`；`echarts-for-weixin@1.0.2` npm 包多年未更新 | 功能完整，雷达图成熟 | 包体大，wrapper 维护风险，Canvas 兼容需 PoC | 暂不采用 |
| AntV F2 / wx-f2 | `@antv/f2@5.14.0`；`@antv/f-wx@1.10.0`；`@antv/wx-f2@2.1.1` | 移动图表能力强 | 仍引入图表栈，需适配 PoC | 暂不采用 |
| uCharts | `@qiun/ucharts@2.5.0-20230101` | 跨端图表常见 | 版本旧，维护和兼容需验证 | 暂不采用 |

### 决策

雷达图采用项目内自研 `RadarCanvas` 小程序原生组件。

技术口径：

- 使用小程序原生 Canvas 2D。
- 数据由 BFF 返回，组件不计算模型。
- 组件只负责绘制、点击命中和展示空值。
- 不引入第三方图表库。

### `RadarCanvas` 输入契约

```ts
interface RadarMetricPoint {
  metricId: string;
  label: string;
  value?: number;
  peerAverage?: number;
  maxValue: number;
  drilldown?: {
    type: "metric" | "radar";
    targetId: string;
  };
}

interface RadarCanvasData {
  title?: string;
  ageGroup?: string;
  updatedAt?: string;
  metrics: RadarMetricPoint[];
}
```

### 组件验收条件

- [ ] 6-10 个指标在 iPhone 小屏和常规安卓尺寸中标签不重叠到不可读。
- [ ] 孩子值和同龄平均两条多边形可区分。
- [ ] 某指标缺少值时不画误导性 0 分。
- [ ] 点击指标标签或轴区域能触发下钻。
- [ ] 画布尺寸变化后可重绘。
- [ ] 截图/分享时渲染稳定。
- [ ] 不依赖 DOM、window、document。

### 回滚策略

如果自绘无法满足后续复杂图表需求，再进入新的 ADR，优先评估：

1. ECharts 自定义构建 + `echarts-for-weixin`。
2. AntV F2 小程序适配。

必须先做包体和真机 PoC。

## PoC 验收清单

### 雷达图 PoC

| 项目 | 验收 |
| --- | --- |
| 渲染 | 6/8/10 维雷达图均可渲染 |
| 数据 | 支持孩子值、同龄平均、空值 |

| 适配 | 小屏、常规屏、较大屏布局稳定 |
| 包体 | 不引入第三方图表依赖 |

### 战术板 PoC

| 项目 | 验收 |
| --- | --- |

| 项目 | 验收 |
| --- | --- |

## 小程序功能开发检查清单

### 开发前

- [ ] 产品规格已冻结。
- [ ] 角色和权限边界已明确。
- [ ] BFF/API 契约已列出。
- [ ] 选型 ADR 已完成。
- [ ] 依赖版本已登记。
- [ ] PoC 范围已明确。

### 开发中

- [ ] 所有业务请求通过 resolve 后的 `clubId/clientId/capabilities`。
- [ ] 不写死重庆天才业务字段。
- [ ] 图表和训练能力数据由 BFF 返回。
- [ ] 低权限入口隐藏，后端再次校验。
- [ ] 写入请求具备幂等或审计策略。

### 开发后

- [ ] 构建通过。
- [ ] 类型检查通过。
- [ ] 关键页面在微信开发者工具验证。
- [ ] 空状态、403、404、网络失败已验证。
- [ ] 图表/拖拽/自动保存有截图或录屏。
- [ ] 新增依赖与版本写入依赖登记。
- [ ] 文档更新。

## 技术风险登记

| 风险 | 影响 | 处理 |
| --- | --- | --- |
| 微信消息能力限制和公众号身份匹配不确定 | 日程提醒无法按理想方式触达 | 消息能力单独 PoC，按官方规则调整 |
| 战术板拖拽与页面滚动冲突 | 比赛日工具难用 | 先做拖拽 PoC，再进入业务实现 |
| 雷达图标签在小屏重叠 | 成长页可读性差 | 自绘组件必须完成多尺寸验收 |
| 测试录入自动保存弱网失败 | 成绩丢失 | 本地保留输入，失败重试 |
| 赛事库自由文本污染 | 长期比赛数据不可治理 | 技术上按 Competition 设计，教练输入作为待规范化 |
