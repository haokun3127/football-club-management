# 重庆天才小程序技术实现与部署选型评估

本文档基于当前后端骨架、重庆天才足球俱乐部小程序产品设计和多俱乐部扩展目标，评估小程序技术实现逻辑、组件选型、部署边界和云厂商选择。

## 结论

- 核心平台部署在我们自己的云账号和服务器环境中，统一承载多俱乐部数据、权限、隐私、WPS 同步、指标图谱、日程和业务 API。
- 每个俱乐部可以拥有独立微信小程序和独立展示体验，但小程序只消费核心平台能力，不持有独立业务模型。
- 重庆天才足球俱乐部首个小程序建议使用微信原生小程序 + TypeScript 开发，不先引入 Taro/uni-app 这类跨端框架。
- 首期部署建议优先选择腾讯云作为基线。它和微信小程序、微信支付、云开发/CloudBase、域名备案链路的协同更直接。
- 阿里云可以作为核心平台部署备选，尤其适合团队已有阿里云运维体系的情况；但微信小程序侧仍要满足微信平台的合法域名、HTTPS、备案和接口调用要求。
- 俱乐部购买的小程序云环境默认不放核心数据库。它只作为小程序侧资源、轻量云函数、临时文件、媒体处理或未来支付扩展的可选能力。

## 技术实现逻辑

小程序启动流程：

1. 小程序根据 `appId` 或预置 `clientKey` 请求 `/app-clients/resolve`。
2. 后端返回 `clubId`、`clientId`、俱乐部能力配置、客户端功能开关和可见性策略。
3. 小程序完成微信登录，后端建立 `clubId + clientId + wechatOpenId/unionId -> parentProfile/coachProfile` 的绑定关系。
4. 小程序按角色进入家长端或教练端，只调用 `/clubs/:clubId/app-clients/:clientId/...` 下的 BFF 接口。
5. 页面展示字段、评测视图、保险/课时状态、媒体/AI入口、日程类型全部来自 capabilities 和 BFF 响应。

关键边界：

- 不把重庆天才字段、WPS 表格字段、评分表结构写进小程序代码。
- WPS 授权、字段映射、同步策略、导入确认和异常处理全部在核心平台后台完成。
- 小程序不直接连接 WPS，不保存 WPS access token，不预览 raw records。
- 小程序不维护保险、课时、收费、评测计算等核心状态，只展示核心平台已经确认的业务事实。
- 用户隐私字段只展示后端脱敏后的结果，小程序不得本地缓存身份证、完整联系方式、raw 同步记录等敏感数据。

## 组件选型

| 领域 | 推荐选型 | 说明 |
| --- | --- | --- |
| 小程序框架 | 微信原生小程序 + TypeScript | 首个目标就是微信小程序，原生方案最贴近微信能力、审核和性能模型。 |
| 跨端框架 | 暂不采用 | Taro/uni-app 适合明确要同时做多端时引入；当前会增加抽象层和调试成本。 |
| UI 组件 | TDesign MiniProgram + 少量自研业务组件 | 基础表单、弹层、按钮、列表用成熟组件；日程、评测雷达、教练点名等做业务组件。 |
| 图表 | ECharts 微信小程序版或 AntV F2，首期优先 ECharts | 能力趋势、雷达图、折线图是主要场景；图表只消费后端聚合结果。 |
| 日历 | 自研业务日历组件 | 训练、比赛、其他活动、孩子切换、冲突提示、参与状态强业务化，通用日历组件只能做底座。 |
| API 类型 | OpenAPI 生成 TypeScript 类型 + 手写 `wx.request` wrapper | 保持契约一致，不引入过重运行时 SDK。 |
| 状态管理 | 轻量 store | 只管理 session、capabilities、当前角色、当前孩子、日期筛选和短期缓存。 |
| 缓存 | 小程序端短缓存 + 后端 ETag/private cache | 日程和首页允许短期缓存；敏感详情不做长期本地持久化。 |
| 监控 | requestId + 后端日志审计，后续接入云日志/前端异常平台 | MVP 先保证可定位请求链路，再补齐前端异常采集。 |

不建议首期采用的能力：

- 不在小程序云数据库里复制核心业务数据。
- 不在小程序端运行评测公式和指标图谱计算。
- 不在小程序端做 WPS webhook、同步调度或导入确认。
- 不在小程序端直接接支付状态机；未来支付也应由核心平台统一落账和对账。

## 部署方案

### 核心平台

核心平台由我们统一部署，建议分两阶段。

MVP 内测阶段：

- 单区域部署 API 服务。
- Node.js 运行时按部署文档使用 `24.x`，兼容已验证的 `22.12+`。
- 使用 HTTPS 反向代理和独立 API 域名，例如 `api.<平台域名>`。
- API 域名配置为微信小程序 request 合法域名。
- SQLite 只作为早期单实例内测数据库，必须有持久化卷、备份和恢复演练。
- WPS 同步、Excel 导入和批量任务限流，避免影响家长/教练端高频访问。

生产多俱乐部阶段：

- API 容器化部署，支持滚动发布。
- 数据库迁移到托管 PostgreSQL 或 MySQL。
- 引入 Redis 或等效托管缓存，用于 session、限流、幂等响应缓存和热点配置。
- 对象存储承载媒体附件、导入文件、导出文件和未来 AI 视频产物。
- 日志、审计、告警、备份和恢复流程纳入生产准入。

### 俱乐部小程序云环境

每个俱乐部可以独立购买或开通自己的微信小程序云环境，但首期不要求购买数据库。

适合放在俱乐部云环境的内容：

- 小程序云开发环境配置。
- 俱乐部独立静态资源、主题资源和临时文件。
- 与小程序审核、体验版、测试链路相关的轻量云函数。
- 未来如需要的图片处理、订阅消息辅助任务或微信支付辅助能力。

不适合放在俱乐部云环境的内容：

- 学员主档、家长联系方式、课时余额、保险状态、训练观察、比赛数据、评测结果。
- WPS access token、refresh token、webhook secret、字段映射和同步队列。
- 评测指标图谱、公式、lineage 和跨俱乐部通用配置。

这样设计可以让不同俱乐部拥有不同小程序体验，同时保证平台数据治理、隐私保护、同步幂等和业务演进不被拆散。

## 腾讯云与阿里云评估

### 腾讯云

优势：

- 与微信小程序、微信支付、云开发/CloudBase 生态协同更自然。
- 小程序云环境、云函数、云存储、消息能力和微信开发者工具的联调链路更直接。
- 首个客户是微信小程序场景，腾讯云能减少小程序侧环境、域名、联调和审核沟通成本。

风险：

- 如果核心平台大量使用 CloudBase 专有能力，未来迁移到其他云会增加成本。
- 需要明确边界：CloudBase 可用于小程序外围能力，核心业务仍以标准 API、数据库、对象存储和缓存为主。

### 阿里云

优势：

- ECS、RDS、OSS、SLS、云监控等基础设施成熟，很多团队和企业客户更熟悉。
- 如果公司现有域名、备案、运维、数据库和监控体系都在阿里云，核心平台放阿里云也可行。
- 对标准 Node.js API、托管数据库、对象存储、日志和 CDN 没有技术障碍。

限制：

- 微信小程序可以通过 HTTPS 合法域名访问阿里云上的 API，但小程序云开发、微信支付和微信生态联调不如腾讯云顺手。
- 仍然需要在微信公众平台配置 request 合法域名，并满足 HTTPS、备案、证书和安全要求。

### 推荐口径

首个重庆天才小程序建议：

- 核心平台：腾讯云优先，使用标准云服务器/容器 + 托管数据库演进路线，避免过度绑定 CloudBase。
- 小程序外围：可以使用微信小程序云开发/腾讯云 CloudBase，但不购买独立核心数据库。
- 对象存储、日志、Redis、数据库：按生产阶段逐步引入，先保证标准接口和可迁移性。

如果团队已经有稳定阿里云运维体系：

- 核心平台可以部署在阿里云。
- 小程序仍通过微信合法域名访问核心 API。
- 俱乐部小程序云环境仍可用腾讯/微信云开发做外围能力。

不建议 MVP 阶段把核心 API 同时拆到腾讯云和阿里云。跨云会增加网络、备案、证书、日志、故障定位和数据一致性成本。

## 支付与数据库购买判断

MVP 不做线上支付、在线投保和财务结算，所以首期不需要为每个俱乐部购买独立支付能力或独立数据库。

仍然必须在核心平台流转的状态：

- 课时剩余、课时变更来源、更新时间、人工确认状态。
- 是否投保、保险有效期、保险来源、更新时间、人工确认状态。
- 到课状态、请假/缺勤状态、训练参与记录。
- 线下收费确认结果和同步状态。

未来启用线上支付时：

- 由核心平台维护订单、支付状态、对账、退款和课时入账。
- 俱乐部可以使用自己的微信支付商户号，或平台按业务合规要求设计服务商/子商户模式。
- 小程序只发起支付和展示结果，不直接决定课时余额。

## 分阶段落地

### P0：部署准入

- 选定首个云厂商和区域。
- 准备 API 域名、HTTPS 证书、ICP备案和微信小程序 request 合法域名配置。
- 核心平台完成 `pnpm check && pnpm build`、迁移、健康检查和 smoke 测试。
- 确认 WPS 开发者账号、授权方式和重庆天才表格映射。

### P1：小程序技术底座

- 创建微信原生小程序项目。
- 接入 TypeScript、TDesign、请求 wrapper、OpenAPI 类型生成。
- 实现 `/app-clients/resolve`、登录绑定、capabilities 拉取和角色入口。
- 实现家长端、教练端的空状态、错误态、加载态和 requestId 展示。

### P2：业务闭环

- 家长端接入孩子列表、日程、活动详情、成长摘要、保险/课时状态。
- 教练端接入今日课表、活动点名、训练观察、比赛事件、评测录入。
- 所有写操作使用 `Idempotency-Key`。
- 所有敏感读取遵循后端隐私策略，不在小程序端绕过字段可见性。

### P3：生产强化

- 数据库迁移到托管数据库。
- 引入 Redis 缓存、限流和幂等记录优化。
- 对象存储接入媒体、导入文件和导出文件。
- 完成日志、审计、告警、备份、恢复演练和 WPS 自动同步任务监控。
