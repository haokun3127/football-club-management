# 07 发布审核与运营红线

出处：`pages/quickstart-release.md`、`pages/product-reject.md`、`pages/product-ops-spec.md`、`pages/product-record-guidelines.md`、`pages/security-basic.md`

## 版本与权限模型 `[官方]`

- 四个版本：**开发版**（每人只保留最新一份上传代码）、**体验版**（从某个开发版指定，只能有一份体验版）、**审核中版本**（同时只能有一份）、**线上版**。
- 版本权限要点：提交审核 / 发布 / 回退 / 下架是**敏感操作，只给小程序的必要人员**。
- 项目成员（可登录后台：运营者/开发者/数据分析者）与体验成员（只能用体验版）分开管理。
- 发布路径：预览 → 上传代码 → 提交审核 → 发布；另有小程序码、运营数据等入口。

## 备案（法律前置项，不备案不能上线）`[官方]`

- 法律依据：反电信网络诈骗法第 23 条（移动互联网应用程序须办理许可或备案）、互联网信息服务管理办法（未取得许可或未履行备案手续不得从事互联网信息服务）。
- 入口：新增（未上架）小程序 **2023-09-04** 起开放备案入口；已上架小程序在后台顶部/设置-小程序备案进入；存量提交有动态配额（当日用完次日 10 点刷新）。
- 流程：备案信息填写（主体/主体负责人/小程序/小程序负责人 + 人脸核身）→ 平台初审 → 工信部短信核验 → 通管局审核 → 备案成功 → **备案号悬挂**（按规定展示备案编号）。
- 材料：小程序备案材料 + 单位有效证件 + 个人身份证件（非个人备案），个别省份另有补充材料或前置审批。

**本项目要确认的事**：小程序（`wx4c588cd106e520e0`）是否已完成备案、备案主体是否为俱乐部/办学主体、备案号是否已在必要位置展示。这些**只能在小程序后台和备案系统核对**，代码里无法验证。

## 常见拒绝情形——与本项目直接相关的条目 `[官方]`

服务类目与首页：

- 3.1.2 **首页必须能直达、或在 2 次点击内到达**所有已提交服务类目的页面。（本项目是三角色分流 + 无 tabBar，家长端/教练端的功能发现路径要在验收里明确走一遍。）
- 3.1.5 功能不能过于简单（只有一页一按钮）；3.1.3 不得超出已开放类目。
- 3.1.4 有隐藏/付费功能时，开发者需提供**可完整体验该功能的测试号**。

可用性与完整性：

- 3.3.1 提交的必须是完成品：能打开、能运行、按钮有响应、文案完整。
- 3.3.3 存在严重 Bug（无法返回/退出、严重卡顿）直接拒绝。
- 3.3.4 **有账号体系必须提供测试号（账号 + 密码）且能体验所有功能** —— 本项目当前用手机号授权登录，提交审核时要按平台要求准备可用的测试账号与说明（这是实际卡审核的高频原因）。

隐私与数据：

- 3.4.1 收集数据必须明确告知用途 + 明确同意 + 授权范围内使用 + **注销后删除**。
- 3.4.5 未经授权不得显示头像、昵称等用户数据。
- 3.4.7 有位置追踪需提供退出功能。

技术实现与 UI：

- 3.5.2 **禁止视频、音乐、语音等多媒体自动播放**。
- 3.5.5 有账户体系必须提供**易发现的「退出」入口**。
- 3.5.3/3.5.4 禁止安装/运行其他可执行代码、违规加载或更新代码。
- 3.6.2 页面内浮层与弹窗**必须可关闭**（本项目多处 `wx.showModal` 与自绘弹窗需逐一确认）。
- 3.6.4 界面不得模仿系统通知/警告诱导点击；3.6.5 logo 背景规则。
- 3.6.1 需符合 WeApp UI 规范（设计规范见 `docs/reference/wechat-miniprogram/notes/` 对应官方页 `pages/design-guide.md`）。

内容红线：

- 3.2.1 禁止诱导分享/诱导关注/诱导下载（"分享后才能操作"这类设计会被拒）。
- 3.2.10 小程序代替用户发表/发送内容前必须取得**明确同意**（家长端若有留言/提交类功能需注意）。
- 3.2.11 需提供过滤不当内容的措施（本项目后台已有内容管理能力，需在提审说明里写清）。
- 3.2.4 不得有测试/算命类内容；3.2.9 图片不得含广告或虚假内容。

## 运营规范（`pages/product-ops-spec.md`，10 万字符全文留档）

平台红线集中在：账号信息与类目一致、内容合法、不得诱导、不得滥用能力、数据与隐私合规、技术与 UI 规范。**评审新功能时按主题去该文件检索具体条款**，不要凭印象判断。相关补充：
- 安全指引（`pages/security-basic.md`）：常见风险与开发建议、平台通知消息。
- 设计指南（`pages/design-guide.md`）：重点突出、流程明确、反馈及时（一个页面同时不超过 1 个加载动画；长耗时提供取消与进度）、异常可控、视觉规范（字体/色板/列表/表单/按钮）、375 或 390 基准尺寸。

## 本项目发版 6 项门禁（建议写进发布 checklist）

1. 备案完成且备案号已按要求展示（后台核对）。
2. 隐私保护指引已声明实际处理的信息（手机号、剪切板），且 `04` 里的同意链路已上线并在真机验证。
3. 服务器域名/业务域名在后台配置完成，`urlCheck` 关掉后真机请求正常；HTTPS 证书有效且链完整（TLS ≥ 1.2）。
4. 提供可体验全部功能的测试账号（家长 + 教练两种角色），并在提审说明里写清。
5. 体验评分无「JS 异常 / 网络异常 / 废弃接口 / HTTP 请求」四类问题；主路径冷启动耗时记录在案。
6. 首页到所有已提交类目页面 ≤ 2 次点击；有账号体系时有明显「退出」入口；所有弹窗可关闭。
