# 06 性能与体验评分

出处：`pages/perf-tips.md`、`pages/perf-start.md`、`pages/perf-setdata.md`、`pages/audits-overview.md`、`pages/audits-best-practice.md`、`pages/operating-mechanism.md`

## 启动性能的官方标尺 `[官方]`

「启动」= 冷启动，从用户打开小程序到**首页 `Page.onReady`** 为止（不等于浏览器的 DOMContentLoaded/load）。

官方给的目标耗时：

| 场景 | 安卓 | iOS |
| --- | --- | --- |
| 需要下载或更新时 | 3.7s | 1.8s |
| 使用本地代码包时 | 2.6s | 0.9s |
| 大盘平均 | 3.0s | 1.2s |

- 中间指标：打开率（到达率）= 首页渲染完成次数 / 启动次数；启动越慢、等待意愿越低（广告类场景）流失越大。
- 开发者可控的三段：**代码包准备**（体积）、**代码注入**、**首屏渲染**；框架侧负责其余部分。

## 体验评分：可直接当验收清单用 `[官方]`

工具：开发者工具 → 调试器 `Audits` 面板 → 开始/停止；分数低于 70 会 console 告警。基础库 ≥ 3.7.0 起官方另有「小程序性能诊断工具」可在真机做性能测试。

9 个评分项（`pages/audits-best-practice.md`）：

| # | 项目 | 得分条件 |
| --- | --- | --- |
| 1 | 避免 JS 异常 | **不出现任何 JS 异常** |
| 2 | 避免网络请求异常 | 所有已授权请求正常返回；未授权请求返回 401/403 |
| 3 | 不使用废弃接口 | 不使用文档中标注废弃的接口 |
| 4 | 使用 HTTPS | 所有网络请求走 HTTPS |
| 5 | 避免 setData 数据冗余 | 传入的数据在模板渲染中都有依赖 |
| 6 | 最低基础库版本 | 使用的组件/API 支持版本 ≤ 配置的最低基础库（提醒项，不计分） |
| 7 | 移除不可访问页面 | 无访问不到的页面被打包（提醒项） |
| 8 | WXSS 使用率 | 每个 WXSS 未使用部分 ≤ 2KB（提醒项） |
| 9 | 及时回收定时器 | 定时器回调执行时所在页面与设置定时器的页面一致（提醒项） |

**第 3 项与本项目直接冲突**：仓库里仍有 `wx.getSystemInfoSync()` 作为降级分支（`components/app-header/index.ts:22`、`components/radar-canvas/index.ts:122`），该接口自基础库 **2.20.1 起停止维护**，官方替代是 `wx.getSystemSetting` / `wx.getAppAuthorizeSetting` / `wx.getDeviceInfo` / `wx.getWindowInfo` / `wx.getAppBaseInfo`（见 `pages/api-getSystemInfoSync.md`）。保留它会被体验评分扣分，且后续可能行为不一致。

## setData 的六条官方建议 `[官方]`

1. **合理划分组件，控制 Shadow 树节点量** —— 影响比数据量本身更大。
2. 控制更新频率：避免毫秒级连续 `setData`；合并连续调用；不要在滚动回调里每次更新。
3. 无法避免的高频更新（倒计时等）封成独立小组件 + 用 CSS `contain` 限制计算范围。
4. **`data` 只放渲染用到的字段**；渲染无关的数据挂 `this.userData` 或纯数据字段。
5. `setData` 只传变化的字段，禁止 `this.setData(this.data)`。
6. 控制后台态页面的数据更新：页面不可见时的更新应避免或延迟到再次展示。

## 与本项目现状的对应 `[本项目]`

- 已有 `lazyCodeLoading: requiredComponents`、`style: v2`，方向正确。
- 教练端「测评批量录入 / 团队能力页 / 战术板 / 雷达 Canvas」是 setData 与渲染的热点区域：批量录入需分项提交、逐项反馈（产品需求已如此要求），实现时要落在「合并更新 + 局部组件」上，避免一次性 `setData` 整个大列表。
- 「不可访问页面」「WXSS 使用率」两项在 56 页全压主包的情况下会持续失分：分包改造（`03-分包与体积`）同时改善体积与这项评分。
- 定时器：验收时按第 9 项检查是否存在页面级 `setInterval`/`setTimeout` 未在 `onUnload` 清理的情况（尤其轮播、倒计时、自动刷新）。

## 建议的验收动作

1. 开发者工具 Audits 跑一遍家长端与教练端主路径，记录分数与问题清单（存 `docs/current/`，作为发版证据）。
2. 用开发者工具的性能面板记录冷启动耗时，与上表目标值对比；改造分包前后各测一次。
3. 把 `wx.getSystemInfoSync` 的降级分支改名为明确的兼容函数并标注废弃原因，或直接改用 `wx.getDeviceInfo()`；改完重跑体验评分与相关单测。
