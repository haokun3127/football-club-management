# 04 隐私与个人信息合规

出处：`pages/privacy-overview.md`、`pages/privacy-intro.md`、`pages/privacy-authorize.md`、`pages/product-ops-spec.md`、`pages/product-reject.md`

这是本项目**风险最高**的一块：登录页已经用了手机号授权能力，而仓库里目前没有任何隐私授权同步代码。

## 强制背景 `[官方]`

- 2023-09-15 之后，**不论 `app.json` 是否配置 `__usePrivacyCheck__`，隐私相关功能一律启用**。
- 开发者在「小程序管理后台」配置《小程序用户隐私保护指引》，**只有在指引里声明所处理的信息，才能调用平台对应的接口/组件；未声明则对应接口或组件直接被禁用**。
- 用户维度还需**同步同意**：对每个用户，要先同步「已阅读并同意隐私政策」的状态，之后才能调用已声明的接口/组件。

## 三种同步同意的实现方式 `[官方]`

| 方式 | 基础库 | 做法 |
| --- | --- | --- |
| 主动查询 + 自绘弹窗 | ≥ 2.32.3 | `wx.getPrivacySetting()` → 看 `res.needAuthorization`；需要时展示弹窗；`wx.openPrivacyContract()` 打开官方指引页 |
| 官方同意按钮 | — | `<button open-type="agreePrivacyAuthorization" bindagreeprivacyauthorization="handleAgree">同意</button>`，回调后才能调隐私接口 |
| 被动监听 | ≥ 2.32.3 | `wx.onNeedPrivacyAuthorization(...)`：用户触发了一个微信侧没记录过同意的隐私接口时回调 |

关键细节 `[官方]`：

- `wx.getPrivacySetting` 同时返回后台配置的指引名称，用 `wx.openPrivacyContract` 打开的是官方页面，**不要自己写一份协议页代替**。
- 更新配置后：**旧版本已同步过的接口不需要重新同步**，但**新增的接口/组件需要重新同步**（官方给了 7 月 11→12→13 日的例子）。也就是说加一个隐私接口 = 一次新的授权链路工作，不是改个开关。
- `<input type="nickname">` 在用户未同意隐私协议时，聚焦**不会**触发 `onNeedPrivacyAuthorization` —— 头像昵称类能力不能用被动监听兜底。

## 隐私接口 ↔ 处理的信息对照表（官方原文）`[官方]`

与本项目直接相关的行：

| 处理的信息 | 接口或组件 |
| --- | --- |
| **收集你的手机号** | `<button open-type="getPhoneNumber">`、`<button open-type="getRealtimePhoneNumber">` |
| **读取你的剪切板** | `wx.setClipboardData`、`wx.getClipboardData` ← **写入也算** |
| 使用你的相册（仅写入）权限 | `wx.authorize({scope:'scope.writePhotosAlbum'})`、`wx.saveImageToPhotosAlbum`、`wx.saveVideoToPhotosAlbum` |
| 收集你选中的照片或视频信息 | `wx.chooseImage`、`wx.chooseMedia`、`wx.chooseVideo` |
| 收集你的位置信息 | `wx.authorize({scope:'scope.userLocation'...})`、`wx.getLocation`、`wx.startLocationUpdate`、`wx.getFuzzyLocation`、`MapContext.moveToLocation` 等 |
| 收集你的昵称、头像 | `<input type="nickname">`、`<button open-type="chooseAvatar">`、`wx.getUserInfo`（已回收）、`wx.getUserProfile`（已回收） |
| 访问你的麦克风 / 摄像头 / 蓝牙 / 日历 / 通讯录 / 各类传感器 | 见原文表格（本项目暂未使用） |

指引里还要填：处理目的、存储期限（如「固定存储期限：180 天」）、信息对外提供承诺、**用户权益与联系方式**（用户可通过该联系方式行使查阅/复制/更正/删除权）、第三方插件与服务商信息。

## 审核侧的硬要求 `[官方]`

- 3.4.1：收集使用用户任何数据必须明确告知用途、取得明确同意，并在授权范围内使用；**用户注销账号后应删除相关数据**。
- 3.4.5：**未经授权不得显示用户头像、昵称等数据**。
- 3.4.4：不得出售、转交、越权披露用户数据。
- 隐私同意与系统权限（相册/相机/麦克风）是**两层**，都要分别处理，系统授权弹窗不能伪装成自制弹框。

## 本项目现状 `[本项目]`

探测结果（`apps/miniprogram-cq-talent`）：

| 项 | 现状 |
| --- | --- |
| 隐私相关接口用法 | `pages/login/index.wxml` 手机号按钮 `<button open-type="getPhoneNumber" bindgetphonenumber="onGetPhoneNumber">` |
| | `pages/parent/coaches/index.ts:53` `wx.setClipboardData({ data: wechatId })`（复制教练微信号） |
| 隐私授权代码 | `grep getPrivacySetting / openPrivacyContract / agreePrivacyAuthorization / onNeedPrivacyAuthorization` **零命中** |
| 隐私文案 | 登录页有静态文字「同意《用户协议》和《隐私政策》」，但**不是** `open-type="agreePrivacyAuthorization"` 按钮，不产生微信侧同意记录 |

即：**当前登录页的手机号能力在真机上会受隐私规则约束**——若后台指引未声明「收集你的手机号」，组件直接不可用；若已声明但该用户没有同步过同意，调用同样被拦。静态文案不构成同意。

## 本项目动作项（按优先级）

1. **后台先声明**：在「小程序管理后台 → 设置 → 服务内容声明 → 用户隐私保护指引」中声明「收集你的手机号」与「读取你的剪切板」；声明文案要与实际用途一致（手机号用于身份匹配俱乐部档案；剪切板仅写入用于复制教练微信号）。
2. **代码里补同步同意链路**（建议做在 launch/login 入口）：
   - `wx.getPrivacySetting({ success })` → `needAuthorization` 为真时展示隐私弹窗；
   - 弹窗里放「查看隐私协议」按钮调 `wx.openPrivacyContract()`，放 `<button open-type="agreePrivacyAuthorization">` 取得同意；
   - 同意后再执行原有的 `getPhoneNumber` 流程；用户拒绝时要有明确降级文案（无手机号无法匹配俱乐部身份 → 提示联系俱乐部，而不是死循环重试）。
3. 把「剪切板」纳入同一个弹窗链路：复制教练微信号前若未同意，先走同意流程 `[官方]`（写入剪切板属于隐私项）。
4. 账号注销/删除数据路径要与指引承诺一致（3.4.1 明确要求注销后删除数据）——若产品暂无注销入口，需在指引与产品上补齐或如实声明。
5. 后续任何新增隐私接口（选图上传、定位签到、头像昵称）**必须先改后台指引 + 补同意链路**，再写业务代码；把这条写进 review checklist。
6. 验证方式：开发者工具「真机调试」+ 一台从未同意过的真机各跑一次，确认弹窗出现、拒绝路径可用、同意后手机号正常返回 `code`。
