# 03 分包与体积

出处：`pages/subpackages-overview.md`、`pages/subpackages-basic.md`、`pages/subpackages-independent.md`、`pages/subpackages-preload.md`、`pages/subpackages-async.md`、`pages/ability-lazyload.md`

## 硬限制（必须记住的三个数）`[官方]`

- **单个分包 / 主包 ≤ 2M**
- **整个小程序所有分包 ≤ 30M**（服务商代开发的小程序 ≤ 20M）
- 启动时只下载主包；进入分包页面时才下载对应分包 —— 所以**主包越小，首页越快**。

## 主包里应当放什么 `[官方]`

- 启动页 / TabBar 页面；
- 所有分包都要用的公共资源、公共 JS；
- 其余按访问路径聚类进分包。

## 配置方法 `[官方]`

```json
{
  "pages": ["pages/launch/index", "pages/login/index"],
  "subPackages": [
    { "root": "packages/parent", "name": "parent", "pages": ["schedule/index", "growth/index"] },
    { "root": "packages/coach",  "name": "coach",  "pages": ["schedule/index", "attendance/index"] }
  ],
  "preloadRule": {
    "pages/launch/index": { "network": "all", "packages": ["parent"] }
  }
}
```

- `subPackages`（小写 `subpackages` 也可）里 `root` + `pages` 是相对该 root 的路径；`name` 是分包别名（预下载用）。
- 页面归属改了，**所有硬编码的跳转路径与 deep link 都要一起改**（本项目大量 `wx.navigateTo` / `wx.reLaunch` 写的是绝对路径，`app.routes.test.mjs` 目前承担路由校验）。

## 预下载 `preloadRule` `[官方]`

- 进入某页面时由框架自动预下载指定分包，减少后续进入分包的等待；只能通过配置使用，**没有 API 版**。
- `network`: `all`（不限网络）/ `wifi`（仅 WiFi）。
- `packages` 里 `__APP__` 表示主包（独立分包可预下载主包）。
- 限制：**同一个分包中的页面共享 2M 的预下载额度**，工具打包时校验 —— 预下载多了会直接报错。
- 验证手段：vConsole 里看 `preloadSubpackages` 开头的日志。

## 独立分包 `independent: true` `[官方]`

- 优点：可以**不下载主包**直接进入（适合「扫码直达」的活动页/落地页）。
- 代价（写代码时会直接踩）：
  - 独立分包**不能依赖主包和其他分包的任何内容**（JS、template、wxss、自定义组件、插件）；
  - 主包 `app.wxss` 对独立分包**无效**；
  - `App()` 只能在主包定义，独立分包**不能定义 App**；
  - 从独立分包启动时 `getApp()` 可能是 `undefined` —— 取全局状态必须写降级。

## 分包异步化（跨分包引用）`[官方]`

- 需基础库 **≥ 2.11.2**（安卓微信 7.0.13 / iOS 7.0.12 / PC 3.4.5 起）。
- 跨分包**自定义组件**：在 `usingComponents` 里引用，并用 `componentPlaceholder` 指定占位组件，等分包下载完自动替换。
- 跨分包 **JS**：用异步 `require('../subB/utils.js', cb, errCb)` 或 `require.async('...')`，不能用同步 `require`。
- 基础库 ≥ 2.24.3 可用 `wx.onLazyLoadError` 监听懒加载失败。

## 本项目现状与判断 `[本项目]`

- `apps/miniprogram-cq-talent/app.json` 目前**没有分包**，56 个页面全在主包；主包上限 2M 是没有余量的硬墙。
- 页面天然分成 **家长端（26 页）** 与 **教练端（28 页）** 两组，且登录后按角色分流（`routeHome`），是教科书式的分包切分点。
- 建议落地顺序（每一步都能单独验证）：
  1. 先量体：用开发者工具的「代码依赖分析 / 包体积」看主包当前大小、各页面 WXSS+图片占用，确认离 2M 还有多少；
  2. 拆 `packages/parent` 与 `packages/coach`，把两个角色的业务页迁进去，主包只留 launch / login / 共享组件与 utils；
  3. 在 launch 或 login 页配 `preloadRule` 预下载「用户角色对应的那个分包」——注意 2M 预下载额度；
  4. 跑 `app.routes.test.mjs` 与全量小程序测试，确认路由与 `wx.navigateTo` 路径全部对齐；
  5. 真机回归：家长/教练各主路径 + 分享/deep link 入口（分包后 deep link 路径会变，需与后台/分享配置同步）。
- 若将来要做「扫码直达」的活动页，才考虑 `independent: true`；独立分包的代价是拿不到主包的一切，本项目大量共享 `utils/`，暂不建议。

## 官方给的体积优化手段（不只是分包）`[官方]`

- `lazyCodeLoading: requiredComponents` 已开（本项目已具备）。
- 及时清理不可访问页面（体验评分提醒项）、按需引入 WXSS（未使用部分 ≤ 2KB）、图片走 CDN 或压缩。
- `enablePassiveEvent` 等配置属于运行时而非体积项，不要混谈。
