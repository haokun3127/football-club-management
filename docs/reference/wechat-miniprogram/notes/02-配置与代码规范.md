## app.json 字段速查（本项目相关的）`[官方]`

| 字段 | 作用 | 关键约束 |
| --- | --- | --- |
| `pages` | 页面路径列表 | 第一项即首页；未列入的页面不可访问 |
| `window` | 全局窗口表现 | `navigationStyle: custom` 在低版本客户端只在 app.json 生效 |
| `tabBar` | 底部导航 | 本项目未配置（导航走自定义 `app-header`），若新增需同时提供图标与选中态 |
| `networkTimeout` | 各类网络请求超时 | 默认 **60s**；接口级 `timeout` 优先级更高 |
| `subPackages` | 分包结构 | 见 `03-分包与体积` |
| `preloadRule` | 分包预下载 | 只在 app.json 配，无 API 版 |
| `lazyCodeLoading` | 按需注入 | `requiredComponents` = 只注入用到的自定义组件 |
| `requiredPrivateInfos` | **地理位置类接口声明** | 2022-07-14 后发布的小程序，用这 8 个接口必须声明，否则无法调用：`getFuzzyLocation`、`getLocation`、`onLocationChange`、`startLocationUpdate`、`startLocationUpdateBackground`、`chooseLocation` 等 |
| `permission` | 权限用途声明 | 目前仅 `scope.userLocation`，`desc` **最长 30 字符**，是授权弹窗里的用途说明 |
| `style` | 基础组件样式版本 | 本项目为 `v2`（正确，官方当前推荐） |
| `sitemapLocation` | 搜索索引配置 | 本项目为 `sitemap.json` |
| `renderer` / `rendererOptions` / `componentFramework` | 渲染引擎与组件框架 | Skyline / `glass-easel` 相关；不配置即 WebView + exparser 默认栈 |
| `resolveAlias` | 路径别名 | 跨分包引用时有用（如 `subBUtils/mod.js` → `subpackageB/utils/mod.js`） |
| `darkmode` / `themeLocation` | 深色模式 | 未启用则不要写死反色样式 |
| `useExtendedLib` | 引入官方扩展库 | 如 `weui` |

### 本项目当前 app.json `[本项目]`

`apps/miniprogram-cq-talent/app.json`：`pages`（56 项）、`window`、`lazyCodeLoading: requiredComponents`、`style: v2`、`sitemapLocation`。

与官方要求对照的缺口：

- 无 `subPackages` / `preloadRule` —— 56 个页面全在主包（见 `03-分包与体积`）。
- 无 `requiredPrivateInfos` / `permission` —— 只有在使用地理位置类接口时才必须加；本项目目前不用定位，**不用补**，但一旦新增「场馆导航/签到定位」就必须补，否则接口直接不可用。
- 无 `tabBar` —— 属设计选择；但注意常见拒绝情形 3.1.2：首页必须能**直达或 2 次点击内**到达所有已提交类目页面（见 `07-发布审核与运营红线`）。

## page.json 要点 `[官方]`

- `usingComponents` 声明组件；跨分包引用要配 `componentPlaceholder`（占位组件）。
- `navigationStyle: custom` 的自定义导航页要自己处理状态栏与胶囊避让（本项目 `app-header` 已做，见 `docs/current/upgrade-readiness-2026-09-18/04-design-and-wechat.md`）。
- 页面级配置会覆盖 `window` 的同名项。

## project.config.json / 项目私有配置 `[官方]`+`[本项目]`

- `appid`：`wx4c588cd106e520e0`；`compileType: miniprogram`；`miniprogramRoot: ./`。
- `setting.useCompilerPlugins: ["typescript"]`：TS 编译由开发者工具插件完成，构建链与 `pnpm typecheck` 是两套（两者都要过）。
- `setting.minified / minifyWXML / minifyWXSS / enhance / es6 / postcss` 已开 —— 上传前压缩，包体评估要以压缩后为准。
- **`setting.urlCheck: false`**：这是开发者工具「不校验请求域名」的开关，**只能在开发期使用**。官方明确建议域名配好后关闭该选项并在各平台真测；线上若域名未在白名单配置正确，真机上会直接请求失败（错误现象是「打开调试能请求，关掉调试不能请求」）。
- `project.private.config.json` 是个人本地配置，**不要作为团队/CI 的配置来源**；发布/交接说明里不要引用它。

## 与代码规范相关的官方硬约束 `[官方]`

- `wx.request` 的 `referer` 头**不可设置**，固定为 `https://servicewechat.com/{appid}/{version}/page-frame.html`（版本号 0 = 开发/体验/审核版，`devtools` = 开发者工具）。服务端做鉴权/来源校验时要按这个事实设计，不能自己发 referer。
- 只要**收到服务器返回（任何 statusCode）都进 `success`**，必须自己判断状态码（本项目 `utils/request.ts` 需持续保持该约定）。
- 服务端返回值建议 UTF-8；小程序只过滤一个 BOM 头。
- 网络并发上限：`wx.request` / `uploadFile` / `downloadFile` 各 **10**；`connectSocket` **5**。进入后台后 5s 内未结束的请求回调 `fail interrupted`，回到前台前网络接口不可调用。

## 本项目动作项

1. 新增页面必须同时更新 `app.json.pages`，并确认落在正确的分包（分包落地前先在规格里写清归属）。
2. **开发联调结束时把 `urlCheck` 关掉（改为 `true`）复测一次**，确认服务器域名在后台已配置正确，而不是靠工具跳过校验。
3. 若新增定位/相册/联系人等能力，先按 `04-隐私与个人信息合规` 声明隐私信息，再补 `requiredPrivateInfos` / `permission`。
4. 交接文档不引用 `project.private.config.json` 的内容作为团队配置。
