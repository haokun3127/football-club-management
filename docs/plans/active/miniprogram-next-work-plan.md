# 小程序后续工作计划

## 基线文档

后续小程序产品设计、技术架构和开发计划必须以以下文件为基线：

- 产品规格：[miniprogram-product-design-cq-talent.md](../../archive/2026-06-discovery/miniprogram-product-design-cq-talent.md)
- 技术选型与开发工作流：[miniprogram-development-workflow.md](../../archive/2026-06-discovery/miniprogram-development-workflow.md)

除非明确更新上述基线，否则后续会话不应重新口头推翻已确认原则。

## 已确认关键决策

### 通用

- 一个小程序同时服务家长端和教练端。
- 一个手机号在一个俱乐部小程序内只能对应一个身份：家长或教练。
- 无注册功能，身份以俱乐部后台/WPS 表格资料为准。
- 首次登录用手机号匹配身份，后续用微信绑定稳定登录。
- 小程序不得写死重庆天才业务字段，必须通过 `appId/clientKey -> resolve -> clubId/clientId/capabilities`。
- 管理员/运营不使用小程序，通过后台或 WPS 管理。

### 家长端

- TabBar：`日程 / 成长 / 我的孩子`。
- 日程是默认首页，包含 Banner、家庭日程日历、选中日期活动列表和详情。
- 家长端只读：不注册、不请假、不申诉、不修改考勤/课时/保险/评测/比赛。
- 训练课详情展示训练项目、关联能力和轻量能力参考。
- 成长页展示成长足迹、训练历程、雷达图、指标下钻。
- 能力对比使用同龄平均，不使用队伍均值。
- 我的孩子展示孩子资料、课时保险、俱乐部信息、球场分布、青训帮助、教练团队和私教意向。
- 私教只发送意向通知，不做预约、订单、支付或自动派单。
- 公众号提醒只服务日程类提醒：活动前一天、活动变更、取消等；多孩子不合并提醒。

### 教练端

- TabBar：`日程 / 训练管理 / 我的`。
- 技术权限按正式 `CoachAssignment / permission context` 设计。
- 日程负责今日/本周活动、新建、编辑、取消、销课、纠正、比赛录入、战术板、记录完善度。
- 所有活动都可能销课；销课在活动结束后确认，默认全员销课，教练只点掉不销课学员。
- 15 天内教练可纠正销课，超出后后台/WPS 处理。
- 战术板是比赛日工具：竖屏球场、球员头像拖拽、阵型模板、本场快照、家长不可见。
- 训练管理负责训练内容、测试成绩、学员雷达图、全队能力概览和待完善项。
- 训练项目库按重庆天才评估模型层级组织：核心能力 -> 二级能力 -> 三级能力 -> 推荐训练项目。
- 训练内容选择需要能力覆盖预览，可显示本队/学员弱项，但不做 AI 推荐。
- 测试录入按测试项目顺序录入，支持缺测、修改、自动保存。
- 投入程度默认 7 分正常努力，教练只调整例外；不阻塞、不计入未完成。

### 技术选型

- 雷达图采用小程序原生 Canvas 2D 自绘 `RadarCanvas`。
- 暂不引入 ECharts/F2/uCharts。
- 涉及雷达图、战术板、测试录入、自动保存、消息提醒或第三方依赖时，必须先走 [小程序技术选型与开发工作流](../../archive/2026-06-discovery/miniprogram-development-workflow.md)。

## 产品设计会话任务

目标：产出可交给技术架构和开发拆解的逐页产品规格。不写代码，不做视觉 UI。

### 1. 家长端逐页规格

输出以下页面的线框级规格：

- 日程 Tab
  - Banner
  - 家庭日程日历
  - 日期活动列表
  - 训练详情
  - 比赛详情
  - 提醒中心

- 成长 Tab
  - 孩子切换
  - 成长足迹
  - 训练历程
  - 雷达图
  - 指标详情/下钻

- 我的孩子 Tab
  - 孩子档案
  - 课时与保险
  - 俱乐部信息
  - 球场分布
  - 青训帮助
  - 教练团队
  - 私教意向
  - 账号绑定

每页必须包含：

- 页面目标
- 模块结构
- 用户操作
- 空状态
- 错误状态
- 数据字段
- 需要的 BFF/API
- 权限边界

### 2. 教练端逐页规格

输出以下页面的线框级规格：

- 日程 Tab
  - 今日/周视图
  - 活动卡片
  - 新建活动
  - 编辑活动
  - 取消/恢复活动
  - 销课确认
  - 销课纠正
  - 比赛录入
  - 战术板入口
  - 记录完善度

- 训练管理 Tab
  - 我的球队
  - 球队详情
  - 训练内容选择
  - 能力覆盖预览
  - 应用到未来课程
  - 测试任务
  - 按项目录入测试成绩
  - 学员雷达图
  - 全队能力概览
  - 待完善列表

- 我的 Tab
  - 教练身份
  - 负责球队
  - 权限范围
  - 私教意向
  - 操作帮助
  - 账号绑定
  - 俱乐部联系方式

每页必须包含：

- 页面目标
- 模块结构
- 主流程
- 非阻塞完善项
- 空状态
- 错误状态
- 数据字段
- 需要的 BFF/API
- 权限边界

### 3. 产品交付格式

建议更新或新增：

- `docs/miniprogram-page-spec-cq-talent.md`

不得只在聊天里描述。最终必须落文档。

## 技术架构会话任务

目标：基于产品规格形成可开发的技术架构和开发计划。

### 1. 小程序前端架构

需要确定：

- 小程序框架选择：原生小程序优先，是否使用 TypeScript。
- 目录结构。
- 页面路由。
- 组件边界。
- 状态管理。
- 请求封装。
- capability gating。
- 错误处理和空状态组件。

### 2. BFF/API 契约

需要输出：

- 家长端 BFF 契约。
- 教练端 BFF 契约。
- 登录/微信绑定契约。
- 权限 context 契约。
- 通知/提醒契约。
- 错误码和响应格式。
- OpenAPI 更新计划。

### 3. 权限与身份

需要设计：

- 微信登录与手机号首次匹配。
- 微信 openId/unionId 绑定。
- WPS 回写绑定状态。
- `CoachAssignment` 持久化和 permission context。
- 家长孩子绑定校验。

### 4. 数据模型与后端缺口

需要评估是否已有模型可承载：

- 训练项目库。
- 训练项目和能力指标映射。
- 课程训练内容选择结果。
- 同龄平均聚合。
- 成长足迹。
- 战术板快照。
- 投入程度评分。
- 测试计划/任务/成绩。
- 赛事库。
- 私教意向通知。
- 内容/Banner/球场/帮助文章。

若需要新增模型，必须说明不是“小程序专属模型”，而是平台能力。

### 5. PoC 优先级

按以下顺序做 PoC：

1. `RadarCanvas` 原生 Canvas 雷达图。
2. 战术板拖拽。
3. 测试录入自动保存。
4. 微信小程序/公众号身份匹配与消息提醒。
5. 训练内容选择页能力覆盖预览。

每个 PoC 需按 [miniprogram-development-workflow.md](../../archive/2026-06-discovery/miniprogram-development-workflow.md) 记录验收结果。

## 开发计划建议

建议拆成 4 个开发窗口，避免混乱。

### 窗口 A：小程序 BFF 与身份权限

- app client resolve。
- 微信登录和手机号匹配。
- 微信绑定。
- 家长 children。
- 教练 permission context。
- 基础 capabilities。

### 窗口 B：家长端 BFF

- 家庭日程。
- 活动详情。
- 成长概览。
- 雷达图数据。
- 我的孩子。
- 内容/Banner/球场/帮助/教练团队。
- 私教意向。

### 窗口 C：教练端 BFF

- 教练日程。
- 活动创建/编辑/取消/恢复。
- 销课/纠正。
- 比赛录入。
- 战术板。
- 记录完善度。
- 训练管理。
- 测试任务和成绩录入。
- 投入程度。

### 窗口 D：小程序前端与 PoC 集成

- 小程序 shell。
- 登录流程。
- 家长端页面。
- 教练端页面。
- `RadarCanvas`。
- 战术板。
- 测试录入自动保存。
- 消息/提醒入口。

## 暂不做范围

- 在线支付。
- 在线投保。
- 退款、发票、结算。
- 家长注册。
- 家长请假。
- 家长线上申诉。
- 私教在线预约/订单/支付/自动派单。
- AI 评价。
- 单堂课自动计算能力提升。
- 家长端写入训练、比赛、评测、课时、保险或收费状态。
- 教练端后台运营管理。
- 小程序内 WPS 配置、字段映射或同步策略管理。

## 风险与优先处理

| 风险 | 优先级 | 处理 |
| --- | --- | --- |
| 小程序/公众号消息能力限制 | 高 | 单独 PoC，按微信官方能力调整提醒策略 |
| 雷达图小屏展示和点击命中 | 高 | 先做 `RadarCanvas` PoC |
| 战术板拖拽与页面滚动冲突 | 高 | 先做拖拽 PoC |
| 测试录入自动保存弱网失败 | 高 | 单格保存和失败重试 PoC |
| 训练项目和能力映射不清 | 高 | 产品设计会话先输出页面字段和数据结构 |
| 同龄平均口径不稳定 | 中 | 后端聚合契约明确样本数和年龄组 |
| 赛事库自由文本污染 | 中 | 技术设计按 `Competition`，教练输入作为待规范化 |

## 下一步建议

1. 产品设计会话读取本文件和两份基线文档。
2. 产品设计会话先产出 `docs/miniprogram-page-spec-cq-talent.md`。
3. 技术架构会话基于页面规格产出 BFF/API 与数据模型计划。
4. PoC 按优先级并行启动，但不得跳过 ADR 和验收记录。
