## 产品定位

后台服务于俱乐部的日常管理、学员培养和专业服务运营，核心分为四个模块：**数据管理、评测与模型、BI、专业服务**。

- 数据管理：维护完整、可信、可追溯的基础资料和业务过程。
- 评测与模型：组织数据采集，构建和使用评测模型，形成学员能力与成长记录。
- BI：通过适合的图表和明细呈现不同分析结果，帮助俱乐部理解业务。
- 专业服务：结合学员需求、评测结果和专业资源，运营私教、定制训练、球探等特色或增值服务。

四个模块共用人员、队伍、课程、测评等数据。同一份记录可以从不同业务入口查看和处理，修改与历史保持一致。

工作台提供日程、待办和关键摘要；账号权限、俱乐部配置和操作记录放在管理设置中。两者是通用入口，不增加核心业务分类。

## 一、数据管理

数据管理包括日常业务操作以及资料维护，支持新增、查询、编辑、批量处理、导入导出和更正追溯。

### 1. 基础资料

| 分类 | 维护内容 | 使用规则 |
| --- | --- | --- |
| 学员 | 个人资料、足球档案、入训信息、学员状态、学校、来源等 | 俱乐部统一维护；教练仅见教学所需资料 |
| 家长与联系人 | 监护关系、联系方式、紧急联系人、通知对象、账号绑定 | 一个学员可有多位联系人；家长只读获准信息，无主档编辑权 |
| 球探库 | 潜在学员资料、发现来源、观察资料、参训和跟进记录 | 独立于正式学员管理；临时参训从授权名单中选择 |
| 教练及专业人员 | 人员档案、教练专长、适用年龄和水平、任职与服务关系 | 任职角色、专业标签、数据权限分别管理 |
| 队伍 | 队名、队徽、学员配置、主教练及其他教练配置、学期归属 | 由俱乐部维护，教练和家长不能编辑队伍基础配置 |
| 业务目录 | 学期、场地、区域、学校、来源渠道、业务标签 | 统一名称与选项，支持业务筛选 |
| 保险与课包状态 | 保险资料、有效期、俱乐部确认的课包余额、来源和更新时间 | 由俱乐部维护或导入；出勤统计不自动改变课包余额 |

支持具有明确类型和权限的自定义字段。人员资料字段与测评指标分别管理。

球探人员转为正式学员时，建议衔接既有身份及历史，保留参训、测评和观察记录。临时参训本身不自动创建正式队员关系、家长账号或课包。

### 2. 日程、训练与活动

日历保持训练、比赛、其他三类。占用训练课时的友谊赛归训练；独立赛事无论规模大小归比赛，由俱乐部创建；参观、观赛等归其他活动。

俱乐部维护学期训练时间、地点及队伍安排。训练内容库保存原子训练内容及对应时长，俱乐部维护公共课程模板，主教练可保存个人模板。

主教练在已安排的训练课中选择和组合内容，支持将模板复制到未来已有课程。应用后的课程保留当时内容，修改模板不直接改动历史。教练填入的内容作为训练统计依据，不额外要求记录计划与实际的差异。

同队只有主教练可以编辑训练安排；授权教练团队可以协同记录出勤、测评和学员评价，操作留痕。

临时取消、改期、变更场地等保存原因、操作人、变更前后信息和通知记录。建议由主教练操作生效并同步俱乐部与家长；是否需要俱乐部审批仍是待确认的规则，不影响学期基础安排由俱乐部维护。

比赛与其他活动支持维护活动资料、参与名单、过程及结果。比赛详细技术统计的项目与录入责任需结合俱乐部实际工作确定。

### 3. 过程记录

维护和查询课程内容、出勤、请假、临时参训、日程变更、测评原始记录和结果、教练评价历史、比赛活动记录，以及专业服务记录。

- 家长申请请假，教练确认；沟通在线下完成，系统记录双方需要共享的事实。
- 未确认的出勤保持待确认状态，不直接算缺席；取消课程不算学员缺席。
- 每名学员维护一份当前教练评价，可选择内置语句并补充；变化进入成长时间线，无每课必填要求。
- 训练积累按已发生课程、学员出勤和课程内容统计。课程次数、内容次数、按配置汇总的训练时长分别表达。
- 正式学员与临时参训分别标识；临时参训不自动加入已下发测评的必测名单。
- 记录区分实际发生时间和录入时间，支持补录，并保留来源、录入人和修订历史。

### 4. 导入导出与数据质量

各业务页面提供就近入口，统一的导入导出页面管理模板、批次、处理结果和错误记录。

导入流程：选择数据类型 → 上传文件 → 字段映射 → 校验与预览 → 确认新增/更新/冲突 → 导入 → 返回处理结果。

支持基础资料、人员关系、日程、出勤、测评、保险、课包状态等业务数据的导入导出；WPS、Excel、后台维护及小程序记录遵循一致的数据定义。

基本要求：

- 使用稳定编号和来源标识识别人及记录，不仅凭姓名或家庭共用手机号自动合并。
- 导入前说明更新影响、空值处理和冲突情况；重复提交可识别已处理记录。
- 明确各类数据的主要维护来源，防止外部表格和后台相互覆盖。
- 历史数据缺少课程或版本信息时保留缺项状态，不虚构关联。
- 测评导入同样遵守项目、单位、版本、对象和发布规则。
- 导出支持筛选与字段选择，继承查看权限；敏感字段独立授权，导出留痕。
- 业务明细、回填模板与分析汇总分别导出，避免汇总结果被误当原始数据导回。

### 5. 俱乐部内容与小程序展示

内容资料纳入数据管理，包括俱乐部信息、新闻 Banner、通知、分享模板及展示配置。

家长首页支持球员卡和成长里程碑等内容滑动切换、新闻 Banner，以及四个可选可排序的快捷入口，默认请假、训练记录、测评结果、私教咨询。重要日程变更独立提示。

分享采用预制模板、普通照片和真实数据。已确定的展示范围不包含人物抠图和自动换球衣。

## 二、评测与模型

该模块承载平台核心专业能力：定义采集内容、组织测评、构建评分模型、解释结果并持续记录成长。

### 1. 数据采集与项目库

项目定义包括名称、数据类型、单位、录入规则、适用条件、来源、标签及可见范围。基础、高级等分类通过标签组织，不因标签变化自动改变评分方式。

数据来源设计覆盖人工测评、训练和比赛记录、设备身体指标及天气、日照、湿度等环境信息。来源需保留对象、发生时间、单位及关联活动，使结果可以解释和复核。具体设备和外部来源的接入规范需按实际提供的数据确定。

身体、环境和训练数据只有通过适用的模型规则才参与分析，不能因被采集就自动计入能力得分。

### 2. 模型构建与管理

支持持续新增基础项目和不同评分模型，不限制为固定的维度数量。模型输出可以被其他模型引用，形成复合分析体系。

模型管理包括输入项目或模型、计算规则、权重、适用条件、输出指标、依赖关系和版本。模型发布前支持样例试算、输入完整性检查和循环依赖检查。

原始测量值与计算结果分别保存。计算结果可追查输入、规则和版本。模型修订不静默覆盖历史结果；重算形成可识别的新结果。跨模型引用需明确取哪次、哪个时间范围及哪个版本的结果，避免使用含义不清的数据。

界面允许按角色维护公共模板及俱乐部适用版本，修改权限与普通测评录入权限分开。

### 3. 培养标准

按年龄段、普通队、精英队等条件维护目标值或参考区间，记录依据、适用范围和版本。

学员展示以个人历史进步和适用培养标准为主，不比较具体个人，不设置学员排名。人群平均值若用于内部分析，需明确标为统计均值，不能直接称为培养目标。

### 4. 测评任务与结果

俱乐部选择项目、周期及对象，可同时下发多个队伍。教练可自建测评任务，项目从库中选择，结果同步俱乐部。

- 支持按周、月、学期等周期组织；教练在相关训练课内看到待完成任务。
- 可按人、项目、课程分批完成，每条结果关联测评周期内实际开展测评的训练课。
- 允许周期之后补录，任务不因周期结束失效。
- 全部任务学员完成必测项目或明确标记不测评后，任务完成；缺席不自动等于不测评。
- 未测、不测评、缺数据与零分分别表达。不测评不会覆盖已有能力结果。
- 保存草稿、确认同步和任务完成分别管理；家长看到个人已确认结果，不等待全队。
- 修正已发布记录时保留原版，确认新的结果后再更新家长展示。

建议任务保留下发时的名单与要求，调队或转入不静默改变任务，名单调整留痕。

### 5. 成长档案与专业输出

整合训练积累和内容分布、测评趋势及原始值、培养标准、教练评价变化、关键成长事件。教练评价服务沟通，不默认参与能力综合分。

报告与训练建议应说明依据。AI 辅助分析、个性化计划等专业输出引用可追溯数据与模型结果，保留专业人员确认和修订记录。

## 三、BI

BI 的目标是满足不同业务问题的数据分析呈现，交互保持简单：**选择分析板块 → 筛选对象和时间 → 查看图表 → 查看明细或导出**。

按业务配置分析页面，使用指标卡、折线图、柱状图、分布图和明细表等适合的呈现。允许按需增加分析板块；日常使用不要求运营人员搭建数据集、编写公式或设计看板。

| 分析板块 | 主要呈现内容 |
| --- | --- |
| 俱乐部运营 | 学员和队伍规模、人员状态、活动开展情况、资料及记录完整情况 |
| 训练分析 | 出勤与请假、参训次数、内容频次和时长分布、学期变化 |
| 测评执行 | 任务进度、已测/不测评/未完成、待同步及数据完整情况 |
| 学员成长 | 单项与综合能力变化、训练积累、适用培养标准的达成情况 |
| 教练与教学 | 任教队伍、教学参与、过程记录和服务承担情况 |
| 专业服务 | 咨询、承接、服务执行、交付记录、球探观察及试训跟进情况 |

筛选条件根据数据支持日期、学期、队伍、年龄、水平、项目和服务类型等。汇总数字能够查看相应明细。

基本口径统一：

- 同一指标在不同页面使用相同定义，标明时间范围、分母、数据覆盖和更新时间。
- 缺失值不视为零；正式学员与临时参训不混用统计分母。
- 出勤区分出席、请假、缺席和待确认；出勤率是否剔除已批准请假需形成明确统一口径。
- 历史队伍归属、项目和模型版本变化应可识别，不把口径变化直接解释为成长或退步。
- 训练与能力变化可以关联观察，不能仅凭时间上的一致就认定因果关系。
- 分析页面、明细和导出使用一致的权限范围。

BI 负责呈现和汇总；专业评分规则由评测与模型模块维护。

## 四、专业服务

专业服务支持俱乐部围绕自身资源打造特色和增值业务。服务既可以面向正式学员，也可以在授权范围内面向球探库人员等服务对象。

### 1. 服务项目管理

由俱乐部维护服务名称、类型、介绍、适用对象、专业方向、服务目标、负责人员、周期或次数、交付内容、咨询入口及开展状态。服务项目与实际承接记录分开管理，一个服务可面向多个对象分别执行。

建议围绕以下服务组织，具体内容由俱乐部定义：

| 服务类型 | 业务内容 | 管理重点 |
| --- | --- | --- |
| 私教 | 一对一、小组专项训练等 | 咨询需求、教练匹配、安排、训练记录和反馈 |
| 定制培养 | 个性化训练、专项能力提升等 | 初始评估、培养目标、训练计划、执行和复评 |
| 专业测评与分析 | 专项评测、成长报告等 | 测评方案、采集任务、模型结果、报告交付与解读 |
| 球探 | 人才观察、选材、试训及发展跟进等 | 人员来源、观察依据、试训记录、专业意见和跟进结果 |
| 其他特色服务 | 俱乐部配置的其他专业项目 | 服务对象、责任人员、执行记录和交付结果 |

“球探库”是数据管理中的人员资料；“球探服务”管理围绕这些人员发生的专业工作，两处关联同一档案。

### 2. 服务承接与执行

建议通用流程为：需求或咨询 → 俱乐部沟通评估 → 确定方案和责任人员 → 安排与执行 → 交付反馈及跟进。

不同服务使用各自需要的记录，不强制私教咨询填写完整的定制培养方案。需求也可由俱乐部根据实际沟通建立，并记录来源；分析发现不自动视为家长已经购买或同意服务。

俱乐部可根据需求方向、年龄、能力、时间偏好和教练专长推荐人员，保存分派、承接、变更和沟通记录。教练职责与获准数据范围匹配，分派服务不自动开放完整个人资料。

服务中的训练安排、出勤和测评复用对应业务记录。定制计划可以关联培养目标和复评节点；报告可以引用测评结果和训练积累，交付记录说明由谁完成、何时完成及面向谁。

### 3. 服务效果与经营记录

同一服务对象能够查看目标、过程、交付和后续反馈。BI 按服务类型呈现需求量、承接和完成情况、跟进结果；成长变化需结合具体记录解读。

如服务涉及收费，服务档案可关联俱乐部确认的价格和收费状态；在线支付、结算或交易平台是否纳入产品需要独立明确，不由“增值服务”自动推导。

## 通用管理与权限

工作台聚合重要日程、待处理导入、资料缺项、测评待完成/待同步及专业服务待办。评价不定期更新不自动成为缺口，测评周期结束不自动关闭任务。

俱乐部管理员维护资料、队伍和学期安排；教学负责人按权限维护项目、模型、标准及教学内容；主教练管理本队训练安排；授权教练协同过程记录；家长查看自己孩子获准资料并使用请假和服务咨询。

详细个人信息由俱乐部维护，教练只见教学所需字段，家长没有主档编辑权限。查询、修改、导出、结果发布分别授权并留痕。

如存在多个俱乐部，业务数据按俱乐部隔离，共享目录和模型模板按授权使用；这些属于统一后台的管理配置，不改变四个核心模块。

## 待继续收敛的业务规则

- 临时日程变更是否需要俱乐部审批。
- 比赛技术统计的深度和具体录入责任。
- 课包信息向家长展示的范围，以及统一出勤率口径。
- 俱乐部具体开展哪些专业服务，以及各类服务必须记录和交付的内容。

以上是业务规则待定项，不是阶段划分。产品讨论按四个模块继续细化。
