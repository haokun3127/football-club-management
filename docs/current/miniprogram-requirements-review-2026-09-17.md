## 2 现状与需求差异

| 模块 | 本地现状 | 本轮要明确的变化 |
| --- | --- | --- |
| 教练日程 | 已有日程、训练工作台和比赛页面 | 确认后台排课与教练调整权限，统一活动分类 |
| 考勤与课时 | 现行规则为点名即扣课；训练工作台点头像立即保存；独立点名页有保存动作 | 明确是否统一改成“调整名单后确认提交”，提交前不影响课时 |
| 训练内容 | 已有分层课程库、多选、取消和保存后回读逻辑 | 对报告的问题做复现验收，完善展示，不按全新功能估算 |
| 学员详情 | 队伍成员入口主要进入学员雷达，未形成完整的基础信息、考勤、训练分析页面 | 整合为完整学员档案 |
| 课堂评价 | 现有课堂训练评测按训练项目录入学员分数和备注 | 改为整堂课评价，与专项测评区分 |
| 测评管理 | 已有任务创建、项目选择、批量录入、历史；新版有草稿与确认发布能力 | 补手册项目、明确小测/大考规则和创建权限，提升导航入口 |
| 能力模型 | 当前评分模型为八维；部分页面残留“六维”文案 | 确定最终模型和历史兼容，不能直接照五维或六维改图 |
| 比赛与战术板 | 已有比赛编辑和战术板；场上棋子显示号码，侧边名单有姓名 | 明确友谊赛/正式比赛规则；场上球员补姓名 |
| 家长首页与成长 | 已有日程、球员成长卡、雷达、训练与比赛历史；首页存在“待处理”条 | 强化个人身份和成长展示，移除指定首页条目，完善数据口径 |
| 教练与球队权限 | 已有球队教练组展示及权限相关页面 | 明确“加一个教练权限”究竟是分配教练、显示角色还是授权管理 |
| 运营后台 | 已有业务 API、数据导入能力及后台产品设计；本仓库未发现独立完整网页后台应用 | 独立后台属于新增交付范围，需单独评估 |

当前八维名称：**运控球、1v1、传接球、射门、小组配合、整体战术、体能、精神**。实际模板及数据仍需在实施前核对；旧页面标题不能作为模型依据。

## 3 产品角色与边界

建议以以下边界作为评审起点，不把尚有分歧的权限提前固化。

| 角色 | 建议职责 | 需要确认的例外 |
| --- | --- | --- |
| 管理员/教练主管 | 维护学员、球队、教练关系、排课、课程库、课程包、测评模板与评分规则 | 哪些操作交给授权教练；是否所有能力都必须通过新后台完成 |
| 教练 | 查看授权球队和日程，选择当堂训练内容，点名，课堂评价，执行测评和比赛记录 | 能否创建测评/比赛、调整日程、临时加入跨队学员 |
| 家长 | 查看绑定孩子的日程、考勤、课时、已公开评价与成长数据 | 图片上传、分享、排名的可见范围 |

“临时加入已有学员”“申请新建学员档案”“编辑基础资料”是三个不同权限。不能因允许临时加入考勤，就默认允许教练创建或编辑学员档案。

## 4 分项产品需求

以下“验收场景”用于说明需求应如何验证，并不代表本轮已经执行测试。

### R01 教练日程与执行入口

来源：M 二.1、二.8。

- 教练通过日历查看本人获授权的训练、比赛和其他任务，选择日期后查看该日全部安排。
- 训练、友谊赛、正式比赛通过文字标签和颜色共同区分；蓝色/红色属于候选视觉方案。
- 日程进入当次活动的点名、训练内容、课堂评价或比赛记录。
- M 提出由后台统一排课并移除教练加课、减课、排课入口。需确认是否同时取消当前活动调整和比赛创建权限；不得只隐藏入口却保留越权写入。
- 验收场景：切换日期或球队后列表正确；教练看不到无权限活动；后台改期后两端重新读取同一安排。

### R02 训练内容选择与保存

来源：M 二.2、五.5。

- 后台维护标准课程库；教练在库中选择当堂内容，不自行创建标准项目。
- 同一模块支持选择多个子项；勾选和取消即时反映在选中状态、数量及摘要中。
- 保存成功后，工作台显示最终内容；重新进入保持选择；保存失败保留待提交内容并提示。
- 材料提到的无法取消、颜色不更新、返回未刷新、层级不清，记录为“待复现问题”，不直接判定为当前版本仍存在。
- 验收场景：同模块选两项再取消一项，保存并返回、重进，所有页面结果一致；不得出现已显示成功但未保存。

### R03 点名提交确认与课时同步

来源：W“出勤情况加一个提交确认”；M 二.3。

- **建议流程**：打开当次名单 → 调整出勤状态 → 核对人数及预计扣课 → 确认提交 → 更新考勤、课时和家长端。
- M 提出默认全员出勤。若采用，默认仅是待提交选择，打开页面不能直接产生真实出勤或扣课；已提交名单重新打开必须回显已有结果。
- 提交前取消或退出，不影响正式记录；提交失败不能显示成功；重复提交同一结果不能重复扣课。
- 提交后改回缺席应按确认后的规则同步课时并保留变更记录。需确认修改时间窗口、是否必须填写原因、是否需要主管审核。
- 操作日志需明确粒度：M 要求每次勾选/取消/恢复都有记录；建议至少记录正式提交前后差异、操作者、时间，未提交点击是否逐次存储另行确认。
- 到课、迟到、早退、缺席、请假、免扣的统计与扣课规则须形成一张规则表。现有“到课/迟到扣一节”不能直接替代本轮全部规则。
- 验收场景：确认前余额不变；确认后准确扣减；重试无重复扣课；修改后各端余额及历史一致。

### R04 从球员库临时加入当次训练

来源：W“后台有个球员库有 ID，可以临时加到训练考勤里面，留记录”；M 五.4。

- 在允许的球员库范围内选择已建档学员，加入当次训练名单，支持考勤及获授权的评价/测评。
- 复用学员唯一 ID，记录加入者、时间、原属队伍和本次活动；建议补充加入原因。
- 加入单次活动不自动改变长期球队归属；同一学员不能重复加入同一活动。
- 需确定跨队可见范围、是否审批、使用哪个课程包、无课包时如何处理，以及其记录如何汇入个人档案。
- 新学员建档申请是独立候选需求，不由本条自动推出。
- 验收场景：跨队学员参与一次训练后，原队伍归属不变，个人考勤/评价可追溯；重复添加被阻止。

### R05 学员详情页

来源：W“球队—学员页面”；M 二.5、二.6。

- 从球队学员名单进入统一详情，包含基础资料、考勤与课时、训练与能力三部分。
- 基础资料：姓名、照片、年龄、位置、惯用脚；学校、年级、入队日期作为 M 提出的扩展字段。
- 考勤与课时：所选周期应到、实到、缺勤/请假等、已上课次、剩余课时；说明课次与扣减课时的区别。
- 训练与能力：训练模块累计完成量、训练/友谊赛/正式比赛参与记录、最新已发布测评及详情入口。
- 教练查看必要资料，基础资料编辑默认由后台负责；身份证、住址等不进入教练或家长分享内容。
- “已完成/未完成项目”必须有目标项目清单才可计算，不把没选过的课程库项目都视为未完成。
- 验收场景：跨队参与记录仍归到同一学员；详情统计与原始记录一致；无数据用明确空态，不用假分数。

### R06 训练统计与学员培养模型

来源：W“学员定位—映射关系、训练模型标准、训练统计分析”；M 二.6、二.9。

拆成两层，避免把基础统计与自动推荐绑在一起：

1. 基础统计：按学员、时间段、训练模块查询实际参与次数；只有存在可靠时长数据时展示时长。
2. 培养对照：按位置/培养目标绑定训练标准，比较已完成量与目标量，展示差距；智能训练建议是后续候选。

后台应提供定位、模块映射、目标量、适用年龄/层级和有效周期。学员定位由谁设置、历史目标如何保留，待确认。

验收场景：缺席课程不计入实际训练量；取消课程不计入；多项目课程按统一口径统计，不把项目数误当课次数。

### R07 整堂课评价

来源：M 二.4、五.7。

- 从按训练项目给学员评分，调整为对整节课表现的评价；专项能力通过测评任务采集。
- 建议支持学员个人文字点评，整堂课综合评分是否保留、是否必填待定。
- 必须确认评价对象：对全班写一条课程总结，还是对每位学员写个人评价，或两者都需要。
- 课堂表现分与专项能力综合分分开展示，不默认混入能力雷达或排名。
- 验收场景：无需逐训练项目填分即可完成课堂评价；家长只能看到自己孩子获公开的评价。

### R08 测评管理与能力手册

来源：W“补充能力手册测试项目、测什么自己选、小测大考、底部增加测评管理”；M 二.7、五.9。

- 增强现有测评流程：选择任务/创建任务 → 选择标准库项目 → 录入成绩 → 校验 → 确认发布 → 家长查看。
- 补充能力手册测试项目，逐项明确名称、单位、适用对象、录入方式、评分方法及所属维度。**本次两份材料未提供能力手册本体，无法确定缺哪些项目。**
- “自己选测什么”建议解释为在标准库中选择本次项目，不代表教练可自行改评分标准。
- 小测和大考建议共用测评基础能力，通过任务类型与必测项目规则区分；月度频率、10 分钟时长、学期必考均为 M 的建议，待确认。
- 普通/精英学员的项目、难度、评分标准和分组规则由产品与教学负责人提供。
- 底部“测评管理”是导航调整：新增独立 Tab、替换“训练管理”，还是保留二级入口，需确认信息架构。
- 当前已有教练创建任务能力；M 的“仅后台下发”会改变现有权限，不能无确认删除。
- 验收场景：可按项目分次录入；重进不丢失；只测部分项目时不把未测项目当零分；发布结果两端一致。

### R09 能力模型与发布历史

来源：W“整体评分、各项评分、维度能力值随成绩变化、家长同步”；M 五.1、五.2。

- 确定最终维度名称、数量、权重及评分尺度，并建立“测试项目 → 分项 → 维度 → 综合分”的解释关系。
- **建议保留当前八维作为讨论基线**，拿到教学标准后再决定是否变更；若改为五维或六维，必须评估历史数据映射和分数可比性。
- 每个结果能识别学员、测评日期、适用标准和状态；无成绩不显示为零。
- 建议保留历史，首页只展示最新已发布结果，历史在详情查看；不同标准下的结果不能无提示连成同一趋势或混排。
- 采用“保存草稿、确认发布”时，草稿不影响家长端；更正经再次发布后生效，保留修订依据。
- 既有新版发布能力尚不能直接视为全部在线用户已启用，需要与发布基线核对。
- 验收场景：两名孩子切换时数据不串；未发布变化不改变家长雷达；发布后总分、分项和历史一致。

### R10 友谊赛与正式赛事

来源：W“友谊赛加入训练内容、关联销课、纳入统计；正式比赛单独板块，统计正赛和商业赛”；M 二.8、五.3、五.8。

- 友谊赛在训练流程中可识别、可记录参与名单，并进入个人统计；是独立活动类型还是训练内容选项，待确定。
- 正式比赛有独立记录入口，关联名称、对手、时间、地点、参与学员；组别、赛制、比分等按实际业务补充。
- W 提到的“正赛/商业赛”需确认是正式赛事下的两个分类，还是与友谊赛并列；该分类不能被整理时遗漏。
- **扣课规则未决**：W 要求关联销课；M 多处倾向不扣课。活动归类、是否参加和是否扣课必须分别确定。
- 需确认比赛创建/编辑角色、友谊赛是否替代原训练、一个活动能否同时含训练和比赛；统计需避免重复计数。
- 验收场景：同一友谊赛在日程、个人参与记录、课时账本按同一规则展示；正式比赛不被误算成普通训练。

### R11 战术板场上姓名

来源：W“比赛战术板显示球员姓名”；M 二.10。

- 在现有战术板球员标记上显示姓名，建议保留号码作为辅助信息。
- 长姓名、同名和球员密集位置应可辨识，不遮挡关键拖拽区域。
- 现有战术板和拖拽能力优先沿用；M 中“后续做战术板”不能将本轮姓名展示误归为新建整个模块。
- 验收场景：场上能认出具体球员，移动后位置与身份关联正确，保存重进仍一致。

### R12 球队教练权限与教练考勤统计

来源：W“队伍里面加一个教练权限、教练可以看到自己在各队的考勤次数”；M 二.5、二.11。

- 权限需明确到球队范围和具体动作：查看学员、点名、课堂评价、测评、比赛记录、日程调整；主教练/助教是否有差异待定。
- 需先澄清客户指的是显示现有权限，还是允许某个角色增减球队教练并分配权限。
- 教练可按时间范围查看本人在不同球队的实际执教/出勤次数，并能下钻到课程记录。
- “被排课”“完成点名”“实际执教”是不同事实。统计依据、代课、双教练和临时助教如何计次须明确。
- 教练收入与结算不由考勤统计自动推出；若要做薪酬另立业务规则。
- 验收场景：同课重复提交不重复增加执教次数；其他教练数据按授权限制访问。

### R13 团课与私教约束

来源：W“团课和私教有不同的约束条件”。

- 当前模型已有团课、小班、私教等类型，但材料没有给出差异规则，因此本条目前只能形成规则评审项。
- 需填写差异表：人数/名额、可参加学员、预约与取消、请假/缺席、扣课单位与扣减比例、课程包适用范围、教练分配、临时加入是否允许。
- 明确同一学员同时有团课包与私教包时，应扣哪个包；不可因都有余额而任意扣减。
- 验收场景：规则确认后，用同一学员参加团课/私教验证各自约束及课时流水；现在不预设私教扣几节。

### R14 家长首页与个人形象

来源：W“归属感、加入天才足球天数、个人照片/GIF、训练总次数、整体评分、移除首页待处理条”；M 三.1、三.5。

- 首页突出孩子姓名、球队/俱乐部身份、个人照片、入队天数、累计训练次数和最新能力综合分，保留清楚的日程入口。
- 综合分支持进入分项详情；未测评时展示空态。
- 移除首页指定“待处理”横条。建议保留已有个人提醒入口与俱乐部公告，除非产品另行决定取消其功能。
- 入队天数以真实入队日期计算，不用注册日期冒充；缺少日期时不编造。
- “像英超”的照片/GIF是视觉方向，不是已确定的格式规范；建议先确认参考效果、照片来源、上传者、审核人和缺图样式，再决定静态图或动图。
- 需确认“首页”是当前日程 Tab 首页，还是希望“成长”成为默认首页，避免两页重复建设。
- 验收场景：多孩子切换后照片、分数、天数和训练次数同步切换；无照片或数据也可正常使用。

### R15 家长成长与能力详情

来源：W“雷达更美观、有姓名、能力值条随成绩变化、测评同步”；M 三.2。

- 在现有成长页和雷达详情上优化层次，明确展示孩子姓名、测评日期、维度名称和分值。
- 能力值条与雷达使用同一份已发布结果；点击维度可查看对应分项。
- 保留训练记录、比赛记录和课堂评价的入口；趋势展示依赖 R09 的历史与可比性规则。
- 验收场景：同次测评在雷达、能力条、分项和教练端一致；局部缺失时明确显示未测，不误导为能力下降。

### R16 排名 分享与激励

来源：W“在所有队员中排名多少”；M 三.3、三.4、五.10。

- 排名、分享卡、徽章分开评估，不捆绑承诺。
- 排名必须定义比较范围、年龄/队别、参与资格、指标、统计周期、有效测评时间、同分规则及小样本展示方式。
- W 的“所有队员排名”与 M 的“同年龄前百分比”不是同一规则。建议优先按同年龄且同标准比较，最终由产品确认。
- 分享先确认是适合截图，还是生成可保存卡片/小程序分享；若生成卡片，字段、照片使用及可见范围需明确。
- 徽章/等级需要统一授予、更新和撤销规则；无规则时不由前端随意计算。
- 验收场景：未测评或不可比学员不被排到末尾；排名注明范围与时间；分享不带其他孩子资料。

### R17 后台 通知与媒体配套

来源：M 三.5、三.6、四。

- 后台第一阶段建议只支撑本轮必要闭环：学员与球队、教练授权、课程库、排课、课程包、测评标准与任务、比赛、操作记录。
- “不依赖 WPS”需明确是后台成为权威来源但保留导入，还是完全停止 WPS 维护；现有设计允许 WPS/Excel 接入，不能默认删除。
- 学员使用内部唯一 ID。手机号可能对应多个孩子，不宜单独作为学员唯一键；身份证是否采集及用途需另定，重复建档须有人工核对机制。
- 学员停训/离队等状态影响名单和未来统计；建议保留其历史出勤，不回写抹除过去参与。
- 日程变更在小程序内可查询；主动推送渠道、订阅条件、接入成本单独评估。M 的“服务号推送为付费附加能力”只是材料说法，不作为已核实的平台事实。
- 图片/视频上传角色、数量、格式、大小、审核与发布范围待定；先做头像与成长展示，不自动扩大成完整视频内容平台。
- 验收场景：后台维护的记录能在授权端正确读取；导入冲突可定位；敏感字段与操作日志按角色可见。

## 5 统一数据口径建议

这些是建议口径，需与教学和运营负责人确认后才能用于开发验收。

| 数据 | 建议定义 | 不能混淆的内容 |
| --- | --- | --- |
| 训练次数 | 学员实际出席且计为训练的活动数，同一活动去重 | 不等于训练项目数，也不必等于扣减课时 |
| 训练模块次数 | 实际参加且完成该模块的活动次数；若无法记录个人完成情况，应标明按到课与课程内容推定 | 教练选了计划不等于每位学员实际完成 |
| 累计时长 | 已确认参与活动/模块的可靠时长累计；使用计划时长时明确为估算 | 多模块时长不能重复叠加整堂课时长 |
| 出勤率 | 在指定周期、名单生效范围内，以确定的应到次数为分母计算 | 请假、取消、停训如何计分母须统一 |
| 剩余课时 | 指定课程包的入账、调整与扣减流水计算结果 | 不靠前端用“总课次减训练次数”计算 |
| 综合能力分 | 指定评分标准版本下已发布的能力结果 | 不等于课堂表现分，不直接混合不同标准 |
| 排名 | 同周期、同适用标准、同规定人群内比较 | 不混合不同年龄或缺测者，除非有认可的换算规则 |
| 教练考勤 | 按约定的实际执教确认记录统计 | 学员出勤人数不等于教练课次 |
| 入队天数 | 按真实入队日期及约定日期边界计算 | 离队再入队是否累计需确认 |

## 7 建议的评估拆分

以下是评估顺序，不是已确认优先级或工期。

**第一组 现有页面与交互调整**：训练内容问题复现与修复、战术板场上姓名、移除首页待处理条、雷达姓名与层次、测评入口整理。主要复用现有能力，仍需明确设计并做真实页面验收。

**第二组 训练业务闭环**：考勤确认、临时参训、友谊赛归类与扣课、团课/私教规则、权限、课堂评价。这组会改变业务数据，应先解决 D01–D04、D07–D09。

**第三组 档案与成长展示**：学员统一详情、训练统计、家长形象卡、入队天数、测评项目与历史展示。依赖稳定的活动、课时与测评口径；部分展示可先行，不能填假数据掩盖缺口。

**第四组 管理后台**：与第二、三组并行评估必要配置和数据维护能力。若要立即关闭教练现有管理入口，必须先证明管理员有可用替代路径。

**第五组 后续增强候选**：培养标准差距、智能建议、公开/可分享排名、徽章、GIF与精选视频、生成式分享卡、教练收入、外部主动通知。是否纳入首期取决于客户目标、规则和预算；W 明确提到的培养模型与排名仍保留为待评估诉求，不因建议分期而删除。

本轮不估算人天。第一组可以较快进入逐项评估；第二至四组需先定业务规则和后台范围，否则估算会失真。

## 8 进入下一轮评估前需要的材料

1. 能力手册/评分表及适用人群，用于核对当前项目库缺项、维度和换算规则。
2. 团课与私教的现行收费、扣课和请假规则，以及友谊赛惯例。
3. “球队教练权限”和“教练考勤”的业务示例，说明谁操作、记录什么。
4. 家长首页参考效果、实际照片来源，以及客户反馈时使用的小程序版本。

其他内容可基于本稿逐项确认，无需一次回答全部问题。
