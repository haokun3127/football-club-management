## 2. 环境矩阵
| 环境 | API 与数据 | 认证及作用 | 准入 |
| --- | --- | --- | --- |
| 本地 | 独立 localhost API + /private/tmp 或项目外缓存目录的临时 SQLite | 仅显式 dev/test 可用调试身份；合成数据 | 不接生产 URL，不写 Documents 高变动缓存 |
| 集成测试 | 独立测试库/卷、合成数据、自动销课时钟可控 | 契约/迁移/并发恢复 | 固定依赖与迁移版本，测试后可清理 |
| 体验/预发布 | 待配置独立 HTTPS 域名与独立库/卷、私有运行时配置 | 真实微信 Bearer 验证；合法域名配置 | 与生产租户、照片和凭据隔离 |
| 生产 | 现有 HTTPS 域名，现场核对真实 release/volume | 只接受已验证认证；真实数据 | 通过发布门禁后单独授权部署 |

候选域名只作为环境槽位，不自行购买或更改 DNS。App ID/Secret、session、手机号及备份路径权限由运维在私有运行时配置，不写仓库。后台静态站点部署与 API 同源或精确 CORS 白名单；禁止通配携带凭据。构建输出注入环境，测试构建不能默认回落生产。

## 3. 数据升级策略：扩展 → 回填 → 核对 → 切换
1. 备份和盘点：真实 schema、记录数、版本分布、source 缺失比例、孤儿关系、当前财务余额来源；只读统计不导出敏感明细。
2. 在副本上增加新结构或 nullable 字段、唯一约束和索引。先兼容旧客户端，再逐步要求新字段。大表分批回填；迁移失败整体事务回滚，长任务独立可恢复。
3. 建立历史映射：旧 attendance/debit 不直接视作新的系统默认事实；保留 legacyId/source/语义标签。课包 ledger 原样保留，禁止把已扣过的历史再次转成扣款。
4. 测评：保留原始单位/旧评分类型与已发布版本；assessedAt 的历史含义不明时标为 legacy/unknown，不能伪造实际测评日。缺课程关联的数据可查，暂不参与需要真实课程的计算。
5. 新旧投影对账：按 club/event/person 检查唯一性、有效课次数及历史；按 task/person/item 检查数值、单位、版本和可见性。可解释差异单列，不强行把新业务口径调成旧口径。
6. 影子计算只在隔离副本运行；确认 O-02/O-14 后才安排线上默认课次补跑。新算法 feature flag 按俱乐部/客户端能力开启，重复任务可恢复。
7. 发布后观察到稳定再决定收紧新字段约束或移除旧接口；旧入口至少在已确认的客户端迁移窗口内给出兼容响应。客户端最低版本/窗口需产品运营确认，不能凭空指定日期。必须逐一列明旧点名/确认/调整接口：可无歧义适配的转培训命令，否则返回明确升级提示；不能以兼容旧客户端为由继续扣课包。独立后台账本接口和数据保留。

备份使用 SQLite 一致快照机制或受控停写备份，包含必要 WAL 处置并验证恢复；不能在活跃写入时只复制主 db 文件。演练必须在独立库执行 integrity_check、foreign_key_check、行数/关键值和业务口径核对，保存校验清单，不泄露敏感内容。

## 4. 发布顺序与回退
顺序：兼容领域与数据库 → API 新契约/feature flags 默认关闭 → 隔离客户端与后台 → Bearer 实机验收 → 小范围俱乐部灰度 → 观察与逐步放量。后台只是另一客户端，不另建数据库。

回退时仍保持培训与扣账隔离，不重新开启旧前台扣账副作用。回退优先：关闭新增写入与相关 feature flag、回退到已固定镜像/客户端入口，同时保留新增历史。新 schema 应允许旧 API 读取；不可逆字段删除不与同次发布混做。迁移或数据回填造成损坏时，先停写并明确最后一致时点、备份恢复和之后新增写入的处置，不能自动全库恢复丢失新数据。

必须保存：release commit、镜像 digest、schema 版本、客户端版本、配置项名称及是否启用、备份校验、灰度范围、放行人、回退演练结果。不能用可变 latest 或旧目录重新 build 代替固定发布。

## 5. 发布验证
在隔离环境执行真实项目命令：
```sh
pnpm install --frozen-lockfile
pnpm check
pnpm build
```
随后以私有环境配置运行 API db:migrate/start，检查 /health、OpenAPI、真实 Bearer 请求、微信合法域名与真机流程。命令需在实际包 scripts 和部署版本核对后执行，本次没有伪报运行结果。

旧部署文档“家长写课时一律 403”与新需求存在冲突：新准入应允许家长修正自己孩子的培训记录，仍拒绝主档、课程编排、财务、其他孩子等写入。不要沿用旧 smoke 的全面禁止断言。

门禁包括：迁移恢复演练、跨租户/绑定关系/角色停任、隐私字段和导出；课次日期任务幂等和人工保护；测评类型/真实课程/补录/个人发布/修订；并发409、断网恢复；导入重复/部分失败；UI与BI与导出一致；生产默认禁用调试身份。

## 6. 运维与容量
沿用单写 SQLite 时，不允许多个独立写实例直接共享同一文件；先明确工作进程所有权、事务和持久化幂等。自动课次与导入/模型批量计算分批执行、设上限、支持恢复，避免长事务阻塞在线写入。

观测：job lag、失败课程/人数、重试、冲突率、草稿保存失败、发布失败、导入错误、SQLite busy、响应延迟分位数、磁盘/备份、数据投影延迟。日志只带必要标识和错误类别，敏感数据脱敏。

既有“500日常用户、50并发5分钟、p95<300ms”是历史建议，产品 v1.2 明确仅需简单保存保护，没有批准高并发 SLA。先取得实际学员/队伍/并发/文件量，压测只读与典型写入、任务和导入混合负载，再订指标。是否迁移 PostgreSQL 由持续写并发、可用性和运维要求决定，不把升级 UI 变成无依据换数据库。
