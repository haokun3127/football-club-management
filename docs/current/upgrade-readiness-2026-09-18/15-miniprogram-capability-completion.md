## 可直接评审的路径

1. **看队伍结果**：C10 → C33 → 20米跑/传接球 → 林予安个人结果；返回同队名单，再查看周子衡待确认、许明澈未测。C33-E独立展示“汇总失败、名单仍可用”。
2. **维护接课时间**：C28/C29 → C34；暂停/开启接课。进入C35 → 周六 → 选17:00 → 保存 → C34-S，核对原工作日時段保留、新周六时段新增。C35-E演示失败后原选择仍在。
3. **找场地**：P22“训练场地” → P29 → 分类/检索 → 场地详情。可定位场地进入地图交接示例；无坐标场地显示原因并联系俱乐部，不拿其他位置代替。
4. **看比赛**：P13 → 未开始/已结束；赛前显示09:30集合、10:00开赛和场地。P31-CANCEL演示取消通知，不提供赴场主操作。教练从C10“本队比赛”进入C24-A。
5. **准备战术**：C24-A → C26 → 选择3-2-1 → C26-A → 保存 → C26-S；或选择替补李沐宸 → 点宋景行换下 → C26-SWAP → 保存后回看。C24已结束比赛进入C26-RO，只有返回动作。

## 数据与业务边界

- 以需求v1.1和第13份服务器代码核查为依据。现有代码支持的字段口径继续使用：`acceptsPrivateLessons`、`availabilitySlots`；UI周一到周日分别对应dayIndex 0–6，17/18/19/20点对应slotIndex 0–3。例如周六17点为`5-0`。没有把旧离散时间点改成未经确认的任意时间区间。
- 暂停接课保留时段与历史咨询；分派不等于已承接、时间可用不等于预约成功。无选中时段应明确为空，不自动恢复默认全选。
- 能力浏览只使用已确认结果；草稿、未测、明确不测评不能相互替换。队伍视图按名单展示，不用队均值充当培养标准。
- 战术图的球员姓名、模板和换人属于本轮可评审设计。O-10的详细技术统计、填写责任等仍未转成已确认实施范围；没有新增强制现场逐事件录入，也没有恢复点名扣课或强制逐课评价。
- 场地、地址、人物和成绩均为设计演示数据，不能导入生产。导航的实现仍需校验真实坐标并交给微信`wx.openLocation`；Figma只展示交接状态，不发起真实导航。
- 地图不支持、无坐标等情况保留地址和联系入口。已结束/取消比赛的写权限须由现有服务端门禁保障；Figma只读原型不能替代权限测试。

## 验证结果

- 45张本轮最终截图已回读并保存；包括36张新画板和9张修改画板。
- 全部45张在375×812基准下未发现缺失字体或横向越界。私教未选时段控件颜色已统一。
- 130个画板跳转目标存在；73项关键目标断言通过。只读战术板唯一的非返回历史动作是回到比赛详情，没有修改入口。
- 两种阵型都保留7名场上球员和2名替补；换人示例中李沐宸上场、宋景行进入替补，没有新增或丢失球员。
- 页面清单、旧路由映射和任务检查点同步更新。原来的“队伍能力由C16任务详情承接”“私教设置由C29咨询跟进代替”“场地只落到P25合页”已改为明确设计入口。

## 完成范围与后续

本轮五项缺失能力的**设计与关键原型状态已补齐**。搜索示例、周一/周六时段示例和选定球员换人示例用于逐页评审，并非任意输入、所有时段组合或所有换人组合都已在Figma实现；自由拖动、真实保存/错误恢复及地图调用属于后续小程序代码实现。

320/430宽、微信字号放大、键盘遮挡、真实权限与iOS/Android设备验证仍留在实施验收阶段。保险家长可见范围、退出登录及旧课堂评分历史属于第14份报告的其他待承接项，不在本轮所列五项内，也未被标成已解决。

本轮未修改业务源码、数据库或生产环境；当前全栈准备任务继续保留，供用户逐页评审后再推进开发链路。
