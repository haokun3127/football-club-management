# 后台逐页设计复查结论 · 2026-09-22

结论：当前后台已具备首版页面框架和视觉模板，但详情、编辑、对象关联及关键操作仍有明显缺口，尚不满足按现稿直接完整开发与验收的条件。需按业务对象补齐维护流程，并修订已确认的新需求；不能用画板存在或需求编号覆盖替代设计完成。

## 3. 优先修订的问题

1. **数据管理对象维护链路。** 先确定分类与数据表清单；补联系人、教练、队伍、学期、场地、原子训练内容等新增/详情/编辑界面。学员资料、成员关系、账号绑定及任职应分别表达。
2. **纠正操作目标。** D10维护成员→D04编辑学员；D14新建原子内容→D15组合模板；M09预览下发→M10采集明细；S03登记需求→已有咨询的S04；S05添加执行记录→S06交付列表。页面名和按钮名都有，但目标未承接该动作。
3. **导入导出可审核。** 保留D18—D21现有四步结构，补字段选择、逐行差异、冲突处理、失败下载和安全重试；补D22字段/范围选择与下载结果，让各业务表可以进入。
4. **评分规则、修订与发布。** M02—M06补原始成绩→整数分值→等级及版本关联、实际参数配置和试算结果；M09/M11补对象范围预览和修订核对。正式标准未提供时保持草稿，不能虚构数值。
5. **BI对象及明细对应。** 补每项指标对应明细及筛选回显；B04需明确学员和项目选择。5页均已有内部纵向滚动，首屏截图之外的内容不列为裁切缺陷；真实原型滚动手势未在本次逐项操作测试。
6. **统一多人维护状态。** 用可复用桌面列表、详情、编辑、只读、无权限、校验错误、保存失败保留输入、并发冲突和成功回读状态，承接所有维护对象。无需每个对象另画一套完全相同的状态页，但需明确适用关系。
7. **前后台衔接。** D24/D25承接已确认Banner图片与点击目标；后台里程碑规则、徽章、鼓励文案及达成记录缺对应管理界面。具体归属模块待设计，不自动新增一级菜单。

## 4. 逐页结论

优先级是设计补齐建议：P1表示涉及关键业务操作、已确认需求或关键对象上下文，应在对应模块开发前解决；P2表示主体可复用、需完善字段/关联/状态。不是生产事故级别，不是新增业务授权，也不是完成度百分比。57页中37页列P1、20页列P2；每页可能包含多个共用问题，不能当成57个独立新页面。

## 5. 需要补的界面类型，不等于新增画板数量

- 数据分类与业务表切换；工作台分区编辑与模块选择。
- 联系人详情/关系编辑、教练档案/任职、队伍主档/成员关系、学期资料、场地资料；独立球探建档及原子内容编辑。
- 活动详情及三类型维护、排课预览与变更影响、训练记录修正。
- 导入逐行差异与冲突处理、失败明细、导出字段选择和下载结果。
- 两段评分区间编辑/试算、任务范围确认、个人修订核对与发布；培养标准配置和成长展示组织。
- Banner图片及跳转配置、里程碑规则与素材/达成管理。
- 服务需求登记、沟通分派、计划/执行记录、交付详情与附件反馈。
- 账号创建/停用、授权与绑定、接入配置状态和审计详情；统一桌面异常与并发状态。

同一编辑抽屉可复用，新增和编辑可共享结构但必须区分初始值与保存结果。最终缺多少独立画板，要在确定复用方式后统计；本报告不把这些界面类型硬算成新页面数量。

## 6. 设计完成的复核标准

每个对象均能说明：从哪个分类/表进入、当前记录是谁、哪些字段可看/可改、如何新增/编辑、如何关联其他对象、如何导入导出、保存后去哪里、失败/冲突如何继续、哪些变化写入历史。关键路径可以在原型中从工作台连续演练，不能依赖评审者手工找另一张画板补流程。

设计验收与实现验收分别进行：画稿表达输入、校验和结果；真实权限、持久化、重试与并发由实施测试验证。继续遵守不凭姓名/手机号自动扩权、正常训练计次与财务隔离、测评确认后家长可见及历史可追溯等既有规则。
