# 数据、接口与权限方案

2026-09-20 已按产品 v1.2 同步，详细契约见 [16号规格](16-confirmed-rules-and-engineering-spec.md)。本文件所有新增实体名、路径及错误码均为技术候选 P；不是已上线接口。现有服务与迁移先复用，再通过契约测试确定变化，禁止照文档重复建一套业务事实。

## 1. 领域边界
- 人员身份、俱乐部成员、队伍关系、联系人、登录账号分别建模。一个人可有球探到正式学员的状态变化；转入沿用 identity，不复制成长历史。联系人维护不等于家长账号绑定。
- 日程保存类型、业务时区、原安排与变更链。当次参与名单及关系有效期必须可追溯，不能用今日名单补齐全部过去课程。
- 训练内容实例保存所选原子内容版本、顺序、配置时长及模板来源。模板更新不改历史；内容频次/时长是配置关联统计，并非实测动作完成。
- 培训记录与财务分离。一个俱乐部/课程/人员只有一个当前有效计课次结果，配多条不可静默删除的修订。取消、请假、撤回和人工明确修正有独立来源。
- 评价是 current + revisions，文本及受控用语按需更新，不转为分数。
- 测评项目定义携带类型、单位、测试方法和版本；任务携带周期、范围、名单、必测项。每人每项成绩记录真实课程和测量日期。
- 模型定义、发布版本、计算结果、个人发布记录分离。现有 DAG 与输入血缘可复用；草稿、计算完成和家长可见是不同状态。
- 服务目录、咨询、分派、承接、计划、执行、交付分开；球探工作复用人员和日程，内部专业意见不默认公开。
- 导入批次记录来源、外部标识、行 hash、映射版本、空值策略、处理结果；导出遵守对象和字段双重权限。

## 2. 培训记录状态与并发
候选结构：training_record_current(clubId,eventId,personId,identityAtEvent,counted,source,explicitOverride,revision)，training_record_revision(before,after,actor,reason,occurredAt,requestId)。字段可归入现有表，但必须满足唯一性、历史与事务约束。

业务日期过后、课程未取消、当次名单有效，自动生成默认结果；有效请假不计课次。自动任务必须持久化游标/运行结果、可重试和补跑，不依赖用户打开页面。幂等键按 club/event/person/ruleVersion，事务中检查唯一键和当前人工明确修正，重试不得覆盖人工结果。

家长只修改绑定子女，教练只修改授权队伍内该堂记录。更新带 expectedRevision；版本一致时当前结果与历史同事务提交。409 返回最新版本及获准差异，用户核对后重新保存；不是提交业务审批。取消课程令全部读端的有效计次为否并保留历史；保存同事务核对课程状态/版本及记录版本。后台课包能力保留，前台不展示且培训计次不触发扣账。请假撤回的默认重算不得覆盖独立的人工明确结果。

O-02 决定日期/名单边界，O-14 决定改期补课关系。上线前以具体案例确认：午夜跨日、跨时区、周末补跑、取消后恢复、事后补假、两端同时修改。未确认边界先不执行历史批量补算。

## 3. 类型化测评
候选值为带判别标签的联合类型：decimal + unit（秒/米等）、integer + unit（次数）、scale + definitionVersion（量表），可扩展枚举等有限类型。空值表示未录；零仅在该项目允许且确实测得时有效。输入精度、范围、单位转换必须来自项目定义，不硬编码统一 0—100。

task.startsOn / dueOn 定义实际发生周期，不等于录入截止。新记录由教练选择有效的周期内课程，所选即为归属；服务端取课程日期作发生日期快照，recordedAt/publishedAt 另存，不要求教练重复填日期。不同项目可属于不同课程，任务结束后仍可录入和确认。历史缺真实课程时保留来源不完整，不伪造关系或日期。

按人维护工作 revision 和已发布 revision。自动保存只表示服务器确认成功；离线缓存不计完成。必测项齐全或明确“不测评”才算处理完成；不测评单列，非零分、不替换既有成绩。个人确认不等待全队。修订先生成草稿，确认前保留旧发布；确认和重复请求幂等。

“最新”按实际发生时间及修订生效关系选择，不能以补录/发布时间把旧事实顶成最新。综合模型涉及不同时间的输入时，依据其明确选择规则执行，并展示血缘。

三层结果：原始项目/值及单位 → 第一段区间映射 → 整数分值项目/结果 → 第二段区间映射 → 等级项目/结果。后台维护关联、边界、适用条件与两个不可变规则版本；教练只输入原始值。原始值可以有小数，分值必须是区间输出整数，等级如 S/A+/A 不写死完整表。不得将原始值隐式包装为 score；缺规则/未命中保留原始值并明确状态，规则更新不静默改已确认历史。

## 4. 候选接口契约
沿用现有 /clubs/:clubId/app-clients/:clientId 的角色 BFF；后台使用同一应用服务，不能绕过领域约束。以下短路径仅表达操作，不承诺最终 REST 命名：

| 操作 | 请求关键字段 | 响应及失败语义 |
| --- | --- | --- |
| 查询个人培训记录 | eventId、personId，分页及时间筛选 | 当前结果、来源、revision、允许操作；字段裁剪 |
| 提交请假/撤回 | expectedRevision、reason、idempotencyKey | 保存后立即生效；重复返回同结果；版本冲突 409 |
| 修正计课次 | counted、reason、expectedRevision、idempotencyKey | 当前记录 + 新历史版本；不返回财务扣减结果 |
| 测评草稿 PATCH | taskId、studentId、entries[{itemId,value,eventId}]（课程日期由服务端解析）、expectedRevision | revision、逐项保存状态、完成度；无效项 422 候选 |
| 标记不测评 | reason、expectedRevision | processed=true、measured=false；内部原因字段裁剪 |
| 个人确认 | workingRevision、idempotencyKey | publicationId、revision、publishedAt；未齐/模型失败明确说明 |
| 试算模型 | immutableVersion / draftRevision、输入引用 | 输出、校验、输入血缘；循环或单位冲突阻止 |
| 导入预览/确认 | templateVersion、mappingVersion、sourceId、fileHash、空值与部分成功策略、previewRevision | 逐行新增/更新/重复/失败；确认校验预览未失效 |
| BI 查询/导出 | 相同筛选、视图数据版本及截止时刻 | 同一版本或显式刷新/新版本；导出独立授权并带条件、版本和生成时间 |
| 服务分派/承接 | serviceRequestId、assignee、expectedRevision | 分派与已承接独立；咨询不形成订单 |

认证 actor 必须来自服务端已验证 session，不能信任 body 中传入的 actorUserId。club、student、team、task、event 和模型输入均校验归属；不要仅比较请求 URL 的 clubId。客户端 capabilities 供显示，服务端每次动作重新授权。错误响应不泄露另一俱乐部对象是否存在。

列表要求分页、稳定排序、过滤条件回显；批量接口限制单次量、文件大小和计算图深度。具体上限由隔离压测确定，不虚构 SLA。统一 requestId、错误码与可恢复建议；日志不包含手机号、成绩草稿正文或令牌。

## 5. 角色与字段
| 身份 | 允许范围 | 必须拒绝 |
| --- | --- | --- |
| 家长 | 绑定子女、提交请假、修正培训记录、看确认结果、咨询 | 改主档/模型/课程；看测评草稿、其他孩子、内部球探意见 |
| 主教练 | 授权队伍教学资料、本人负责课程内容、测评与评价、课次修正 | 编辑长期队伍/学期主档、默认读取敏感联系人或财务 |
| 协同教练 | 授权队伍内教学记录、课次修正、测评录入/更正/确认；不只检查默认主教练 | 从协同身份自动取得课程内容编辑权 |
| 俱乐部授权人员 | 明确动作、对象和字段白名单 | 仅凭管理员 UI 导航取得所有敏感数据 |
| 平台人员 | 接入及公共定义配置 | 因共享模板直接读取跨俱乐部资料 |

读权限不自动包含导出权限；完整联系人、证件、保单单独授权。当前小程序 BFF 不返回课包余额/扣减信息及余额提醒，后台课包按独立权限保留。分享另有字段白名单和图片使用依据。角色切换清理不再有权访问的内存/缓存；草稿缓存按用户、俱乐部、任务、人员分区，退出或权限撤销时处置，不跨账号复用。

## 6. 一致口径
MET-01—14 以权威 03 文档为定义。服务层只维护一份公式，页面和导出引用同一查询/投影。草稿不进入家长成长，未测不填零，临时参训不混正式分母，未知日期不计成导入日。更正提交后失效相关缓存，若异步重算，返回 processing + dataAsOf，不用旧数冒充已刷新。

并发采用 SQLite 单写和短事务；版本检查、数据及历史写入在同一事务内，避免事务外检查后无条件覆盖。冲突返回最新获准状态并保留输入；无需分布式锁或多写架构。

关键验收：重复任务不重计；人工结果不被系统覆盖；409 不丢另一方数据；旧发布仍可看；周期外补录可用但课程必须在周期内；跨人/跨队/跨 club 写入和导出均拒绝；同筛选 UI、BI、导出一致。
