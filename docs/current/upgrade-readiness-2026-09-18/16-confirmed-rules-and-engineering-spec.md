## 2. 测评课程归属

### 2.1 操作与事实

- 课程入口预选当前课程；任务入口提供授权范围内、符合任务周期的训练课。教练选定后，提交条目以该课为归属；不要求重复填测评日期。
- 同一任务按人、项目来自不同课程。批量选择显示人数、项目及选中条目，只修改这些条目；允许逐条改课程。
- 服务端校验课程、学员、任务和俱乐部关系及权限。普通有效课程可录；取消/跨周期/无可用课等异常按 O-06，未定前明确提示并保留输入，不偷偷换课。
- 保存 `eventId` 与课程业务日期快照，课程版本用于识别后续变更；`recordedAt`/`confirmedAt` 来自服务端。不要把录入时间或发布时间写成 `assessedAt`。
- 更正课程即使数值相同也算变化；比较覆盖值、单位、课程、日期和定义版本。已确认来源不因课程改期静默漂移，按异常/修订流程处理。
- “最新成绩”按所选课的发生日期及已确认修订选择；跨课综合模型保留各条来源，不能给整份结果虚构一个共同测评日。

### 2.2 条目契约建议

教练提交 `taskId/studentId/expectedRevision/entries[{rawProjectId,rawValue,eventId}]`。服务端解析单位、定义版本和课程日期，不信任客户端提交的分值、等级或操作者身份。复用既有 `testItemId/metricId` 时保持明确映射，不平行造一套不可互通 ID。

响应逐项包含原始值及单位、课程与日期、保存状态、工作版本、两段映射状态/结果和获准动作。日期快照和来源随发布事实持久化；不仅放在前端草稿中。

## 3. 原始成绩、整数分值和等级

### 3.1 三个关联项目

| 层 | 建议定义 | 产生方式 | 保存与展示 |
| --- | --- | --- | --- |
| 原始成绩 | rawProjectId、值类型、单位、精度、定义版本 | 教练录入或获准导入 | 原始值可含小数，原样保留有效精度 |
| 分值 | scoreProjectId、关联 rawProjectId、原始区间映射版本 | 第一段区间映射 | 输出必须是整数；不把原始值四舍五入后冒充得分 |
| 评价等级 | gradeProjectId、关联 scoreProjectId、整数区间映射版本 | 第二段区间映射 | 标签如 S、A+、A；名称、顺序和边界由后台维护 |

三个项目可复用现有项目/模型/输出定义体系，业务关联必须明确，无需为每层新建一整套独立模块。模型如需消费分值，应引用分值项目的具体结果；不能把带“秒/米/次”的原始输入包装成 score。等级不能自动数值化混入综合模型，教练文字评价和培养目标保持独立。

### 3.2 区间与配置校验

- 配置明确输入项目、单位/合法域、适用条件、下上界与开闭边界、输出值及版本。常用连续数值区间可默认左闭右开，末端闭合须显式表达；整数等级区间可采用含端点整数范围。
- 同一适用范围内的区间不能重叠、重复命中或存在无效边界；分值输出只能是有限整数。规则对合法输入域的空缺须在预览显示；不能默认为零、最高等级或最近区间。
- 发布校验：第一段合法域覆盖、第二段覆盖第一段可输出整数；空缺应补规则或明确从有效输入域排除，不能发布一个宣称完整却无法映射的配置。运行时遇到历史异常仍返回“未命中”。
- 数值比较遵守项目精度，可转为最小精度整数后比较，避免二进制浮点误分临界值；范围方向由配置表达，不把跑步秒数当越大越好。
- 提供临界值、临界值两侧、无效单位、缺规则的试算。完整等级表、正式阈值、年龄/组别选择仍属 O-04；演示值仅用于 ACC-63，不进入生产标准。

### 3.3 版本与缺配置状态

后台维护草稿→校验/试算→发布不可变版本→停用。每次结果保存原始记录版本、整数分值、等级、两段映射版本和必要输入引用。既有结果不因配置发布而重算；显式重算形成修订草稿，再确认后家长才见新版。

未配置或未命中不妨碍原始草稿保存；对应分值/等级为空并带原因，禁止隐式采用旧结果。个人确认沿用既有完整性规则：可以展示的原始事实与可计算的派生结果分别表达，不为缺失派生结果伪造完成；如具体模型要求全部派生输入，返回可解释的缺项。是否允许仅原始值确认的细分策略须在实现前与该项目的确认条件对齐，不能默认新增整队等待或俱乐部审批。

旧 `score_0_100/rating_1_5` 数据保留 legacy 标识和既有结果，不能逆向伪造原始秒数或映射版本。现有 DAG、发布事务和血缘优先复用；旧评分适配与新两段映射分开。

## 4. 课次修正、后台扣课与权限

### 4.1 已确定的轻量规则

家长仅改自己绑定孩子，授权教练仅改教学范围；保存直接生效、无需审批。历史至少有孩子、课程、操作方、操作人、时间、前后值及可选原因。恢复成旧值仍保留中间修改；失败不生成成功历史。

同人同课只有一份当前有效计次。取消课程令有效计次为否，历史人工选择仍保留；保存事务同时核对课程状态/版本和记录版本，避免取消前的编辑把结果写回。自动补跑不覆盖人工修正；取消后恢复的业务细则仍按 O-14，不暗自恢复历史 true。

### 4.2 保留能力但隔离入口

| 入口/数据 | 当前模式处理 |
| --- | --- |
| 后台课包/扣课账本、历史及获准调整 | 保留存储、领域能力、权限与独立维护；不是本轮删除对象 |
| 自动计次、请假、家长或教练课次修正 | 仅更新培训事实和历史，不调用扣账副作用 |
| 旧点名、lesson-confirmation、lesson-adjustment 等前台写入口 | 按实际路由逐一归类：可无歧义适配为培训命令则适配；否则返回升级/不支持提示；不得继续扣账 |
| 家长/教练详情、首页、提醒及 BFF | 隐藏/不返回余额、扣减明细和余额提醒；培训课次、请假及修正历史继续提供 |
| 后台导入、手动账本调整 | 专门权限、独立语义、幂等与历史；不得由普通教练权限获得 |
| 回退/兼容策略 | 服务端保持培训与账本隔离；回退 UI 或旧客户端不能重新启用已禁用副作用 |

前台隐藏不替代服务端控制。后台保留能力也不意味着本轮自动接通财务、支付或收费结算。对保留接口和适配接口建立清单，测试来源请求而非仅检查新按钮。

### 4.3 协同教练

以有效身份、俱乐部关系、队伍范围和动作权限判定测评录入、更正、确认。不能只比较 `team.defaultCoachId`。无关教练、已撤权教练、家长不能写测评；协同教练不能因此编辑课程编排或后台映射规则。读、写、发布、导出按各自权限执行。

## 5. 简单并发保护

保留当前 SQLite 架构，采用单写服务部署、共享数据库连接事务队列和短事务。无需新增分布式锁、协作编辑、消息系统或高并发数据库。

1. 表单读到 `revision`；提交带 `expectedRevision` 和请求标识。
2. 事务内重新读取当前状态与授权对象、核对版本及业务状态，再写入数据、递增版本并追加历史。现有仓储能用条件更新时以 `WHERE revision = expectedRevision` 判成功；JSON 状态可在同一独占写事务内读检写，不能先在事务外检查再无条件 UPSERT。
3. 不匹配返回已有冲突语义（通常 409）及获准最新状态；保留本地输入，让用户核对后显式重提，不静默自动覆盖或强制最后写入获胜。
4. 更新和历史/发布指针同事务提交或回滚。请求响应丢失可重试，同一标识与相同负载返回原结果；相同标识不同负载拒绝。
5. 批量保存明确逐条成功/失败，成功项不重复写，失败项保留重试。数据库 busy/锁超时不伪报保存成功，可做有限技术重试；业务版本冲突不自动重试覆盖。

现有版本控制不能称为“没有并发保护”；需要补核对持久化事务是否满足上述原子性。部署明确单写约束；今后需要多写实例时再评估，不将它作为当前项目门槛。

## 6. 自由拖放战术板

- 打开授权名单与球场；新增球员由教练拖入，不按前11人、固定7人或模板自动填满。已有合法布局可继续回读。
- 每名球员最多一个球场位置；从名单拖入、场内移位、拖回名单均可。允许空球场和不同人数，不弹阵型选择、不强制一对一换人。
- 建议保存 `eventId/boardId/revision/placements[{playerId,x,y}]`；坐标使用球场内归一化值，在不同屏幕保持相对位置。服务端检查坐标为有限有效值、无重复人员、人员可用及对象权限；不保存冗余固定阵型作为真相。
- 显示未保存/保存中/已保存/失败；重进恢复服务端实际人员与位置，失败保留本地修改。既有对象只读门禁继续遵守，拖放自由不自动扩大赛后修改权限。
- 老布局迁移保留位置及人员，不自动删到7人或补满11人；历史人数错误通过教练调整，不能迁移时静默猜测真实上场。
- 不从战术布局推导实际参赛、课次、比赛统计或评分。画布仅是布置工具。
