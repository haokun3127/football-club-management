# 新旧 UI 优点继承评审

日期：2026-09-18。范围：新版继续作为主体，检查旧版有价值的能力和体验是否遗漏；本轮不整合两套设计、不修改 Figma、不处理开发链路。

更新：本篇保留恢复前的文档对照性质。已另完成 9 组重点新旧画板实图复评，见 [本轮实图对照](12-ui-visual-comparison.md) 和 [截图报告](12-ui-visual-comparison.html)。该报告纠正七天周历、成长能力条及里程碑入口的判断；用户解锁后已补齐重点教练端与比赛实图，并发现个人结果入口指向任务页。

## 结论与证据边界

新版覆盖更多业务页面，但“旧路由有映射”不等于原有能力已保留。当前交付材料中，比赛/其他活动详情、可解释的成长历史、队伍能力浏览和连续测评录入存在缺口或弱化，需要纳入逐页评估。

本次完成的是**设计内容与交互说明的对照检查**。缺口指新版页面目录、内容清单或已有原型回读证据没有表达相应能力，不代表线上产品已经丢失该功能。

**在线视觉比较未完成。** Figma MCP 读取失败（HTTP transport error），浏览器创建页面及读取状态均超时，无法取得新旧当前画面的配对截图。没有据此认定新版整体视觉不如旧版，也没有进行实际可用性测试。

## 二、视觉优点：继承方向与待核验项目

本节是基于历史设计材料的建议，**不是已证实的新版视觉退步清单**。须取得 V6/V7 与新版配对截图后才能做最终比较。

| 值得保留的旧设计思路 | 新版逐页检查重点 | 继承时的边界 |
|---|---|---|
| 品牌红点缀、深色核心卡、浅色内容区的层次 | P01/P08/C03 是否能在首屏迅速识别球员、当天课程和主要数据；是否所有内容都变成同权重白卡 | 沿用新版 #A80F1B 红色；深色卡只服务重点，不能为“体育感”牺牲阅读。新旧品牌红本身已经延续 |
| 工作台将时间做成清晰视觉锚点，队伍和场地紧邻 | C01/C03 的课程时间、地点、队伍是否容易扫读；长名称是否自然换行 | 保留上下文层次，去掉不再需要的整班点名和强制课后评价 |
| 成长信息兼有图形、趋势、数值和详情入口 | P08/P09/C11 的能力概览是否可理解，历史来源是否可达；多维/缺值状态是否清晰 | 不机械保留固定六维雷达；真实模型维度决定图形，缺值不填零 |
| 球队概览和学员卡支持快速扫视、直接进入个人 | C10/C11 的学员浏览效率，姓名/状态层次和触区 | 不恢复旧图中的 TOP/底部排名；同一层级头像保持同一品牌语义 |
| 测评页的固定连续操作区 | C18 键盘弹出时是否仍能看到当前学员、单位、保存状态和下一步；长名单是否过度滚动 | 连续录入与逐人确认分开；安全区和大字模式必须实际检查 |
| 战术板大工作面和真实名单分区 | C26 的球场空间、密集姓名、替补区与拖动反馈 | 具体交互受 O-10 约束，静态画板不等于可拖动实现 |

历史离线图自身也有不该继承的内容：成长页“出勤率”不能直接沿用为实测出勤；能力总览中的同伴排名不符合新需求；小字和长内容挤压要按新版可读性目标重评。因此继承的是层次、可读性和操作效率，不能照搬整张旧图。

## 三、按新需求保留的改进，不算遗漏

- 正常训练自动生成轻量记录、双方直接修正；不恢复逐堂点名销课、请假审批或双方再次签认。
- 按需更新评价，不恢复每堂训练强制评价、拍照或视频任务。
- 个人结果独立确认、原始值和单位清楚、缺测不填零、周期后仍可补录；不恢复全队齐备才能发布。
- 能力按个人历史和适用培养标准解释，不恢复同伴排名，也不恢复旧 P5 已明确移除的“历史对比”按钮。
- 保留新版四个可配置首页入口、成长分享、服务咨询跟进；旧版导航数量和页面拆分不是硬约束。
- 新后台缺少同范围的旧视觉基准，本轮不宣称其视觉比旧后台退步；单独按新需求评估表格、筛选、状态与操作反馈。

## 四、逐页评估建议顺序与验收

1. P02/P03/P13：三类活动能看全，比赛/其他详情不误用训练操作。
2. P08—P11、C10/C11：概览→详情→来源→历史变化可追查，队伍任务进度与学员能力分清。
3. C17/C18/C20：连续输入几个项目再核对个人结果，含保存失败、退出恢复、键盘遮挡。
4. C01/C03/C04：跨队安排清楚，训练内容找得到、选得准、保存后回显。
5. P25/P22/C28/C26：到场信息、身份切换和战术板候选交互。

每页先保留新版布局，再标明“保留旧优点/补缺口/按新需求取消/待决”；通过截图与原型操作复核后才标完成。先评页面并修改，再处理开发链路，遵循用户已明确的顺序。
