## P01-01 · 家长首页信息与成长展示调整

- 提出及确认日期：2026-09-22。
- 页面：[P01 家长首页](https://www.figma.com/design/EyQtDtILGDZDf6neLBL6vs?node-id=15-2)。
- 状态：用户已确认，待设计修改及后续实施。
- 确认依据：助手逐条复述后，用户回复“你理解的准确，麻烦你评估一下是否有价值的改动”。

### 已确认修改

1. 顶部“首页”改为当前俱乐部名称。
2. 原第一张卡片拆分为上下区域，不强制为两张独立卡片：上部左侧是孩子姓名、俱乐部等基础信息，右上角是孩子头像；点击头像可以切换孩子，页面数据随孩子切换。
3. 下部显示训练数据统计、已达成里程碑、对应鼓励话语和最近成长事件，例如某项训练内容累计达到一定次数、某项测评指标有所提高。既表达累计成果，也表达最近进步；里程碑使用徽章图标。空间不足时可采用左右滑动卡片。
4. 指标进步采用已确认测评结果，鼓励内容对应真实达成事件。
5. 成长区域后为俱乐部 Banner，整体展示后台维护的图片，点击支持跳转；后台维护图片及跳转目标。
6. 功能图标区保持现有设计；“下一次训练”保持现有设计。

### 关联工作及未定细则

- 涉及 P01 布局、孩子切换、成长数据展示、徽章素材及后台 Banner 维护。
- 复用现有训练事实与已确认测评结果；具体累计门槛、比较条件、徽章和文案规则、历史更正后的达成处理仍需细化。不能把课程配置关联次数冒充实测动作完成次数。
- Banner 跳转目标类型尚未规定，不自动扩大到任意外部链接。
- 与既有需求和16号规格衔接，沿用前台隐藏课包余额、培训记录可更正及测评确认可见等规则。

### 价值评估（方案判断，不是界面实测）

整体值得实施。身份区域有助于辨认当前孩子及切换；训练事实、进步事件与鼓励结合，有助于家长理解训练价值；Banner 支持俱乐部内容运营。功能入口与下一次训练保留，限制改动范围。

标题、身份布局和 Banner 的工作量相对较小；里程碑需要明确数据规则、来源追溯、去重及更正处理，不能当成单纯装饰改版。尚未修改或截图核验新界面，也没有用户测试证据支持留存或续费提升。

### 评估建议（尚未确认，不作为实施要求）

- 累计统计保持直接可见，横滑主要承载近期里程碑；露出下一张卡片边缘或分页提示，避免内容不可发现。
- 头像旁增加明确的切换提示，避免家长以为只用于看头像或资料。
- 控制成长区和 Banner 高度，保证功能入口及下一次训练仍容易找到；具体尺寸待改图后核验。
- 优先少量可解释的里程碑；无新成果时展示真实累计进度，不生成虚假祝贺。
- 达成文案区分训练内容参与/配置关联与实测成绩进步，同一项目在可比较条件下解释提高，避免把秒数增大误判为进步。

## P01-02 · 后台规则驱动的里程碑自动达成

- 提出及确认日期：2026-09-22。
- 关联：P01-01 的成长区域，以及后台里程碑规则维护。
- 状态：用户已确认，待设计修改及后续实施。
- 确认依据：用户明确“参与数字从课堂统计来，能力提高从测评成绩来，后台制定一些规则，数据达到了就给予对应的里程碑”；助手复述数据来源、后台规则、自动生成达成记录及无需手动颁发后，用户回复“对”。

### 已确认修改

1. 训练参与和积累类里程碑使用课堂统计，关联孩子与训练内容；可按累计训练课次、某项训练内容累计参与次数设置条件。
2. 能力进步和达标类里程碑使用已确认的测评成绩；可按某项成绩的进步幅度、分值或等级达到目标设置条件。
3. 后台维护每项里程碑的达成条件、名称、徽章和鼓励话语。
4. 系统根据真实业务数据自动判断是否满足规则，满足后生成该孩子的里程碑达成记录；家长首页展示最近获得的里程碑。
5. 教练正常记录课堂和测评即可，无需另外手动颁发里程碑。
6. 某项训练内容参与次数按课堂记录统计，不推算孩子实际完成动作的次数；不能用参与次数直接证明能力提高。

### 关联工作及未定细则

- 复用现有课堂统计与已确认测评事实，补齐规则配置、自动判定、达成记录和前端展示链路；以上均为待实施计划，不代表已有代码完成。
- 具体门槛、统计时间范围、成绩比较基准及可比条件、重复达成策略、规则版本变化及历史数据更正后的处理仍需细化，不将示例数值作为正式规则。
- P01-01 的其他评估建议维持原状态；本次确认不扩大为所有建议均已确认。

## P02-01 · 可展开月历、事件配色、孩子筛选与位置展示

- 提出及确认日期：2026-09-22。
- 页面：[P02 日程](https://www.figma.com/design/EyQtDtILGDZDf6neLBL6vs?node-id=15-6)。
- 状态：用户已确认，待设计修改及后续实施。
- 确认依据：用户提出月历展开、三类色块、平铺头像筛选、位置展示；助手复述后用户回复“准确，你评估一下合理性和价值，还有没有我没考虑到的地方”。

### 已确认修改

1. 当前紧凑日历可向下拖动展开整月视图，在页面内展开并支持收起，不跳转新页面。
2. 训练为蓝色，比赛为红色，其他活动为绿色；日历事件以带名称的清晰色块呈现，不仅使用小圆点。下方日程卡片沿用相同颜色规则。
3. 顶部平铺“全部”以及孩子头像、姓名，点击选择并显示当前选择；支持看所有绑定孩子的合并日程或其中一个孩子，不用下拉菜单。筛选同时作用于日历和下方列表。
4. 日程安排区域保留现有信息，增加场地名称和必要的地址信息。

### 与既有需求衔接

- 颜色按 REQ-SCH-001 的业务分类决定：占用训练课时的友谊赛归训练、显示蓝色；独立比赛显示红色；课堂测评不改变训练分类。
- 查看范围仍限于家长绑定孩子；“全部”不扩大数据权限。
- REQ-SCH-003 已要求取消、改期、换场地可查最终安排和变更历史；新视觉需承接该规则。具体状态表现见 P02-02 已确认补充。

### 价值评估（方案判断，不是界面实测）

值得实施。整月展开有助于提前安排家庭时间，紧凑状态保留日常查看效率；固定类型色块有助于扫读；平铺孩子筛选减少切换步骤；列表直接展示地点有助于安排接送。月历交互与多孩事件合并需要处理信息密度和事件身份，单纯增加颜色或头像不能完成该流程。

现有活动类型、起止时间、场地标识及家长孩子绑定可复用。月历应查询当前可见日期范围，不能把未加载日期当作没有安排；场地后台持久化仍属既有待补能力。未改 Figma、未实现或实测交互，不宣称已经证明使用效率提升。

## P02-02 · 日程交互与多孩展示补充

- 确认日期：2026-09-22。
- 状态：用户已确认，纳入 P02 后续设计与实施计划。
- 确认依据：助手提出六项补充并询问是否采纳，用户回复“可以，采纳你的思考”。本次仅确认该轮向用户说明的六项，不扩大到 P01 的待确认建议。

### 已确认补充

1. **多孩活动归属与合并。** “全部”视图通过孩子姓名或头像区分归属，事件颜色仅表示类型。两个孩子参加同一活动时合并为一条并标出两人，各自请假状态分别显示。以活动身份识别同一活动，不能仅凭时间相同合并。
2. **月历内容溢出。** 单日展示有限条可读色块，超出显示“另有 N 项”；点击日期，在下方查看完整列表，避免日期格子过高。具体条数随布局验证确定。
3. **展开操作与日期保持。** 日历提供可点击的展开把手，同时支持下拉展开，避免与页面下拉刷新冲突。展开、收起和切换孩子时保持当前选中日期，提供“回到今天”。
4. **事件类型与状态分开。** 保留训练蓝、比赛红、其他绿及类型文字；取消、改期、换场地有明确文字标签，比赛红色不代表异常。占用训练课时的友谊赛仍按训练显示蓝色，独立比赛显示红色；承接既有变更追溯与最终安排规则。
5. **位置与导航。** 日程展示场馆及必要的具体场区/球场；有有效坐标时提供导航，地点未确定显示“地点待定”。不伪造坐标；具体导航入口样式在设计时确定。
6. **时间重叠提示。** 同一孩子活动重叠时提示冲突；不同孩子同时有活动时提示时间重叠，方便家长安排接送，不认定为数据错误。提示不阻止安排、不自动修改活动。

### 其他工程评估（非本次新增业务确认）

原评估还提出区分无安排、加载中和加载失败，以及当前可见日期范围的加载与日历/列表筛选一致性；作为既有通用状态要求的实施检查保留。切换月份入口等未在本轮六项中单独确认的交互细节，仍在后续设计时核对，不扩大本次确认范围。

## P08-01 · 单孩成长档案与可下钻的能力雷达图

- 提出及澄清日期：2026-09-22。
- 页面：[P08 成长](https://www.figma.com/design/EyQtDtILGDZDf6neLBL6vs?node-id=15-30)。
- 状态：以下用户明确要求及澄清已记录，待设计修改及后续实施。
- 依据：用户提出成长页布局；随后纠正孩子选择必须与首页一样、只展示一个人的信息，并明确“点击某项看构成”使用下一级雷达图、配具体数值。助手此前关于日程式头像排列选择的理解作废。

### 已明确修改

1. **单个孩子。** 顶部右上角展示当前孩子头像，点击切换孩子，方式沿用首页。整页始终只展示一个孩子的信息，不设“全部”，不合并或叠加多个孩子的数据；切换后整页同步更新。
2. **可选指标的能力雷达图。** 顶部信息下方为雷达图，复用后台指标、模型及构成关系，支持选择不同指标进行展示，不将能力维度写死。
3. **下一级雷达图与数值。** 查看整体能力后，点击某一项能力，以其组成指标形成下一级雷达图，并展示各组成指标的具体数值。层级和构成以后台定义为依据，不虚构固定的指标分类。
4. **测评趋势。** 雷达图下方为测试数据趋势板块，可查看雷达图上相应指标在时间段内的变化。
5. **关联训练统计。** 点击趋势中的相应指标，可查看与该指标相关的训练次数统计；来源沿用课堂统计，不以此替代能力测评结果。
6. **评价与事实记录。** 最底部是教练评价和测评记录。测评记录明确哪一天、做了什么测试、成绩多少；教练评价作为独立内容展示。

### 与既有需求衔接

- 家长只查看已确认的测评结果；测评日期沿用所关联课程的业务日期，原始成绩保留单位，分值和等级沿用已配置映射规则。
- 关联训练统计来自课堂数据；不将训练次数与测评变化的同时展示解释为已经证明因果关系。
- 复用既有后台指标图、模型、展示组织和来源关系；本次记录不代表可下钻雷达图及趋势联动已经实现。

### 展示契约进展

分值与原始成绩分工、下钻返回、少量指标展示、日期与缺测、趋势联动已在 P08-02 获确认。具体尺度转换配置、默认指标组合、当前值取值时点、默认时间范围、版本可比判定、训练关联维护和去重细则仍需在后续设计与工程规格中落实，不据此虚构正式参数。

## P08-02 · 成长页可读性与数据解释优化

- 确认日期：2026-09-22。
- 状态：用户已认可，纳入成长页后续修改计划；未改图或代码。
- 确认依据：助手评估 P08 方案并提出六项优化、标明建议优先落实的四项后，用户回复“好的”。本次确认限于成长页，不改变 P01 待确认建议的状态。

### 已确认优化

1. **默认整体能力视图。** 打开页面直接呈现后台维护的默认指标组合，无需家长先配置；需要时再切换或调整指标，保留后台配置能力与家长选择能力。
2. **分值与原始成绩分工。** 雷达图使用后台映射后的可比分值；旁边展示原始成绩及单位、整数分值和已配置等级。不同满分须明确统一展示尺度，不能由前端随意换算，更不能让秒、米、次数直接共用同一刻度。具体尺度配置仍待落实。
3. **下钻路径与少量指标。** 显示“整体能力 › 某项能力”等当前位置并可返回上级；组成指标配名称和数值，名称也可点击进入，不依赖点准图形节点。没有下级时查看具体成绩；仅一两个组成指标时使用数值列表或条形展示，不虚构维度凑雷达图。列表与条形的具体选择留待设计。
4. **日期、缺测与可比性。** 各项目说明测评日期，不将来自不同课程的成绩呈现为同一天测出；未测不填零。规则版本变化导致不可直接比较时明确说明，避免把口径变化表现为真实进步或下降。
5. **单项趋势与训练联动。** 趋势默认聚焦一项，以指标切换入口查看其他项；点击雷达图某项后定位对应趋势，不默认叠加全部指标曲线。进入相关训练统计时保持同一孩子、指标和时间范围，可查次数对应的课堂记录；不将同时展示理解为已证明因果关系。
6. **评价与测评记录分层展示。** 底部先展示最新教练评价和近期测评，完整历史按需展开。评价显示作者与日期；测评记录展示所关联课程日期、项目、原始成绩和单位，沿用既有已确认结果可见规则。

### 实施优先建议

优先落实第1、2、4、5项：默认整体视图、分值与原始成绩分工、时间与缺测说明、单项趋势联动。第3、6项同样属于已认可优化，不因优先顺序而移出计划。

复用现有后台指标图、模型和测评事实，重点补齐取值时点、展示关系、版本可比性及训练关联的契约；本记录不代表上述数据能力已全部接通，也不新增独立实施任务。
