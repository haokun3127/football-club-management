# 待决项与实施顺序

未决项只影响相关分支。下列候选用于画面表达与工程拆分，不替用户作业务决定；具体定义以权威 [05](../product-requirements/05-decisions-and-sources.md) 为准。

## 1. 决策登记
| 待决 | 设计候选/处理 | 确认前限制 |
| --- | --- | --- |
| O-01 单课临时变更生效 | 显示影响范围及历史；候选为直接生效并通知俱乐部 | 不把请假/课次修正套入审批；单课变更生效策略可配置但不默认上线 |
| O-02 日期、名单、参与率 | 明确俱乐部时区、当次名单和系统默认来源 | 不追补全部历史；参与率分母待确认 |
| O-03 当前范围已关闭 | 后台扣课/课包能力保留，家长教练前台不展示 | 培训计次及前台旧请求不触发扣账，未来启用另行定义 |
| O-04 具体阈值、年龄、标准 | 三层结果及两段区间映射结构已定，整数分值；后台维护 | 正式区间/等级表/适用条件仍需输入，不用演示值冒充标准 |
| O-05 客户导入模板/来源责任 | 标准模板+映射预览+来源字段 | 未拿到样表只做通用流程，不宣称任意文件自动识别 |
| O-06 测评边界 | 明确整个人不测评；必测项齐全才处理完成 | 单项豁免、名单调整/重开等具体规则确认后启用 |
| O-07 导航 | 家长首页/日程/成长/我的；教练日程/测评/队伍/我的 | 保留旧路由映射，导航方案可调整 |
| O-08 跨队评价范围 | 当前学员评价保留队伍上下文和作者 | 不默认全俱乐部教练互改所有评价 |
| O-09 实际执教 | 区分排课安排和实际执教事实 | 不从点名、登录或排课自动算薪酬/执教次数 |
| O-10 比赛统计/查看范围 | 战术已定自由拖放，不选阵型、不固定人数；技术统计仍待决 | 不从布局推导出场事实，不强制逐事件记录 |
| O-11 照片、里程碑等细则 | 普通照片、预制模板、公开字段白名单；入训天数未知不造数 | 未获准照片不公开，累计规则待确认 |
| O-12 通知 | 页面展示变更与站内记录，渠道状态分开 | 不把发起当送达/已读，不承诺平台通知必达 |
| O-13 专业服务细则 | 人工沟通、分派、承接、简洁计划交付 | 不默认跨俱乐部/外部人员权限或支付结算 |
| O-14 改期、补课计次 | 保留原课与新课关联及变更历史 | 不直接复制课次导致重复计数 |
| O-15 内容时长/重叠 | 显示配置时长、分类及明细来源 | 不把多标签重复相加解释为真实运动总时长 |

字段白名单、真实容量、备份保留期、环境域名及上线窗口另由实施/运维阶段取得依据。当前不要求用户为了启动设计一次性回答全部问题。

2026-09-20 的数据契约、简单并发、自由战术板及后台维护细项以 [16号规格](16-confirmed-rules-and-engineering-spec.md) 为准。本轮不新建实施任务。

## 2. 实施分期及完成证据
| 阶段 | 工作 | 前置 | 完成证据 |
| --- | --- | --- | --- |
| 0 隔离与基线 | 环境拆分、合成数据、现有测试基线、只读部署盘点 | 无；可立即开工 | 开发/体验不落生产；版本/DB/配置清单；现有用例结果 |
| 1 领域契约 | 人员/名单/时区/修订、课次与财务拆分、类型化测评/真实日期、权限白名单 | O-02核心边界；已确认部分先做 | 领域状态与反例测试、候选接口评审、迁移副本对账 |
| 2 课次闭环 | 日期任务、请假、双方修正、冲突与历史、新旧BFF兼容 | 阶段1 | 重试不重计，人工不覆盖，家长越权拒绝，取消/补假一致 |
| 3 测评闭环 | 分批采集、真实课程、补录、不测评、个人确认/修订、模型/标准版本 | 阶段1；O-04只阻塞评分发布 | 单位与日期正确；旧发布保留；跨人引用拒绝；按人完成 |
| 4 小程序升级 | 首页/导航/成长/日程/教练工作流，旧深链兼容，离线与真机适配 | 阶段2/3接口稳定 | 关键流程渲染交互验收、设备矩阵、无旧逐堂确认残留 |
| 5 后台四模块 | 先账号范围和基础数据，再导入、模型、服务、BI | 服务层与权限稳定 | 管理界面与小程序共享事实；导出一致；模板映射可重试 |
| 6 灰度发布 | 副本迁移、备份恢复、压测、认证实机、固定镜像与灰度 | 所有依赖业务规则/上线门禁 | 独立发布记录、回退演练、观测与用户验收 |

每阶段继续使用现有 Trellis 任务/子任务习惯；不与需求整理任务混写。实施包按 domain / api / miniprogram / admin / ops 拆责任。当前任务只完成设计与准备，未擅自开始生产代码改写。

## 3. 后台技术候选
建议新增独立 TypeScript Web 客户端，React + Vite 可作为评估候选，与现有 pnpm workspace 共用领域契约和客户端类型；确切组件库与版本在实施启动时核对，不因为 Figma 使用了通用控件就默认为某库。

关键取舍是维护单一业务服务与权限、稳定表单/表格、可访问性、部署隔离和测试能力；不需要为了后台改写现有原生小程序。后台服务端渲染/复杂微前端不是当前需求的必要条件。

## 4. 验收组织
原62条 ACC 保持编号并更新预期，新增ACC-63—69。实施任务直接引用权威 04-acceptance.md 中的69条场景；不另编一套口径。每条关键验收记录角色、前置数据、步骤、响应、UI状态、持久化和权限反例。自动化测试覆盖状态与安全不变量；视觉与真机检查覆盖排版、触达和微信平台行为。

本次不为静态文档/画板编写镜像式单元测试。检查重点是需求覆盖、路由映射、节点与原型、文本溢出和真实外部限制。
