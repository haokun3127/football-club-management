# 后台用户确认的设计修改计划

本文件记录后台评审中用户明确确认的修改要求。与17号前端修改计划关联；补充建议与已确认范围分开。记录不等于已修改 Figma 或实现代码，本次未创建 Trellis 任务。

## D01-01 · 工作台功能分区与模块库配置

- 提出及确认日期：2026-09-22。
- 页面：[D01 工作台](https://www.figma.com/design/EyQtDtILGDZDf6neLBL6vs?node-id=18-2)。
- 状态：用户已确认产品方向，待设计修改及后续实施。
- 确认依据：用户要求工作台有清晰功能分区、每个分区能自定义模块；助手询问“从系统提供的模块库里自由选择、排列和配置”或“管理员自行创建新的统计卡片、图表和计算指标”，用户回复“好的，用第一种”。该回复确认模块库配置方案，不自动视为框架选型确认。

### 已确认修改

1. 工作台页面具有清晰的功能分区。
2. 每个分区支持从系统提供的模块库中选择模块、调整排列并配置模块。
3. 第一版采用预制模块库方案，不包含管理员自行创建新统计卡片、图表或计算指标的设计器。

### 实现建议及待细化事项（不自动并入已确认范围）

- 候选分区：今日工作、数据管理、评测与模型、运营分析、专业服务；最终名称、数量与模块清单待逐项评审。
- 每区提供添加模块与编辑布局入口；支持模块增删、调整顺序和大小。拖拽、尺寸档位、跨区移动及分区本身能否调整仍待细化。
- 按模块提供实际支持的队伍、日期等筛选条件。
- 提供角色默认布局、个人保存及恢复默认；布局生效范围、保存方式与默认模板维护者待细化。

### 与既有需求衔接

- 关联 REQ-ADM-001 工作台与业务入口、REQ-ADM-002 权限及俱乐部配置、REQ-BI-001 简单分析呈现。
- 模块及数据遵循既有俱乐部、角色和对象权限；界面配置不能扩大授权，接口独立校验。
- 点击事项进入同一业务对象，复用既有记录、指标口径和状态，不新增独立事实台账。
- 请假直接生效、正常训练计次不生成点名确认待办等已确认规则继续适用。
- 工作台模块配置不扩大为 BI 数据集、公式或图表设计器。

## DAT-01 · 分类、多用户与多业务数据表管理

- 提出及确认日期：2026-09-22。
- 范围：数据管理模块整体，涉及多个页面；不绑定某一个详情页。
- 状态：用户已确认，待信息架构设计、改图及后续实施。
- 确认依据：用户要求分类下以详情表维护数据，支持整表导入导出及单条编辑，按标准多用户、多数据表后台模块设计；明确学员基础信息、场地信息、教练排课安排仅为举例。助手复述分类、表格、导入导出、多用户协作四方面，并标出配套建议后询问理解是否准确，用户回复“对”。

### 已确认修改

1. 数据管理采用“大类 → 对应业务数据表 → 单条记录详情”的组织方式，具有清晰分类和完整维护能力。
2. 各业务数据表支持列表、搜索、筛选、分页、查看记录详情和单条编辑；有关联的数据支持相互跳转，沿用同一业务对象。
3. 提供整张业务数据表的批量导入、导出，并保留逐条维护能力。导入包含字段对应、数据校验和错误反馈；已有记录的更新规则及可导出范围须明确。
4. 按多用户协作设计：不同账号按权限查看、编辑和导出；多人修改同一条记录时提示冲突，保留修改人、修改时间和操作历史。
5. 第2至4项中的搜索筛选、关联跳转、导入校验和修改冲突处理，是经本次复述确认的配套设计方向；具体交互及参数仍需细化。

### 分类示例及未定细则

- 学员基础信息、场地信息、教练排课安排仅用于说明分类概念，不作为正式分类名称、层级或必设菜单。
- 正式分类、分类下的数据表清单、字段及关联关系须结合全部业务设计后评审。
- 整表导入导出指所选业务表的批量数据处理，受权限约束；本次不推导为全库备份恢复、全表覆盖或导入即删除旧数据。
- 各表的必填字段、唯一标识、关联校验、重复处理、空值处理、更新策略、导出字段和范围，以及单条编辑采用抽屉还是独立页面，仍待细化。
- 多数据表管理不自动包含管理员任意建表、自由创建字段、公式或业务流程的低代码设计器。

### 与既有需求衔接

- 关联 REQ-DAT-001 基础资料维护、REQ-DAT-002 日常业务维护与记录查询、REQ-DAT-003 导入导出、REQ-DAT-004 数据质量与历史、REQ-ADM-002 账号权限。
- 复用既有身份、业务服务、事实和权限；业务表视图不要求一比一暴露数据库物理表。
- 既有导入预览确认、逐行结果和重试、敏感导出独立授权、俱乐部隔离及保存后可回读规则继续适用。
- 测评发布、训练记录修正和专业服务分别遵循其既有业务规则；统一表格体验不统一覆盖这些不同规则。
- 当前只记录评审结论，未改动 Figma 或业务代码。
