# 01 产品目标与小程序需求

版本、状态和使用方式见[文档入口](README.md)。数据对象、统计和权限统一见 [03](03-data-and-permissions.md)，未定项见 [05](05-decisions-and-sources.md)。

## 1. 背景与目标

客户已有培训机构的基本运营流程，但日程沟通、过程记录和成长分析缺乏统一的数字化支撑。产品应减少重复沟通及录入，使日常业务持续产生可信数据。

### REQ-GOAL-001 培训过程协作

**状态：C。** 让俱乐部、教练、家长围绕时间地点、训练内容、请假、出勤和训练统计共享信息。线下讨论仍是有效协作方式，系统不强制把所有沟通和争议处理搬到线上。

### REQ-GOAL-002 学员成长与专业数据资产

**状态：C；设备与 AI 服务为 E。** 以日常训练、测评及评价历史构建成长档案；项目和模型应持续扩展，支撑专业分析和培养。

演进方向包括可穿戴身体指标、天气/日照/湿度等环境数据、多来源分析、AI 辅助、个性化计划、专项教练匹配，以及设备与专业服务收入。保留来源、时间、单位、版本和数据关系，不据此默认交付所有设备连接和自动决策功能。

## 2. 产品组成与交付边界

| 使用端 | 主要任务 |
| --- | --- |
| 家长端 | 看孩子安排和成长、请假、查看训练事实、咨询专业服务、分享成长内容 |
| 教练端 | 看日程与待办、主教练准备课程、处理销课例外和测评、维护学员评价 |
| 俱乐部后台 | 数据管理、评测与模型、BI、专业服务及必要的权限与内容配置 |

明确排除的自动推导：销课记录自动形成收费或财务结算、个人评价自动计入能力分、将未测视为零分、球探临时参训自动转正式成员、普通教练自动获得主教练编辑权、将“增值服务”自动扩展为交易市场。训练日期过后的默认销课属于已确认需求。

人物抠图、自动换球衣等复杂图像生成不纳入已确定的分享方案。完整财务结算、线上支付、复杂赛事平台、自动撮合和设备实时接入没有因本次讨论自动成为交付要求。

### 术语约定

| 术语 | 本文含义 |
| --- | --- |
| 原子训练内容 | 库中可选择的细粒度训练内容，带时长；不等于一次完整训练课 |
| 一堂训练课 | 有时间、地点、队伍的单次训练活动，可包含多个原子内容 |
| 课程模板 | 可复用的内容组合；应用模板不等于新增或修改日程 |
| 学期训练安排 | 俱乐部维护的一段时期内的课表，与主教练填写的单课内容分开 |
| 测评项目 | 一项有明确采集定义的数据项目，原始值可为计时、次数或评分量表 |
| 测评任务 | 为指定对象、周期和项目组织的一次采集工作，可跨多堂训练课完成 |
| 评分模型 | 根据项目或其他模型输出计算结果的规则及适用条件 |
| 培养标准 | 教学方指定的适用目标值或区间，不等于当前样本平均成绩 |
| 确认同步 | 将已核对的结果版本提供给获准家长查看，与自动保存草稿分开 |
| 简化销课 | 日期过后默认计入该堂训练的课次记录，请假排除，家长与教练可直接修正；不等于真实金钱扣款或财务结算 |
| 专业服务 | 俱乐部围绕培养和专业资源开展的工作或增值项目，不默认涉及付费交易 |

## 3. 角色和基本资料

### REQ-ORG-001 学员与家长资料

**状态：C。** 俱乐部维护学员和家长的详细个人信息，能够承接保险、监护关系、紧急联系人等用途。教练仅查看教学所需字段；家长查看获准部分，无编辑权限。具体字段白名单见 03，尚未决定的字段不默认向教练开放。

资料更正可由家长线下联系俱乐部处理。原始材料中的教练新建、任意编辑学员不能继承为权限。

### REQ-ORG-002 队伍与教练配置

**状态：C。** 队名、队徽、成员及主教练、主力教练、守门员教练等配置由俱乐部维护；教练、家长无队伍主档编辑权。业务角色名称与系统动作权限分别表达。

同队只有主教练编辑训练安排中的授权内容；获授权的同队教练可协同出勤、测评和评价。资料访问、课程编排、测评项目管理不是同一权限。

### REQ-ORG-003 球探库与临时参训

**状态：C：独立球探库及参训记录；2026-10-05 用户委托总控按简单操作、自动留痕、减少审批原则定稿名单细则。** 俱乐部维护球探库，教练从获准名单选择临时参训人员，俱乐部掌握资料及参与数据。

本场有执行权限的主教练、助教和协作教练均可直接维护临时名单，无额外审批；复用同一人员标识，防止同课重复加入。课后补加只选择参加/未参加，与名单一并保存。已有业务事实保留并通过原更正流程修正，不通过移除名单删除；系统自动留操作者、时间、前后状态，备注选填。临时测评由有本课测评权限的教练明确勾选，不额外审批；已有任务名单不随活动名单静默变化。临时参训不改变长期队伍归属、不自动绑定家长或课包，也不自动加入已有评测必测名单。转正式学员时衔接历史，不复制成无关联人员。

## 4. 日程、训练与活动

### REQ-SCH-001 三类日历

**状态：C。** 顶层固定为训练、比赛、其他。

| 场景 | 顶层分类 | 操作归属 |
| --- | --- | --- |
| 正常训练 | 训练 | 俱乐部排课，主教练编排内容 |
| 使用训练课时开展的友谊赛 | 训练 | 作为训练子类型/内容，沿用训练权限与参与记录 |
| 独立比赛、少量队伍比赛、商业赛事 | 比赛 | 俱乐部后台创建，具体类别在比赛内区分 |
| 参观、观赛及其他集体活动 | 其他 | 俱乐部安排，按活动记录参与 |

友谊赛在俱乐部课时业务上属于训练，适用同样的日期过后默认销课、请假不销及双方修正规则。独立比赛和其他活动不因出现在日历中自动套用训练销课。测评任务是附着于训练的工作，不因课堂进行测评而改变日历类别。

### REQ-SCH-002 学期基础安排

**状态：C。** 俱乐部和教练线下沟通确定训练计划，后台维护学期时间、地点及队伍安排。小程序无整体学期计划调整权限。查看范围按授权队伍和家长绑定孩子确定。

重复排课、批量维护及冲突提示为 **P**：提高管理效率，冲突提示不自动改动课程或代替管理员决定。

### REQ-SCH-003 单次临时变更

**状态：C：需要取消/改期等例外处理；O：审批模式，见 O-01。** 暴雨等原因导致单堂课取消、改期、换地点时，主教练应能在日程中发起变更，家长能够看到最终安排，俱乐部能够获知和追溯。

建议采用操作生效并通知俱乐部的轻量方式；若选择审批模式，需明确待审批展示及实际生效时点。该模式尚未最终确认，不得同时实现相互矛盾的状态。

保留变更前后信息、原因、操作人和时间。取消不计缺席或训练积累；改期关联原课程，避免重复统计。补课是否属于原课程改期或新课见 O-14。

### REQ-TRN-001 原子训练内容库

**状态：C。** 库中每个训练内容有对应时长，俱乐部维护。主教练通过分类、搜索或标签选择内容组成一堂训练课；可选择同一分类下的多个内容，并能取消选择。

同一内容能否在同课重复编排、时长是否可覆盖属于 O-15，未定前不假设内容次数等于动作重复次数。

### REQ-TRN-002 课程模板与复制

**状态：C：个人及公共模板、复制；P：应用细则。** 主教练可以将课程内容保存为个人模板，俱乐部提供公共模板，可复制到未来一定时期的已有课程。

建议复制前展示目标课程及已有内容，明确替换或跳过；不得静默覆盖。应用模板保存当次内容和时长，修改模板不直接修改历史课程。复制内容不生成新日程，不改变时间、地点和队伍主档。

### REQ-TRN-003 选择、保存和统计来源

**状态：C。** 勾选、取消、数量与摘要保持一致；保存成功后页面回显，返回及重新进入读取同一结果。保存失败保留待提交内容，不显示成功。

不另填实际完成内容，也不做计划与实际的逐项比对。训练统计建议以当前有效销课结果与课程内容关联，系统默认结果及人工修正的来源均可追查；家长或教练修正后同步更新相关统计。不另要求教练确认一套出勤表。记录反映日常业务约定，不能宣称系统实测或双方逐条点击确认了每项动作的实际完成。

## 5. 自动销课、请假与共同修正

### REQ-ATT-001 请假直接生效

**状态：C（2026-09-18 最新澄清）。** 家长针对自己孩子的训练提交请假后，该学员不销课，无需教练同意或俱乐部审批。相关课程、队伍、学员详情能够查看有效请假和课次结果。

家长和教练可以在线下沟通确认事实，再直接修改线上记录。已销课后补记请假或改为不销课，应更新该堂课的结果并留痕；已请假但实际参加，也可直接改回销课。没有待批准、同意或驳回的请假审批链，不要求另一方再次确认。

### REQ-ATT-002 课程结束后自动记录与双方修改

**状态：C。** 依据 2026-09-22 教练评审 C03-01 的进一步明确，课程结束后（按课程结束时刻），系统按该堂课应参与名单自动生成默认训练记录；已有效请假的学员不销课。教练不必打开课程、点名或整班确认，家长也不必逐堂确认。已取消课程不销课。

家长可修改自己孩子的结果，授权教练可修改自己教学范围内的结果；修改成功即生效，不经过审批。双方看到同一份当前有效结果与修改历史，用于反映共同认可的培训事实。系统不设置双人逐条确认流程，也不将默认结果伪称为双方已签认。

每次成功生成或修改均记录操作者/系统来源、时间、修改前后值；撤回、补记和恢复同样留痕。可补充原因，是否有必填原因属 P，建议避免增加不必要输入。未成功保存不能显示修改已生效。

**C：简单并发保护（2026-09-20 再确认）；P：其余可靠性实现细则。** 自动处理重试不重复销课，不覆盖家长或教练已经明确修正的结果；并发更正识别冲突，核对当前值后保存即可，不增加业务审批。课程结束时刻按 C03-01 执行；迟到早退、临时参训的课次含义等剩余细节见 O-02。

### REQ-ATT-003 课次记录与财务边界

**状态：C。** 这里的销课是培训过程的课次记录，可自动产生并由家长、教练共同修正，不涉及真实金额扣款、退款或财务结算。

俱乐部后台的扣课、课包余额及历史数据能力保留，供以后升级使用。当前家长端和教练端不展示余额、扣减明细、余额提醒或扣课操作入口；培训课次及修正历史仍正常展示。后台授权维护与培训计次分开，自动计次、请假和双方修正不自动触发课包扣减或财务记账。O-03 当前展示与联动边界已关闭，未来重新启用另行定义。

## 6. 每名学员的教练评价

### REQ-EVA-001 当前评价和历史

**状态：C。** 在队伍管理中维护每名学员在该队伍的一份当前评价，提供内置语句供教练点选，可以按需更新；有变化才形成历史。家长能看到最新评价及时间线中的变化。

无需每堂课、每个训练内容评价；未更新不生成逾期任务。评价用于沟通，不默认进入能力综合分。

评价允许授权同队教练协作，记录修改人和时间。09-22 R06 已明确补充文字可选；遵循“有变化才形成历史”，无变化保存不新增节点。2026-10-05 用户确认 O-08：同一学员每个队伍独立一份，家长按队查看当前评价与历史，不覆盖其他队评价。

## 7. 测评任务与录入

### REQ-ASM-001 创建与下发

**状态：C。** 俱乐部创建任务、选择库内项目及周期，下发一个或多个队伍。周期可为周、月、学期等。教练也可自建测评任务，项目仅从库中选择，数据同步俱乐部。

“教练自定义”指任务组合，不包含小程序新建测评项目或改评分标准。基础、高级等通过项目标签筛选，无需建立两套独立测评系统。

### REQ-ASM-002 分批执行和课程归属

**状态：C。** 任务在相关课程中可见，支持分学员、分项目、分训练课完成。教练选择哪节有效训练课录入，该条成绩就归属哪节课。从课程进入时预选该课，从任务进入时选择课程；不因录入或确认日期变化自动改挂课程。所选课程仍须满足测评周期、对象范围及授权要求。

可在周期后录入，不因到期锁死任务；以所选课程的日期作为成绩发生日期依据，另存录入时间和确认时间，不要求教练重复填写测评日期。一个任务可以关联多堂课，不强制全队同一课测完。重复显示在各课时仍是同一个任务，不能累加为多个待办。

关联课程被取消、改期到周期外，或周期内没有可用课程时的处置见 O-06，不能随意挂到不真实的课程上。

### REQ-ASM-003 完成条件与不测评

**状态：C。** 对任务中的全部学员，要求项目都已有效填写，或学员已明确标记不测评，任务才能自动完成。缺席不能自动免测，也不能缩小任务名单。

不测评独立标识，不生成零分、不算获得成绩，不覆盖该学员已有有效能力结果。其标签及原因可配置；学员部分项目确实不测的处理粒度见 O-06。

任务下发时保存名单与必测要求为 **P**；人员变更时不静默改变已下发任务，显式调整保留原因。

### REQ-ASM-004 保存与确认同步

**状态：C（已接受的交互设计）。** 支持按学员或项目录入、批量选择关联课程并修正例外、自动保存草稿和恢复；界面明确保存中、已保存、失败。

已准备好的个人结果可以核对后确认并同步，家长仅见已确认版本，不等待全队完成，不增加俱乐部审核。

数据采集完成和结果同步是两条状态：任务全部填完但有结果未确认时，仍提供待同步入口。确认失败可重试，不能产生重复结果或重复成长节点。

### REQ-ASM-005 更正和历史

**状态：C。** 已确认结果可更正，编辑先成为修订草稿；旧确认结果在新版本确认前继续展示。新版本保留修订人、时间和可追溯来源，不能把原始历史覆盖删除。

### REQ-ASM-006 项目、结果与模型

**状态：C（2026-09-20 明确）。** 每项测评有三个相互关联的项目/结果定义：①原始成绩，按项目保留秒数、次数、距离或量表值及单位；②分值，按原始成绩所属区间映射得到整数，不带小数位；③评价，按整数分值所属区间映射为 S、A+、A 等等级。两段映射由后台获授权人员维护，教练只录原始成绩，不重复填写三份独立结果。

原始成绩可按项目精度保留小数；“不要小数位”约束第二层分值。分值是区间配置的整数，不是把原始值四舍五入后当分数。保存三层关联、两段规则版本及来源，家长查看已确认的三层结果。等级名称和阈值由后台配置，不在代码写死完整等级表或默认 0—100 分。模型可扩展且输出可继续作为输入，具体管理见 REQ-MOD-001 至 REQ-MOD-004。

规则未配置、区间未命中或模型输入不齐时说明原因并保留已有原始/单项结果，不把缺测填零，不把原始值隐式当分数，也不凭空给等级。缺失输入下是否允许模型计算必须由模型规则明确，不临时改变权重。

## 8. 教练端页面和工作流

### REQ-COA-001 工作首页

**状态：C：工作导向、日程结合任务；P：具体排序。** 首页以今日/所选日期安排为核心，同时显示需要处理的工作。

建议顺序：当日课程及已请假人数 → 需要关注的变更/例外 → 测评等未完成工作。课程卡展示时间、地点、队伍、类型及下一步操作，主教练看到内容待准备，其他教练不出现无权限编辑任务。请假和销课不产生逐条审批或整班点名待办；自动处理失败属于系统异常，不能转化为教练的日常必填任务。

任务按真实业务聚合；不因未更新评价、未上传照片或视频制造工作缺口。课程取消后相关待办同步处理，具体保留规则随业务状态确定。

### REQ-COA-002 队伍和学员详情

## 9. 家长端页面和成长

### REQ-PAR-001 首页结构

**状态：C。** 从上到下为：个人球员卡/成长里程碑等滑动切换区域、俱乐部新闻 Banner、四个功能快捷入口。

默认快捷入口为请假、训练记录、测评结果、私教咨询；用户从获准功能目录中选择、排序，仍保持四个。新增功能不要求增加首页图标数量。首次默认、恢复默认和权限失效替换为 **P**，不允许保存无效功能。

顶部以手动滑动为建议；卡片显示真实身份和成长信息。不同孩子切换时照片、队伍、统计、分数及操作对象一起切换。缺图、未测、无训练数据采用真实空态。

### REQ-PAR-002 安排、请假与事实查询

**状态：C。** 家长查看孩子训练、比赛、其他活动，时间地点、内容和变更清楚可见；从课程或快捷入口提交请假，查看生效状态、销课结果及训练统计。家长可直接修正自己孩子的销课结果并查看历史，无需教练审批，不获得课程安排或主档编辑权。

重要取消/改期独立提示，不依赖新闻轮播。外部主动通知渠道和送达能力见 O-12，页面内最终安排应始终可查。移除原首页指定待处理横条的材料诉求不等于移除必要通知。

### REQ-PAR-003 完整个人成长

**状态：C。** 成长页面包含训练累计与内容分布、最新已确认测评与历史、原始值及分项说明、当前评价与变化、成长时间线。

能力图按实际模型组织，不限定五维、六维或八维。雷达、能力条、总分及详情取同一确认结果；维度较多或数据不足时采用适合的列表/图表，不能填充假值凑图。

时间线包含重要训练积累、测评、评价变化和里程碑。普通训练记录按周聚合为 **P**，仍能展开课程明细。历史更正更新原事件对应记录，不伪装成新的一次训练或测评。

### REQ-PAR-004 培养标准对照

**状态：C。** 优先呈现个人成长，对照适用年龄段、普通队或精英队应达到的标准，不比较具体个人、不做学员排名。

标准由教学人员提供，注明适用范围与版本；统计均值不能直接命名为应达标准。无标准时仅展示个人历史，不虚构目标。年龄变化或模型变化影响可比性时解释变化。

### REQ-PAR-005 预制分享与里程碑

**状态：C：预制模板方案；P/O-11：具体模板和授权字段。** 用预制背景、普通照片和真实数据形成球员卡、里程碑或成长分享内容。不做人物抠图、自动换球衣；不展示其他孩子信息或个人敏感字段。

### REQ-PAR-006 专业服务咨询

**状态：C：私教咨询入口及专业服务方向；P：具体表单。** 家长从入口查看适用服务并表达需求，俱乐部负责跟进。建议记录孩子、需求方向、简要说明和时间偏好，已有资料自动关联，避免重新填写详细档案。

咨询提交不等于已购买、已匹配或已排课。服务流程与边界见后台专业服务要求。

## 10. 共同体验与业务完整性

**状态：P（开发评审建议）。** 涉及保存的操作必须区别编辑态、保存中、成功和失败；失败可恢复，重复提交不重复生成业务事实。多人协作发生冲突时显示并要求核对，不静默覆盖。
