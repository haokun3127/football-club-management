# 03 数据口径、权限与状态规则

本文是产品层的业务约束，不规定数据库表结构或接口路径。需求状态承接 [01](01-product-and-miniprogram.md)、[02](02-backoffice.md)；新增的具体实现口径标为 P，待决编号见 [05](05-decisions-and-sources.md)。

## 1. 业务对象与关系

以下字段组是 **P：概念数据要求**，用于检查信息是否完整，不代表所有字段必填或已获准采集。

| 对象 | 主要信息 | 必须表达的关系或区别 |
| --- | --- | --- |
| 人员身份 | 稳定标识、姓名、获准身份资料 | 同名不同人；正式学员、球探对象不是两份无关联成长历史 |
| 学员档案 | 足球资料、入训日期、状态、运营资料 | 俱乐部归属与个人身份、当前状态与历史记录分开 |
| 联系人 | 联系方式、关系、紧急/主要联系人标记 | 一个孩子多个联系人，一个联系人多个孩子；账号与联系人分开 |
| 教练/专业人员档案 | 任职、专长、适用范围、状态 | 职业角色、队伍授权、服务责任分开 |
| 队伍及成员关系 | 队名队徽、学期、人员、角色、关系有效时间 | 当前名单与历史参与名单分开 |
| 日程活动 | 类型、队伍、开始结束时间、场地、状态、变更 | 训练/比赛/其他；原安排、改期、取消可追溯 |
| 原子训练内容 | 名称、分类、说明、时长、版本或修订历史 | 标准内容与当堂选中内容分开 |
| 课程模板 | 所有者、内容顺序、版本/修订 | 公共模板与个人模板；模板与应用结果分开 |
| 课程内容 | 活动、内容、顺序、当次时长、来源模板 | 后续模板编辑不能静默改写当堂历史 |
| 请假 | 学员、课程、提交者、生效/撤回记录、时间 | 提交后即排除默认销课，无审批；历史与当前有效结果分别保留 |
| 销课/训练参与记录 | 人员、活动、销课/不销课、原因、身份类型、来源、修改版本 | 日期过后自动默认生成、双方可修正；同课同人只有一份当前有效结果 |
| 评价及修订 | 学员、队伍上下文、语句/文本、作者、时间 | 当前评价与历史；沟通文本与测评分数分开 |
| 测评项目 | 标识、值类型、单位、方法、标签、适用条件 | 原始采集定义与评分模型分开 |
| 测评任务 | 创建者、周期、队伍、对象名单、必测项目 | 下发规则与每条成绩分开；周期与录入截止不同 |
| 测评记录 | 人员、原始项目、原始值及单位、任务、所选课程、课程日期、录入/确认时间 | 所选课程决定归属；每人每项可来自不同课程；未测不等于零 |
| 分值与等级映射 | 原始项目 → 整数分值项目 → 等级项目，两段区间与版本 | 教练只录原始值，后台维护映射，三层关联可追查 |
| 模型定义/版本 | 输入、参数、规则、输出、适用条件、依赖 | 原子值与派生值；模型身份与模型版本分开 |
| 计算结果 | 人员、模型版本、输入引用、输出、计算时间 | 结果可复用且可追溯；不能只保存最终总分 |
| 结果确认/修订 | 数据版本、确认人/时间、可见范围、历史 | 草稿、已确认、修订草稿分开 |
| 培养标准 | 项目/模型输出、适用范围、目标/区间、版本、依据 | 规范目标与样本均值分开 |
| 服务目录/服务记录 | 类型、介绍、对象、目标、负责人、状态、交付 | 一种服务与一次服务承接分开；内部球探不强制付费 |
| 课包/保险状态 | 俱乐部确认值、适用对象、来源、时间 | 维护结果与训练次数分开，不能自行推导余额 |
| 导入批次/来源关联 | 来源、外部记录标识、映射、预览、结果、操作人 | 外部行与内部对象关联，重试不重复导入 |
| 通知记录 | 业务对象、受影响人、内容版本、发起时间、渠道状态 | 已发起、已发送、已送达、已读不能混称 |

## 2. 统一身份、时间与历史

### DATA-01 身份与归属

**C：权限范围；P：身份细则。** 使用稳定内部人员标识关联资料，不仅靠姓名或手机号。家庭共用联系方式不能合并孩子。跨俱乐部身份存在关联时也不代表资料自动共享。

转队、转正式、暂停和离队不抹除旧记录。历史记录要能识别当时的活动及队伍归属；按当前归属回看历史属于另一种查询条件，必须标明。

### DATA-02 时间和日期

**C：所选课程决定测评归属，课程日期、录入时间及确认时间分开；P：通用时间口径。** 日期按俱乐部明确的业务时区解释；课程开始结束、实际测评、录入、确认、变更分别记录。周期边界要明确首尾包含规则，不能依赖不同客户端各自判断。

测评发生日期取所选课程业务日期，保存课程标识与当时日期，不要求教练重复填日期。只改课程不改成绩也属于修订，再确认前保留旧结果。课程后续改期不无痕改写已确认来源，异常按 O-06 处理。

历史导入时间不等于事实发生时间；日期未知时保留未知。入训日期不由账号注册日期替代。年龄按测评时还是统计时计算见 O-04；入训天数是否含首日、离队再入训如何累计见 O-11。

### DATA-03 状态与更正

**C：保留真实历史和更正；P：通用实现规则。** 保存记录应保留操作者、来源及修订关系。修改既有事实后，受影响的列表、明细、汇总和家长展示应一致更新；已发布成绩按再次确认规则处理。

取消事件、更正事实、作废错误记录和删除草稿是不同操作。涉及历史统计的动作应展示影响，并保留追溯路径。

## 4. 状态与完成规则

以下为产品状态模型，名称可在技术设计中调整，业务含义应保持一致。

### STATE-01 日程

**C：基础安排与临时变更区分；P：具体状态。** 正常安排、已取消、已结束可区分；改期保留变更关联。审批待处理是否存在取决于 O-01。

训练日期已过且课程未取消时，按名单自动产生默认销课，已有效请假的人员不销课。该结果是轻量业务记录，来源标明系统默认，不表示教练已点名或系统实测出勤。复制模板不改变日程状态。

### STATE-02 默认销课、请假与人工修正

**C。** 核心规则为“训练日期过后默认全员销课；有效请假不销；家长和授权教练可直接修改；无需审批；每次修改留痕”。系统与两端共享当前有效结果，不设置等待对方同意的中间状态。

**P：具体状态表达与可靠性细则。**

| 情况 | 当前结果与处理 | 记录要求 |
| --- | --- | --- |
| 日期未过、未请假 | 尚未默认销课，不提前计入已销课统计 | 按俱乐部业务日期判断；触发边界 O-02 |
| 日期过后、未请假且未人工修正 | 自动销课 | 标明系统来源，不要求教练打开页面 |
| 已有效请假 | 不销课，原因请假 | 记录提交者和时间，无审批 |
| 已自动销课，家长/教练补记请假或改不销课 | 保存后直接变为不销课 | 保存前后值和修正记录，更新统计 |
| 已请假但实际参加，家长/教练改回销课 | 保存后直接销课 | 原请假历史保留，当前明确结果生效 |
| 撤回请假、未另行指定结果 | 按当前日期和课程状态重新确定默认结果 | 不覆盖独立的最新人工明确结果；撤回和重算留痕 |
| 课程取消 | 不销课；已有默认记录按取消状态调整 | 保留原记录及取消造成的变更，不无痕删除 |
| 自动任务重试 | 保持同人同课一份结果，不重复计次 | 不覆盖已有人工作出的明确修正 |
| 家长和教练同时修改 | 校验当前版本，冲突时提示刷新核对后直接保存 | 无业务审批；保留每次成功修改，不静默丢失另一方改动 |

系统按当次应参与名单处理，不能用今天新增的队员无条件追补全部历史训练。临时参训和暂停状态的具体名单口径见 O-02；改期/补课按 O-14。

修改历史至少包括人员、课程、操作方（系统/家长/教练/后台）、操作人、时间、前值、后值及可选说明。每次成功修改均留痕，恢复成原值也保留中间过程；未提交的点击或保存失败不伪造一条已生效修改。

双方线下确认、线上直接修正即可。系统展示最新有效记录及来源，不标称双方逐条签认；无需另建一套逐堂人工出勤确认。销课不会自动完成测评任务或专业服务。

### STATE-03 测评采集

**C：填完/不测评才完成，允许补录。** 对任务中的学员 s：

`学员处理完成(s) = 已明确标记不测评(s) 或 所有必测项目均有已有效保存的数据(s)`

`任务采集完成 = 任务名单内每名学员都处理完成`

录入框尚未成功保存的值不算完成。缺席、周期结束和页面打开都不触发完成。按项目分批测得的数据可归属不同课程。

**P：边界处理。** 空名单任务不能以“全部完成”显示，提示无对象；多人修改或名单调整后重新计算进度并保留变更。个别项目不测如何替代必测条件需 O-06 确认。

### STATE-04 结果确认和修订

**C。** 每个人的结果独立保存和确认，不需要全队一起公开。

| 采集情况 | 结果情况 | 家长展示 | 教练待办 |
| --- | --- | --- | --- |
| 未填完 | 有草稿 | 不显示该草稿 | 继续采集 |
| 某学员已填好，全队未完成 | 该学员已确认 | 显示该学员确认结果 | 其他学员仍待处理 |
| 全员已处理 | 有结果待确认 | 只显示已确认部分 | 仍有待同步入口 |
| 全员已处理 | 所有可发布结果已确认 | 显示相应结果 | 无此项采集/同步待办 |
| 正在修订 | 新草稿未确认 | 保持旧确认结果 | 待确认修订 |
| 标记不测评 | 无新分数 | 不生成零分，不覆盖旧结果 | 计入已处理，不计入已测 |

不测评原因是否对家长显示属于可见字段规则，不能将内部原因全部公开。任务完成和模型能否生成综合分不同：项目已填齐，但不满足某额外模型要求时不得编造综合分。

### STATE-05 模型与结果

**P，承接 C 的版本要求。** 模型配置草稿 → 试算/校验 → 发布版本 → 停用。使用中的发布版本保持可追溯，修订产生新版本。

计算执行状态与家长发布状态分开；计算失败、输入不足应可见，不用旧分数冒充本次新结果。引用其他模型结果时保存实际使用的结果版本。

### STATE-05A 三层测评结果

**C。** 原始成绩按第一段已发布区间规则得到整数分值，再按第二段已发布区间规则得到等级；后台维护两段映射并保留版本。无有效映射时保留原始值，说明缺配置或未命中，不生成假分值或等级。已确认结果引用实际使用的规则版本；规则变更不静默改历史，重算走修订和再次确认。

配置草稿/发布/停用与结果草稿/确认分别表达。等级不是教练文字评价，培养目标也不是评分映射，三者不能混用。

### STATE-06 专业服务

**P。** 私教/定制可使用待跟进、沟通中、待承接、执行中、已交付、已结束/未达成等简单状态；球探使用观察中、待试训、已试训、待跟进等业务状态。

状态以最少必要项为原则，具体枚举见 O-13。交付报告不自动表示已收费，咨询不等于购买，内部球探工作不要求付款状态。

## 5. 统计口径

以下为统一候选公式（P），其中日期过后默认销课、请假不销、双方直接修正留痕、不涉及真实金钱统计、不排名及不以缺测当零等边界为 C。实施时不得在不同页面悄悄采用不同公式。

| 编号 | 指标 | 定义或计算方法 | 特别处理 |
| --- | --- | --- | --- |
| MET-01 | 已销课次数/按记录统计的训练次数 | 指定范围内，训练日期已过、课程未取消、学员当前有效结果为销课的活动去重数 | 包括系统默认及人工修正；友谊赛属训练；请假/其他不销课不计；修正后重算；不是实测出勤证明 |
| MET-02 | 内容参与次数 | 已计入 MET-01 的课程中，包含指定原子内容的课程数 | 一堂课多个内容可以分别计；不是动作实际重复次数；同课重复项按 O-15 |
| MET-03 | 训练内容时长 | 对 MET-01 纳入的课程内容时长求和，明确为按销课记录和配置汇总 | 不称为穿戴设备实测时长；缺时长不补零冒充完整；超课长或并行内容按 O-15 |
| MET-04 | 内容分布 | 按原子内容主分类/约定分类汇总次数或时长，并说明采用哪种 | 多标签可多维筛选；若展示占比，不能因标签重叠导致总量误导 |
| MET-05 | 应参加人次与按记录统计的参与率 | 分母为训练日期已过、未取消课程中的应参加正式学员人次，分子取当前有效销课人次 | 是否剔除请假 O-02；系统异常/缺记录单列，不当缺席；分母为零显示不适用；明确使用轻量销课口径 |
| MET-06 | 测评任务处理完成率 | 已满足 STATE-03 的学员数/任务应处理学员数 | 不测评计完成；同时显示实际已测、不测评和未完成，避免混淆 |
| MET-07 | 待同步结果数 | 已有效录入、具备确认条件但尚未确认的个人结果数 | 全队采集完成后仍可大于零；按人/版本去重 |
| MET-08 | 当前能力与趋势 | 适用项目/模型下的有效已确认结果，按实际测评时间组织 | 补录不会因录入较晚就自动覆盖更晚发生的测评；版本不可比时分段解释 |
| MET-09 | 培养目标达成 | 采用指定标准版本对相同单位及适用范围的有效值比较 | 越高/越低/区间最佳不同；无标准或缺值显示无法判断 |
| MET-10 | 入训天数 | 根据真实入训日期、业务时区及确定的累计规则计算 | 含首日、暂停和再入训口径 O-11；未知不造数 |
| MET-11 | 课包余额 | 俱乐部另外维护或提供的确认状态 | 后台数据能力保留；当前小程序不展示，不因培训计次、请假或修正自动触发扣账；未来启用另行定义 |
| MET-12 | 球探参训与转正式 | 试训活动参与去重数，以及显式转正式记录 | 观察记录数不等于试训次数；转正式不能重复建立人 |
| MET-13 | 教练实际教学次数 | 依据经确认的实际执教事实去重 | 记录来源和多教练计次 O-09，不能用点名点击次数代替 |
| MET-14 | 服务需求/承接/交付 | 按服务记录有效状态及统计时间去重 | 重复沟通不是新需求；取消、未达成单列；收入统计需真实收费来源 |

MET-02/03 代表按当前有效销课结果和课程内容关联得到的训练经历，包括自动默认及后续修正。任何界面都不能将其解释为学员实际做完每项动作的证明；也不得为了提高“确认率”额外要求教练逐堂确认默认记录。

“最新结果”建议以实际测评发生时间决定，同时间更正按版本取有效确认结果；多项目来自多课时，结果详情保留各输入日期。综合图的混合时间窗口由模型规则决定，不能任意拼接旧单项形成“本次综合分”。

## 6. 可靠性与扩展要求

**C：简单保存保护及后台工程补齐（2026-09-20）。** 本项目不以高并发或复杂实时协作为目标。其余未明确实现细节为 P，具体方案见 [16 号规格](../upgrade-readiness-2026-09-18/16-confirmed-rules-and-engineering-spec.md)：

- 自动销课重试和重复点击不重复创建课次、测评、发布或导入事实；批量操作展示成功/失败明细。自动任务不覆盖人工修正，未处理成功可恢复，不能长期依赖用户打开页面才生成课次。
- 家长/教练/后台修改携带版本号，事务内检查、更新并追加历史；冲突保留输入，核对最新值后重存，不静默覆盖、不增加审批。沿用 SQLite 单写部署与短事务，不为本轮建设分布式锁或多写实例。
- 已确认结果的输入、项目定义和模型版本能追溯；重算不静默修改历史。
- 列表、图表和导出针对同一范围和数据截至时间一致；计算尚未更新时明确提示。
- 权限在服务端及导出入口生效，页面隐藏只是表现层；记录关联校验防止跨孩子、跨队、跨俱乐部错误写入。
- 标准字段与有限类型扩展字段分开，核心关系不藏在自由文本里；新增采集来源复用来源、时间、单位及对象关联。
- 数量和性能限制按实际学员规模、并发、批量导入与模型复杂度评估。当前没有已确认的秒数、并发量或容量 SLA，不在文档中虚构指标。
- 保留必要的错误、操作和更正记录；历史清理、保留期限、备份恢复由技术与业务依据真实要求确定。

这些要求不等于本轮已完成技术方案或测试。后续开发应将具体容量、错误恢复、兼容和发布策略写入相应任务。
