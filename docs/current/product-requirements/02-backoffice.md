# 02 后台功能需求

统一按数据管理、评测与模型、BI、专业服务四个模块设计。状态含义见[入口](README.md)，业务主流程见 [01](01-product-and-miniprogram.md)。

## 1. 信息架构

| 一级模块 | 建议二级入口 | 主要用户 |
| --- | --- | --- |
| 数据管理 | 人员与队伍、日程与训练、活动与记录、导入导出、内容资料 | 管理员、运营、授权教学人员 |
| 评测与模型 | 项目库、模型库、培养标准、任务、结果与成长 | 教学负责人、授权模型维护者、执行教练 |
| BI | 运营概况、训练分析、测评执行、学员成长、专业服务分析 | 管理者及获授权人员 |
| 专业服务 | 服务目录、需求与承接、计划与交付、球探工作 | 服务负责人、教练及授权专业人员 |

四模块为 **C**，二级入口名称与页面拆分为 **P**。工作台和管理设置作为通用入口，不能用这些菜单名称推导数据权限。

### REQ-ADM-001 工作台与业务入口

**状态：C：工作导向；P：聚合方式。** 工作台建议显示近期日程、已请假人数、销课修正/异常、临时变更、导入错误、资料缺项、测评未完成/待同步、服务待跟进。请假直接生效，不设请假审批；正常销课不形成教练点名或确认待办。

点击事项进入对应业务对象，不另建一份记录。临时变更是否需要审批按 O-01，不能默认每项变更都生成审批待办。未更新个人评价不属于工作缺口。

从学员或队伍详情可直接进入课程、训练记录、测评和服务记录。在各页面重复出现同一对象时，共用状态、历史和权限。

### REQ-ADM-002 账号、权限与俱乐部配置

**状态：C：俱乐部资料隔离与角色边界；P：配置界面。** 管理账号、教练任职、队伍授权、家长绑定关系和操作历史。详细矩阵见 03。

平台配置承接俱乐部接入、公共目录/模板分配和必要的集成状态；俱乐部管理自己的业务资料及获准版本。跨俱乐部资料不因共享模板而互通。

建议使用清楚的角色模板与必要的范围授权，避免将复杂权限设计器作为日常管理的必需步骤。

## 2. 数据管理

### REQ-DAT-001 基础资料维护

**状态：C：管理对象与权限方向；P：字段分组。** 支持学员、家长与联系人、球探人员、教练、队伍、学期、场地、保险和课包状态的维护、查找、筛选和导出。

建议表单按身份、教学、联系、运营、保障等分组，必填项只覆盖建档和使用所需信息，不强制一次填完所有扩展资料。具体采集字段和可见范围需要业务核定，不把可扩展性解释为无限采集。

一个学员可以关联多个监护/联系人；联系人不必已注册小程序。绑定登录账号与维护联系人是不同操作，不能因手机号相同自动绑定另一名孩子。

独立球探库与正式学员列表分别管理，转正式学员建议沿用人员身份，保留来源和历史。身份疑似重复时提示人工核对，不仅凭姓名或电话号码合并。

暂停、离队、教练停任、目录停用等保留历史；不得因不再参与当前活动而直接删掉成长和业务记录。具体状态枚举及恢复规则属 P。

**2026-09-20 补充（C）：** 已确认维护对象须可保存、重进回读，具有校验、权限和历史。场地复用已有标识、类型、地址、设施和坐标定义；缺坐标不伪造导航位置，停用不破坏历史活动引用。保留后台课包/扣课能力及受权维护，当前小程序不展示，正常培训计次不触发扣账。

### REQ-DAT-002 日常业务维护与记录查询

**状态：C。** 后台统一维护队伍主档和学期安排；创建比赛与其他活动；维护原子训练库及公共模板；查看和按权限修正课程、出勤、请假、参训及其他过程记录。

每条记录应能定位到相关人员、队伍、课程/活动和来源。测评内容进入评测模块的同一记录，专业服务内容进入服务模块的同一记录，不在数据管理再建立独立评分或服务台账。

销课日期过后自动生成，家长和授权教练直接修正，保存即生效且每次留痕；无需审批。后台可查询系统默认与人工修改来源。更正后相关统计刷新；外部课包余额和真实财务不由该记录自动改写。课程内容与测评更正分别沿用各自规则，测评确认发布不能套到销课流程中。

### REQ-DAT-003 导入、导出和外部来源

**状态：C：能力要求；P：具体操作方案；O-05：来源责任与客户模板。** 各业务页面可发起导入导出，统一页面查看批次和结果。

导入对象覆盖人员资料与关系、日程、过程记录、测评、保险与课包状态等；模板逐项定义相应字段、单位、选项和关联标识，不能用一个没有规则的通用表格承接全部对象。

建议流程：

1. 选择数据类型，下载标准模板或使用已配置的客户表格映射。
2. 上传并选择映射，识别新增、更新、重复、缺失和冲突。
3. 预览影响，确认空值处理与更新规则。
4. 确认导入，展示成功和失败情况，提供失败行及原因。
5. 修正后重试，识别已处理记录，避免重复生成事实。

保留来源、外部标识、映射版本、批次、操作者和处理结果。采用全部拒绝还是合格行部分入库应在对象模板中明确，预览不得显示含糊的“导入成功”。

WPS/Excel、后台和小程序遵循同一业务定义；每类字段明确主要维护来源。自动双向同步、任意文件自动理解不是本轮已确认要求。

导出支持筛选和获准字段选择，区分回填模板、业务明细和 BI 汇总。敏感字段需要明确权限并记录导出行为。测评导入仍遵守草稿/确认规则，不能因批量导入就自动对家长公开。

### REQ-DAT-004 数据质量与业务历史

**状态：P（基于数据管理目标的必要设计建议）。** 识别缺少必要关联、重复身份、未知单位、无效日期、缺版本及跨俱乐部错误引用等情况。记录可补齐，问题可定位到具体行或对象。

历史数据若缺少真实关联，保留“历史导入/来源不完整”标识。可供查阅，但只有满足相应统计和模型输入条件才进入计算，不能伪造课程或测评日期。

更正与合并均保留操作历史；合并不能把两个不同孩子的训练数据混在一起。删除、停用和修订按对象影响分别处理，关键业务事实不能通过列表误操作无痕消失。

### REQ-DAT-005 内容与展示配置

**状态：C：支撑已确定首页；P：配置细节。** 维护俱乐部信息、队徽、新闻 Banner、通知、预制分享模板、评价用语和小程序可选功能目录。

俱乐部配置哪些功能可以被选；家长选择自己的四个快捷入口及顺序。内容编辑不授予改评分规则的权限，也不能绕过学员照片和数据可见范围。

重要日程变更与新闻分别管理，前者关联具体活动和受影响人员。通知发送、送达、已读按实际能力区分，不用一个“已通知”掩盖未知结果。

## 3. 评测与模型

### REQ-MOD-001 项目与采集定义

**状态：C：可扩展项目、原始值、标签；P：定义项细则。** 项目具有稳定标识、名称、数据类型、单位、说明、适用条件、标签和显示权限。不同项目可分别记录时间、次数、距离、量表分等。

建议同时定义测试方法、合理范围、数值方向、多次测量取值方法，避免相同名称下的测量不可比。标签支持基础、高级等多个分类，标签自身不改变评分。

数据来源可拓展至设备身体指标、外部环境等。采集来源、单位和测量时间必须能保存，具体连接能力按实际业务接入要求单独设计。项目数量不在产品上固定为某个小常数，但系统需按实际容量定义分页、批量和性能边界，不承诺物理无限。

**2026-09-20 补充（C）：** 每项测评关联原始成绩、整数分值、评价等级三层定义。后台分别维护“原始成绩区间 → 整数分值”和“整数分值区间 → 等级（如 S、A+、A）”。边界、单位和适用条件须明确，冲突区间不能发布；正式阈值未提供时可配置草稿和试算，不拿演示值冒充标准。原始值保留项目精度，映射分值为整数。

### REQ-MOD-002 模型定义与复用

**状态：C：模型可扩展、结果可复用；P：模板化操作及安全规则。** 模型声明输入项目或其他模型结果、计算规则、参数/权重、适用条件和输出。一个输出可以被多个模型使用。

建议普通管理操作为选择模板、关联输入、调整获准参数、试算和发布。专业模型维护者管理复杂定义，教练录入端不提供修改模型入口。

引用其他模型结果应明确对象、版本和时间选择规则；循环依赖应被阻止。不同单位、适用人群或不完整输入不能无提示混算。模型有多个输出时引用需指明输出项。

任意公式语言、可视化节点编辑器、跨历史窗口自动取值的具体支持深度需在技术评估中确认；核心结果可复用是产品方向，不等于上述所有编辑方式均已批准。

### REQ-MOD-003 版本、试算与发布

**状态：C：历史可追溯；P：管理工作流。** 模型、两段区间映射和标准变化保留版本。结果能追查原始成绩、整数分值、等级、两段映射版本及时间；配置变更不直接改写已确认历史。

建议配置草稿通过样例试算和输入校验后发布，已用版本不原地改写。历史重算创建可识别的新结果，原结果仍可追查；不会无说明地改变家长看到的历史趋势。

同一模型版本给定相同有效输入应得到相同输出。停用项目或模型不能破坏已存在的历史结果；被使用定义的删除改为停用或明确处理依赖。

### REQ-MOD-004 培养标准和展示组织

**状态：C。** 管理年龄、普通队/精英队等适用条件下的培养目标或参考区间，注明依据、版本、生效范围及比较方向。

标准应关联具体项目或模型输出，避免把不同单位的值直接比较。家长成长可以对照标准，但不出现具体同伴排名或点名比较。年龄按何时计算、重叠标准如何选择见 O-04。

维度组织与计算关系分开：同一结果可以有不同展示方式，不能因为调整图表顺序或分组就改变分数。

### REQ-MOD-005 测评运营与结果管理

**状态：C。** 后台创建并多队下发任务，查看各队、各人、各项的采集与同步状态，查阅原始值、计算结果、不测评原因及历史更正。

复用 REQ-ASM-001 至 REQ-ASM-006 的规则。超过测评周期仍保留任务；管理视图可提示尚未录完，但不称作不可处理的过期任务。不测评计入任务处理完成，不计入实际已测人数。

按周、月、学期下发表示支持这些周期；是否自动重复生成任务尚未确认，不能把周期字段直接推导为复杂自动调度需求。

## 4. BI

### REQ-BI-001 简单的分析呈现

**状态：C。** 使用主题分析页，选择时间和对象后查看图表、明细或导出。满足不同数据分析呈现即可，不要求运营人员搭建数据集、编写公式或拖拽设计看板。

图表形式按问题选择指标卡、趋势、柱图、分布和表格。新增主题可增加页面或图表，不增加一套独立事实库。各主题默认条件明确，刷新状态与数据截至时间可见。

### REQ-BI-002 分析主题

**状态：P（按已确认 BI 目标提出的内容建议）。**

| 主题 | 回答的问题 | 建议指标/明细 |
| --- | --- | --- |
| 运营概况 | 俱乐部在服务谁、工作是否完整？ | 学员/队伍状态、活动开展、资料完整、待办 |
| 训练分析 | 学员和队伍的训练记录如何分布？ | 当前有效销课次数、请假/不销课、内容参与频次、配置时长、学期分布；可查系统默认或人工修正来源 |
| 测评执行 | 测评任务进行到哪里？ | 应处理、已测、不测评、未完成、待同步 |
| 学员成长 | 同一孩子如何变化？ | 已确认结果趋势、原始值、适用培养标准、训练积累 |
| 专业服务 | 需求有没有承接、服务做到哪里？ | 咨询和承接、执行和交付、球探试训及跟进 |

支持数据实际具备的日期、学期、队伍、年龄、水平、项目和服务类型等筛选；不虚构缺少的维度。教练参与可作为相应主题的分组，实际执教统计待 O-09。

### REQ-BI-003 统一口径与明细

**状态：C：结果真实一致；P：口径实现细则。** 同名指标在所有页面采用一致定义。数字可定位到构成明细，导出带筛选条件与统计日期。详见 03 的 MET 口径。

缺失不等于零，不测评不等于低分，草稿不混入家长能力趋势，正式队员和临时参训不混用分母。模型或分组变化时说明可比性。训练与能力变化的关联展示不自动生成因果结论。

BI 使用与源记录相同的对象、字段和导出权限。必要时仅提供汇总，不让敏感明细通过图表绕过授权。

## 5. 专业服务

### REQ-SVC-001 服务目录

**状态：C：专业服务模块及可扩展类型；P：具体表单。** 俱乐部可围绕自身资源建立私教、定制培养、专业评测与分析、球探等特色或增值服务。

建议配置名称、类型、介绍、适用对象、目标、负责专业人员、周期/次数、交付内容、咨询入口和开展状态。服务目录与某次具体服务分开，一个项目可以服务不同对象并各自记录进度。

新增服务尽量复用类型、标签和模板，不要求每次建立一整套独立管理系统。可供配置不意味着所有服务必须开展。

### REQ-SVC-002 需求、匹配与承接

**状态：C：私教咨询和连接学员教练；P：处理流程。** 接收家长咨询或俱乐部根据真实沟通建立的需求，关联服务对象、方向和负责人。

建议按教练专长、适用年龄/水平和时间条件人工选择，保存沟通、候选人员、最终分派和处理结果。咨询不自动形成订单；分派不自动等于教练已承接。

数据分析发现薄弱项可作为服务沟通依据，不能直接认定家长已同意服务。是否允许外部专业人员、跨俱乐部服务及相关权限见 O-13。

### REQ-SVC-003 定制计划、执行与交付

**状态：P。** 支持需求 → 沟通评估 → 确定方案和人员 → 安排执行 → 交付反馈的简洁流程。简单私教只填必要记录，定制培养可增加初始评估、目标、训练计划和复评节点。

计划中的训练链接到共同日程、课程和出勤，测评引用共同任务与结果，报告说明数据来源及确认人。方案文档和附件可作为交付物，不默认开发复杂在线方案编辑器。

服务涉及收费时可关联俱乐部确认的价格和收费状态；不从增值服务自动推导支付、结算、分账或课包自动扣减。团课和私教人数、取消、预约等业务约束见 O-13。

### REQ-SVC-004 球探工作与专业跟进

**状态：C：球探库、参训数据及专业服务方向；P：工作流。** 球探库作为基础资料，观察、试训、选材意见和跟进作为专业工作记录，关联同一人。

建议流程为发现/建档 → 观察或试训 → 专业意见 → 跟进。球探可作为内部选材工作，不强制经过家长咨询或付费流程。记录来源、负责人、证据/观察、安排和结果即可，不默认引入职业转会、合同谈判或外部人才交易。

临时参训经共同日程记录，转正式学员时保留旧历史。球探专业意见与学员通用教练评价分别保存，内部意见不自动面向家长展示。

## 6. 后台工程补齐要求

**C：2026-09-20 授权按工程规范补齐既有范围。** 后台与小程序共享业务服务、身份、权限及持久化事实；工程补齐不扩大未决业务范围。

- 维护对象具备列表/筛选、详情、编辑、校验、保存、重进回读与操作历史；停用保留历史引用，不强制所有对象提供删除。
- 活动按训练/比赛/其他提供表单及保存闭环；场地、保险、后台课包明确字段、来源、更新时间与可编辑范围。
- 映射规则支持草稿、边界试算、校验、版本发布/停用及失败重试，评分关系不写死在小程序。
- 表单覆盖加载、空、无权限、保存中、成功、失败保留输入、版本冲突核对；重试不重复创建。
- 导入具备预览、确认、逐行结果和重试；导出独立授权、裁剪字段、携带条件与数据版本。BI 卡片、明细和导出同口径，数据变更可识别。
- 服务端执行关联校验与授权，重启后可回读保存结果；迁移、备份和恢复验证后再发布。
- 复用已有有效入口和能力；专业服务细则、外部通知渠道等 O/P 项不自动变成已确认范围。

页面差距、实现建议和验收对应见 [16 号开发规格](../upgrade-readiness-2026-09-18/16-confirmed-rules-and-engineering-spec.md)。

## 7. 演进能力与实现评估

扩展性集中在稳定身份、关系历史、类型化数据、来源与时间、项目/模型版本、可复用结果、服务分类和一致权限。设备、环境、AI 与专业商业服务沿这些边界增加能力。

实现前应核对已有 API、数据与页面，特别是销课触发时点、请假排除、家长与教练直接修正和留痕、与财务隔离、任务周期限制及固定维度展示等差异。本文件不指定新的数据库表名或接口路径，也不宣称已有通用配置界面；后续技术设计应基于本需求与实际代码明确。
