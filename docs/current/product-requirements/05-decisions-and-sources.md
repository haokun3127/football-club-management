## 3. 不再沿用的口径

以下内容出现在早期材料或实现记录中，后续明确讨论已改变；保留此表防止开发误读。

| 不应再作为默认需求的说法 | 本次采用的口径 |
| --- | --- |
| 小程序不自动销课，必须教练逐堂确认后才有课次 | 训练日期过后默认全员销课，已请假不销；无需逐堂点名或确认 |
| 请假需教练同意，家长不能改销课 | 请假直接生效，家长与授权教练均可修正课次，不经过审批，每次留痕 |
| 自动销课等于真实金额扣款或财务结算 | 简化销课是业务课次记录，不自动产生金钱统计，也不擅自改写外部课包余额 |
| 所有教练可维护球队或安排课程 | 队伍/学期由俱乐部维护，主教练仅编辑授权安排内容 |
| 每堂课给每人或每个内容评价 | 每名学员一份当前评价，按需更新并保留历史 |
| 教练不能创建任何测评任务 | 可自建任务，但项目选自库中，不能任意改标准 |
| 测评到期不能再录入 | 可以补录，实际发生仍须关联周期内训练课 |
| 缺席就自动免测或当任务完成 | 缺席与测评完成独立，需填数据或标不测评 |
| 一次测评只能绑定一堂课 | 可按人、项目、课程分批完成 |
| 只保留最新测评、不存历史 | 保留历史、修订和适用模型/标准，支持成长追踪 |
| 产品固定五维、六维或八维 | 模型与展示可扩展，具体维度由适用模型决定 |
| 学员个人排名、百分位是默认首页内容 | 个人成长与培养标准对照，不比较具体同伴 |
| 友谊赛必须独立日历类型或归比赛 | 利用训练课时的友谊赛归训练；独立赛事归比赛 |
| 将其他活动归入训练或比赛 | 保留“其他”顶层类别 |
| 成长卡依赖人物抠图、自动换球衣 | 使用预制模板、普通照片和真实数据 |
| 运营人员必须自行搭建 BI 看板 | 主题分析页加筛选、图表、明细和导出 |
| 球探库人员都属于正式队伍成员 | 独立管理，单次参训不改变长期归属 |

补充不再沿用：固定 7/11 名上场人数、强制阵型选择或一换一上场；以发布时间充当测评日期；原始值隐式当分数；将双方课次修正或协同测评重新待决。

## 6. 实施交接检查

本轮不进行新的完整代码审计；此前会话中的局部核查仅是差距线索。后续开始相关开发时必须基于当时分支和部署状态重新确认：

1. 现有系统是否按训练日期自动生成课次，能否排除请假、允许家长/教练直接修正并留痕；自动任务是否会重复生成或覆盖人工结果；是否误联动真实财务或外部课包余额。不得继续沿用 v1.0 的“不自动销课”理解。
2. 现有任务周期限制是否阻止补录，任务是否支持按人/项目关联多堂课程。
3. 任务完成、原始记录保存、模型计算和确认发布是否已分离；失败和重试如何处理。
4. 固定维度文案、图表和评分规则能否按模型展示；实际项目与能力手册是否一致。
5. 教练权限是否真正受主教练角色及队伍范围限制，后端接口和导出是否同步限制。
6. 现有逐课评价如何保留历史并过渡到当前评价；不得在无映射规则时直接删除历史。
7. 临时学员与球探资料是否共用可追溯身份，历史导入是否有不完整关联。
8. 后台哪些只是领域/API 能力，哪些已有可用页面；不得将“接口存在”当成界面已交付。
9. 当前上线版本、功能开关、数据库与小程序发布状态；本文不继承过往线上结论。
10. 在线设计稿、导航、测试账号和实施环境；未经新需求评审，不因旧设计稿存在而恢复已否定业务规则。

需提供的最关键业务输入：能力手册与评分标准、脱敏导入样表、实际服务目录、团课/私教约束、照片及公开展示规则。其余已确认部分可继续技术评估，不需要为整个项目重新逐条确认。
